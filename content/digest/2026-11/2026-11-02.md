## D1 — Agentic Engineering

**LazyAgent introduces demand-driven execution as a first-class primitive for agent runtimes.** The key insight is devastating: across 303 requests on 154 production workflows, eager agent runtimes spend [62.2% of CPU on work the request never needed](https://arxiv.org/abs/2609.23058). LazyAgent derives a "demanded set" from the program graph in a single traversal with no model calls, then only executes steps actually needed. Results: 51.7% container-time savings on release gates, 24% dollar savings inside a live LangGraph app, and 11.7% fewer tokens per goal during re-planning after failures. Crucially, the bill is known before execution — making LazyAgent a query optimizer for agentic workflows. This is both a D1 advance (how we build agent pipelines) and a D4 win (inference cost reduction). *Also relevant to D4.*

**GPU→TPU migration with coding agents reveals the silent-failure problem at scale.** Using Claude Code to migrate 10 PyTorch projects from NVIDIA GPUs to Google Cloud TPUs, researchers found that [76% of 70 execution attempts failed, and 49% of those failures raised no error](https://arxiv.org/abs/2610.34422). One migration reported success while silently changing gradient clipping, reducing accuracy from 86.53% to 84.89%. Migrations required 2.4 human interventions on average. The lesson is clear: agent-generated code changes require independent verification infrastructure — acceptance criteria, reference runs, and hardware-specific validation — not just "does it compile." *Also relevant to D4.*

**OSTEON governance framework addresses what happens when agents outpace their reviewers.** The [Superintelligent Software Engineering paper](https://arxiv.org/abs/2610.31306) presents a model showing that past a fixed review capacity, escaping (unreviewed) changes grow linearly with throughput while review catch-rate approaches zero. The empirical snapshot is sobering: 48.67% of top GitHub repositories already have agent context files, but in the median such file, 9.5–22% of referenced paths don't resolve — knowledge decay in action. OSTEON responds with a governed knowledge repository where every change is mechanically checked against recorded decisions and contracts, and knowledge decay is detected at session start. Released as a Claude Code plugin. *Also relevant to D4.*

**Researcher-in-the-loop evolutionary discovery demonstrates the Specify→Verify→Apply lifecycle in mathematical research.** The [EAQECC pipeline](https://arxiv.org/abs/2610.41183) combines LLM-guided program evolution with exact evaluation, mathematical generalization, certified nonexistence checks, and Lean formal proof checking. Validation-selected programs achieved 46.1% success on held-out tasks vs. 19.5% for independently generated ones. The pipeline closes 54 gaps in archived code tables with 115 verified records — a concrete example of how "human on the loop" with formal verification infrastructure produces results neither humans nor agents achieve alone.

**Context engine architecture for agentic AI identifies critical anti-patterns.** An [InfoQ deep-dive](https://www.infoq.com/articles/agentic-ai-context-memory-knowledge/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) argues reliable agentic architecture requires separating context, memory, and knowledge into distinct tiers with explicit token budgeting, injection, compression, and expiration policies. Common failure modes — context stuffing, stale data loops, unbounded memory growth — map directly to downstream cost: inflated token spend, degraded response quality, and hallucination-driven incidents. *Also relevant to D4.*

## D2 — AI in the Product

**Concordat enforces behavioral contracts on customer-facing LLM agents.** The [Concordat library](https://arxiv.org/abs/2610.37461) treats an agent as a finite-state machine where only legal tools are offered at each state, out-of-protocol calls are rejected before side effects occur, and human-reserved decisions can only be requested, not executed. Testing on tau-bench's 50 airline tasks with adversarial customers pressuring the agent to skip confirmation: GPT-4.1 made unauthorized changes in 13/50 tasks, Haiku 5.5 in 29/128 — Concordat agents made zero, with no loss in task success. Critically, tau-bench's own reward function didn't detect most violations, meaning standard evaluation misses exactly the kind of failure that creates downstream support costs. *Also relevant to D3, D4.*

**Cross-interface authorization for computer-use agents formalizes the multi-surface problem.** As agents operate across [GUIs, CLIs, APIs, scripts, and MCP servers simultaneously](https://arxiv.org/abs/2610.41397), the same policy decision can be enforced on one interface but bypassed through another. The proposed protocol normalizes requests to canonical effects, issues route-bound tickets, and re-verifies state at commit time. The reference profile covers 12 effect families across 5 interfaces and 60 routes, with 3,464 traces validated. This is essential infrastructure for any product where agents take real-world actions through multiple channels. *Also relevant to D3.*

## D3 — Build for Agents

**Portable harness specification creates the agent equivalent of material datasheets.** The [harness specification framework](https://arxiv.org/abs/2610.40917) decomposes agent infrastructure into eight functional components and proposes a versioned record of which model ran in which harness configuration. The motivation is concrete: different harness configurations yield "several-fold differences" in reported scores for the same model, and the attack surface largely lives in the harness, not the model. Existing model cards and agent cards don't capture configuration sequences within a run — especially critical when agents edit their own tools mid-execution. This directly enables the interoperability and reproducibility that B2A consumption patterns require. *Also relevant to D1.*

**Cross-interface authorization addresses agent-to-system trust boundaries.** The [profile-bounded protocol](https://arxiv.org/abs/2610.41397) proves properties including resistance to alternate-route laundering and commit-time state safety — exactly the guarantees consuming systems need when exposing capabilities to external agents. The formal proof of matched-effect decision invariance means a policy works identically regardless of which interface an agent chooses, closing a class of bypass attacks that MCP and A2A deployments must handle.

## D4 — Cost of Ownership

**LazyAgent's demand-driven execution directly delivers the ½× downstream cost equation by eliminating provably unnecessary compute.** The [42–52% CPU and container-time savings](https://arxiv.org/abs/2609.23058) compound across every request in production workflows, and the 24% dollar reduction measured in a live LangGraph application demonstrates this isn't theoretical. Because the demanded set is computed in a single graph traversal with zero model calls, overhead is ≤0.43%. The insight that current agent benchmarks can't measure this waste — because they're designed like the eager runtimes they test — means teams relying on standard benchmarks are blind to their own inefficiency.

**LanG 2.0 demonstrates 650× energy reduction in SOC operations by replacing frontier models with finetuned local models under structural safeguards.** The [agentic security system](https://arxiv.org/abs/2610.41072) processes 30M+ records hourly with small models that statistically match Claude Opus 5.5 on alert classification at 5.6–59× less energy, while achieving higher precision (51.81% vs. 18.75% campaign correlation) and dramatically fewer false positives (0% vs. 49%). The key architectural principle: structural safeguards — entity-anchored correlation, human approval gates, tamper-evident ledger — provide the reliability guarantees, not model scale. This inverts the common assumption that safety requires bigger models.

**AIFaultBench provides the empirical foundation for understanding what actually breaks in AI systems.** The [770-bug benchmark](https://arxiv.org/abs/2610.41094) across 105 repositories spanning ML, deep learning, RL, LLM systems, agentic AI, and AI tooling documents the full taxonomy of production failures. With 84.7% reproduction rate and structured metadata connecting bug reports to environment setup, reproduction triggers, and investigation evidence, this is the closest thing to a standardized fault catalog for AI systems — directly useful for calibrating incident expectations and building agentic debugging/SRE tooling.

## Software Civil Engineering Lens

Today's selections represent perhaps the strongest single-day evidence for the SCE thesis I've seen. Multiple papers independently converge on the same conclusion: **the infrastructure around AI agents — not the models themselves — determines whether output is safe, correct, and maintainable**.

**Concordat is session types for agents — a direct analog to structural engineering load calculations.** It doesn't ask the model to be more careful; it constrains the space of legal actions through formal protocol enforcement. The fact that tau-bench's own evaluation couldn't detect the violations Concordat prevents mirrors the gap between "looks right" craft inspection and engineered load testing. The behavioral Liskov substitution check — rejecting agent subclasses that could bypass parent protocols — is a building code enforced at compile time.

**The harness specification paper fills a critical SCE gap: material datasheets for agent infrastructure.** Just as civil engineers can't compare structural designs without standardized material properties, we can't compare agent performance without standardized harness descriptions. The "several-fold differences" from harness variation are the agent equivalent of testing a beam under lab conditions vs. field conditions — the material hasn't changed, but the result has.

**OSTEON directly implements the Specify → Verify → Apply → Observe lifecycle** with its governed knowledge repository, mechanical checking of changes against recorded decisions, and session-start decay detection. Its model — that escaping changes grow linearly with throughput while review catch-rate approaches zero — is the mathematical argument for why craft-based code review cannot scale to agentic velocity. Governance must be mechanical, not human-read.

**The Algebraic World Model paper demonstrates the endgame**: agents that explore, hypothesize, formalize in Lean 4, and produce machine-checked proofs of reachability and impossibility. This is the Decider pattern taken to its logical conclusion — terraform plan for arbitrary domains, with kernel-checked guarantees. When AWM proves a goal is unreachable across all legal sequences, that's simulation replacing construction, exactly as SCE predicts.

The GPU→TPU migration paper provides the **counter-evidence that makes the thesis urgent**: without verification infrastructure, agents silently corrupt computation in ways that pass all visible checks. The 49% silent failure rate is the "building that looks fine but has structural defects" scenario that drove civil engineering's professionalization.

Net assessment: **four of six SCE pillars showed meaningful progress today** — formal specification (harness specs, Concordat protocols), simulation (AWM's Lean proofs, LazyAgent's demand analysis), codes/norms (OSTEON governance, cross-interface authorization), and material datasheets (AIFaultBench, harness components). Licensure and education remain unaddressed.
