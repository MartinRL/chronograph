## D1 — Agentic Engineering

**Parallel subagents are mostly cost sinks for coding tasks — except on hard, modular problems.** A rigorous empirical study comparing single agents vs. main-agent-with-subagents on repository-construction benchmarks (NL2Repo, ProgramBench) found that [parallel subagents raise pass rates by only 1–5 percentage points at up to 3.8× cost](https://arxiv.org/abs/2611.33893). The study identifies three mechanisms where subagents actually help: self-checking (which a single agent can replicate with a one-sentence prompt), fresh context (periodically resetting conversation state outperforms continuing), and modularity (multi-agent runs produce more files and shorter functions). The practical takeaway for agentic engineering pipelines: default to single agents with periodic context resets, and reserve subagent fan-out for tasks where modularity is structurally important. Also relevant to **D4** — the cost multiplier is real and usually unjustified.

**Agents can now build entire LLM serving systems from scratch.** [VibeServe](https://arxiv.org/abs/2605.06068) introduces an agentic loop with an outer planning layer and inner implementation/benchmarking cycle that generates complete serving stacks end-to-end. It matches vLLM and SGLang on standard workloads and delivers 2.3× the goodput of tuned SGLang for a 397B MoE model on AMD MI300As. The key insight is that bespoke systems exploit hardware- and workload-specific opportunities that generic stacks miss. This is a D1 milestone: the agentic engineering loop has moved from writing application code to generating infrastructure. Cross-cuts **D4** — if agents can generate optimized serving stacks per deployment target, the cost of maintaining hand-tuned inference infrastructure drops substantially.

**Partial routing breaks the all-or-nothing model selection problem.** Rather than routing entire tasks to cheap or expensive models, [partial routing](https://arxiv.org/abs/2611.33402) lets a frontier lead model delegate specific subtasks to a cheaper worker based on historical performance data. With δ=0.75, this raised ViBench scores from 70.2 to 78.5 while cutting cost 19%. No model training is required — delegation guidance is derived from past run traces. This is an immediately implementable pattern for any team running multi-step agentic workflows. Cross-cuts **D4**.

**AI code review scales effort against cost — but no setting is a reliable gate.** A [preregistered study](https://arxiv.org/abs/2611.33639) tested Claude 5.5 Opus/Sonnet/Haiku at low/medium/high effort on 90 Django patches. High effort reduced false acceptance from 67% to 45% for Opus, and medium effort was statistically non-inferior to high at 20% less cost. However, every model at every setting still accepted at least 45% of wrong patches. The implication for agentic engineering: AI review is a useful signal, not a gate — it must be layered with stronger verification (property tests, formal specs). Cross-cuts **D4**.

## D2 — AI in the Product

**Firefox integrates open-weight models for in-browser AI.** [Mozilla partnered with Mistral](https://www.infoq.com/news/2026/11/mozilla-mistral-ai-smart-window/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) to offer Mistral Small 4 in Firefox's Smart Window AI assistant, now in beta. ## D3 — Build for Agents

**MCP's trust model has a fundamental privacy hole.** [IntentMiner](https://arxiv.org/abs/2512.14166) demonstrates that semi-honest third-party MCP servers can reconstruct user intent with over 85% semantic alignment by analyzing only authorized metadata — function signatures, arguments, and receipts. No raw query access needed. This is an endogenous vulnerability: the transparency required to execute tool calls inherently leaks intent. For anyone building or consuming MCP services, this means the protocol's modular architecture trades privacy for interoperability unless semantic obfuscation is added at the protocol level.

**MCP enables agents to co-pilot live engineering simulations.** An [MCP server for discrete element simulation engines](https://arxiv.org/abs/2611.33926) lets general-purpose AI agents submit, monitor, modify, and stop long-running simulations while a human modeler works at the same console. Seven language models calibrated a drained triaxial model of Toyoura sand, with 20/21 sessions reaching targets. The tool design principles (correctness, coverage, orthogonality, simplicity) and the dual-user pattern (agent + human sharing a live session) are a reusable template for exposing any long-running computational tool via MCP.

**Agent economic transactions need cryptographic governance boundaries.** [AESP](https://arxiv.org/abs/2603.00318) proposes a layered protocol where agents transact autonomously on crypto-native infrastructure but remain bound to human-defined limits through dual-signed commitments, tiered escalation, and context-isolated privacy. Implemented as an open-source TypeScript SDK with MCP and A2A interoperability. This is early but directionally important: as agents perform economic actions (purchasing APIs, provisioning infrastructure), the governance layer between agent autonomy and human authorization becomes critical infrastructure.

## D4 — Cost of Ownership

**Partial routing directly improves the 2× output / ½× downstream cost equation.** By [delegating cheap subtasks to smaller models based on historical performance](https://arxiv.org/abs/2611.33402), teams get *better* output quality (ViBench +8.3 points) at 19% lower inference cost — a rare case where both sides of the equation improve simultaneously. The technique requires no model training, only trace analysis, making adoption cost minimal. This is the most actionable D4 finding today.

**Subagent parallelism is borrowing speed at 3.8× the cost unless task structure warrants it.** The [empirical study on parallel subagents](https://arxiv.org/abs/2611.33893) shows that for typical coding tasks, the marginal quality gain (1–5 pp) doesn't justify the cost multiplier. The paper's intervention experiments provide a cheaper alternative: a single agent with periodic fresh-context resets makes faster early progress than one that resumes its conversation. Teams running Codex or Claude Code with subagent delegation should audit whether their tasks actually hit the three conditions where parallelism pays off (early self-check termination, context degradation, modularity benefit).

**Agent calibration frameworks formalize the cost of keeping agents production-ready across model/tool changes.** [Agent Calibration under Deployment Change](https://arxiv.org/abs/2609.35149) defines versioned deployment contracts and measures the total cost of maintaining agent qualification — annotation, training, serving, review, and rework. Their diagnostic audits reveal that aggregate scores hide real failures: in a 60-record financial reporting test, five records passed numeric proxies but failed the reporting contract. This is a maintenance cost argument: without formal acceptance contracts, model upgrades create hidden support burden downstream.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with three papers directly advancing professionalization concepts:

**Formal specification is gaining traction, from both ends.** The [AutoformBench](https://arxiv.org/abs/2611.33165) work reveals that the bottleneck in AI-assisted mathematical formalization isn't theorem proving itself — it's *building the missing formal infrastructure* (definitions, intermediate lemmas, connecting scaffolding). This mirrors the SCE thesis precisely: agents can execute within formal specs, but someone must write the specs. The paper's finding that "success depends less on mathematical domain than on models' ability to construct missing formal infrastructure" is the blueprint problem in microcosm.

**Authorization continuity is bounded autonomy made formal.** The [Earned Authority under a Fixed Ceiling](https://arxiv.org/abs/2607.23586) paper proves that under four conditions (complete mediation, sound effect abstraction, attenuating delegation, monitor integrity), agent evolution cannot amplify effects beyond a user-issued ceiling. This is the most rigorous formalization of "bounded autonomy" I've seen — directly analogous to structural load limits in civil engineering. The transition envelope concept (determining whether a grant survives a mutation) maps to the SCE notion of inspectable, constrained agent operation.

**Deployment contracts are acceptance testing for agents.** The [Agent Calibration](https://arxiv.org/abs/2609.35149) paper's "versioned deployment contract" is essentially a building code for agents: it specifies capabilities, precision requirements, and user acceptance criteria, then measures whether a changed agent still qualifies. The source-to-destination mapping (preserved, transformed, added, retired) is a material datasheet for agent capabilities across versions.

Together, these three papers suggest the SCE pillars of *formal spec*, *codes/norms*, and *simulation* are being independently reinvented by researchers who don't use the SCE framing — which is evidence the need is genuine, not theoretical.
