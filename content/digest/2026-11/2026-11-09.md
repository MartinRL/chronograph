## D1 — Agentic Engineering

**Aegis OS reframes agent security as a workspace transaction, not a per-tool-call gate.** [Aegis OS](https://arxiv.org/abs/2611.08516) presents a Rust-based "Agent Operating System Runtime" that wraps coding agents (Claude Code, Codex CLI, Google Antigravity) in kernel-enforced sandboxes with Copy-on-Write shadow workspaces. By shifting authorization from individual tool calls to transactional workspace boundaries, it eliminates 90.7–99.88% of confirmation prompts across 28,087 real calls in 52 coding sessions. Critically, it also exposes interfaces via both MCP and A2A, making it cross-cutting with D3. The attack surface reduction — from 100% success to 0% across 80 attacks in 8 categories — makes this the most credible answer yet to the security-autonomy dilemma that plagues every team running agents with filesystem access.

**Stale instruction files are a silent tax on every agentic coding session.** A [study of 732 agent trajectories](https://arxiv.org/abs/2611.09802) reveals that when AGENTS.md or CLAUDE.md files contain outdated references (wrong test commands, moved directories), agents faithfully follow the stale guidance even when correct information exists elsewhere in the repo. On a stale test command, Claude Sonnet 5.5 burned ~33% more tool calls per run. Worse, no agent in any run repaired the underlying instruction file — the debt compounds silently. This is D1/D4 cross-cutting: the engineering practice of maintaining agent context files is now a first-class cost-of-ownership concern.

**Deliberate pacing proposes a structured theory for when agents should pause for human review.** [This position paper](https://arxiv.org/abs/2611.09550) argues that neither full autonomy nor constant interruption is correct, and that pacing decisions should be context-dependent across the SDLC. The three identified factors — relative cost of human involvement, timing of oversight windows, and cross-phase interdependencies — provide a useful vocabulary for teams designing "human on the loop" workflows. The concept directly maps to the SCE lifecycle's Verify stage: where in the Specify → Plan → Verify → Apply → Observe cycle do you insert human checkpoints?

**Build-and-Find evaluates whether agent-generated codebases are legible to other agents.** The [Build-and-Find protocol](https://arxiv.org/abs/2605.06136) is a benchmark that measures not just behavioral correctness but *inspection effort* — how many tool calls a downstream "finder" agent needs to recover design intent from a "builder" agent's repository. Frontier models now saturate on intent recovery accuracy, but their artifacts differ significantly in legibility. This matters for D1 because in agent-managed codebases, the code is a communication channel between agents across time. A repo that takes 3× more inspection effort is 3× more expensive to maintain, extend, or audit.

**LLM agents discover formally verified quantum programs via collaborative specification synthesis.** [This work](https://arxiv.org/abs/2611.09822) builds a quantum program library in the Lean theorem prover where agent teams synthesize programs against formal specs and verify correctness. Agent collaboration occurs through shared wikis and "organized conferences." The results — up to 290× improvements in quantum arithmetic — are domain-specific, but the *pattern* is broadly applicable to D1: agents operating within formal specification boundaries, with proof obligations that constrain their output, achieving results beyond what classical testing could verify.

## D2 — AI in the Product

**SafeOrchestrate turns natural language intents into formally verified CPS actions via MCP.** [This reference architecture](https://arxiv.org/abs/2611.09364) decomposes NL intents into atomic goals, generates LTL-style specifications, grounds them to device affordances via MCP Thing Descriptions, and checks every candidate action against SMT-backed guardrails before execution. On smart home, greenhouse, and industrial automation tasks, it achieves 100% required action accuracy vs. 13% MCP Execution Similarity for the direct LLM-to-MCP baseline. This is primarily D3 (building for agent consumption) but has strong D2 implications: products embedding LLM-driven orchestration of physical systems need this kind of runtime constraint checking or they will ship unreliable experiences.

**Reversible Multi-Agent Systems propose a control framework for growing agent collectives.** [This research agenda](https://arxiv.org/abs/2611.09054) addresses a problem that will hit any product embedding multi-agent architectures: as agents learn, share memory, and delegate, they can route around restrictions via emergent paths that bypass the original control mechanism while still passing compliance checks. The three identified research problems — tracking capability dependencies, handing off control before mechanisms lose effect, and distinguishing legitimate repair from unauthorized reconstruction — are relevant to any team building products with persistent, learning agent systems.

## D3 — Build for Agents

**Five MCP server architecture patterns are now catalogued with GoF-style rigor.** [This industry experience paper](https://arxiv.org/abs/2606.30317) identifies five recurring patterns across 15 production and public MCP servers: Resource Gateway, Tool Orchestrator, Stateful Session Server, Proxy Aggregator, and Domain-Specific Adapter. Each is documented with context/problem/solution/consequences. Four anti-patterns and cross-cutting concerns (auth, versioning, observability) are also captured. Inter-rater reliability (Cohen's κ = 0.76) validates the taxonomy's consistency. Transport overhead benchmarks show stdio at 0.01ms p50 vs. streamable-http at 0.39ms p50 on loopback. For teams building MCP infrastructure, this is the closest thing to a pattern language the ecosystem has produced — treat it as a design checklist.

**Aegis OS bridges MCP and A2A with identity-pinned egress and content-addressable IPC.** As noted in D1, [Aegis OS](https://arxiv.org/abs/2611.08516) exposes its transactional runtime via both MCP and Google A2A protocols. The L7 egress proxy with method/path-scoped secret injection and outbound DLP, combined with a Content-Addressable Storage bus for inter-agent communication, provides a reference implementation for how agents should exchange artifacts without inflating LLM context windows with raw file contents. This directly addresses the token overhead problem that plagues multi-agent architectures.

## D4 — Cost of Ownership

**Retry storms in LLM engines waste the majority of compute on work that is never delivered.** This directly undermines the 2× output / ½× cost equation: you're paying for 3–8× the prompt tokens you think you're consuming. [Research on vLLM overload behavior](https://arxiv.org/abs/2611.08684) shows that after a transient overload, client retries prevent recovery even when arrival rate drops below capacity. Cancellation alone restored only 12–38% of post-overload calls. The root cause: retries that vLLM executed typically started prefill less than 0.5 seconds before timeout, and aborted executions consumed 79–85% of prompt tokens. vLLM's own token counter missed 33–50% of computed tokens, meaning observability dashboards systematically underreport actual compute cost. Request coalescing — not cancellation, not retry budgets — was the only strategy that delivered every call from overload onward.

**Workload isolation is the fleet-level lever for inference capital efficiency.** [This paper from production serving experience](https://arxiv.org/abs/2611.08999) argues that the extreme heterogeneity of generative AI request costs means a minority of expensive requests determines the operating point for the entire fleet. Workload isolation — routing "like" requests to the same fleet segment — doesn't make expensive requests cheaper, but prevents them from dragging down capital efficiency fleet-wide. The paper positions isolation as a foundation for compounding gains via narrow-band optimization and custom silicon. For teams managing inference infrastructure, this reframes cost optimization from "make everything faster" to "stop letting outliers set your floor."

**CPU-ARC converts reasoning traces into CPU-executable caches at 16–291× lower cost.** [Agentic Reasoning Caching](https://arxiv.org/abs/2611.09891) observes that LLMs "reinvent the wheel" by conflating task-solving with solution execution. Once a task has been reasoned through, the solution can be distilled into a robust, CPU-executable cache that handles new instances of the same problem type. ARCs match frontier LLM performance on mathematical and scientific tasks while being fully explainable and robust to input perturbations. The cost implications for the agentic factory are significant: if even 30% of your agent invocations fall into cacheable patterns, you could reduce inference spend by an order of magnitude on those calls.

## Software Civil Engineering Lens

Today's batch is unusually rich in SCE-relevant developments, with multiple papers independently converging on the thesis that specification-driven constraints are the key to reliable agent operation.

**SafeOrchestrate is the most complete demonstration yet of the Specify → Plan → Verify → Apply → Observe lifecycle in production-adjacent conditions.** The [architecture](https://arxiv.org/abs/2611.09364) literally implements spec generation (NL → LTL), grounding (spec → device affordances via MCP), verification (SMT constraint checking), and guarded execution. The 100% vs. 13% accuracy gap against the unguarded baseline is the strongest quantitative evidence to date that formal specification is not just theoretically desirable but practically necessary for agent reliability.

**The quantum program discovery work provides a compelling proof of concept for "bounded autonomy."** [Agent teams operating within Lean's proof obligations](https://arxiv.org/abs/2611.09822) achieved results that neither humans alone nor unconstrained agents could have reached. The formal specification language (Lean) acts as the SCE "blueprint," and proof verification acts as the "simulation/inspection" step. This is the clearest example of agents producing novel engineering artifacts that are *provably correct by construction* — exactly the paradigm shift SCE predicts.

**OmniLink advances the "simulation" pillar for concurrent systems.** [Specification-based trace validation against TLA+ specs](https://arxiv.org/abs/2601.11836) with substep linearizability semantics is directly analogous to structural simulation in civil engineering — checking that the as-built system conforms to the as-designed specification. The fact that it uncovered a previously unknown bug in a state-of-the-art lock-free data structure validates the approach's practical value.

**Build-and-Find introduces "artifact legibility" as an engineering quality metric.** The [protocol](https://arxiv.org/abs/2605.06136) separates behavioral correctness (does it work?) from structural legibility (can another agent understand it?). In civil engineering terms, this is the difference between a building that stands and a building whose engineering drawings allow future contractors to safely modify it. As codebases become agent-managed communication artifacts, legibility becomes a *material property* that must be measured and optimized.

**The stale instruction file study is a cautionary tale about the absence of "codes and norms."** Without a norm requiring that agent instruction files be validated against the codebase — analogous to requiring structural drawings to match as-built conditions — [documentation debt silently compounds](https://arxiv.org/abs/2611.09802) in every session. This is precisely the kind of failure that professionalized engineering disciplines prevent through mandatory inspection regimes.

The overall signal today: we are accumulating evidence across multiple independent research groups that the specification-driven, formally-verified approach to agent engineering is not just aspirational but demonstrably superior in practice. The gap between "agents with specs" and "agents without specs" is consistently measured at 5–10× across safety, accuracy, and cost dimensions.
