## D1 — Agentic Engineering

**Claude Code's secret-leaking "Don't Ask Again" feature is a case study in how agentic convenience creates systemic risk.** Security firm Apiiro discovered that Claude Code stored user-approved permissions in `claude/settings.local.json` files on developers' machines, and those files — along with agent chat transcripts — ended up in public repositories. The count: [1,122 secrets in settings files and another 1,160 in git history and shared configs](https://www.infoq.com/news/2026/11/claude-code-leaking-secrets/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering). This isn't a novel vulnerability class — `.env` files have leaked forever — but it's notable because the agent itself created the leak vector as a UX optimization. For teams adopting agentic coding tools, this means your `.gitignore` templates and secret-scanning pipelines need to be updated for every new agent tool you onboard, not just your own application code. (Cross-cuts D4: incident risk.)

**Muru demonstrates what "human on the loop" looks like for a solo AI-assisted engineering effort.** Graham Dumpleton, the creator of mod_wsgi, is building [Muru — an AI-assisted Rust server for Python web apps](https://simonwillison.net/2026/Nov/21/muru/) — and publishing an extraordinarily detailed series (18 posts in 3 weeks) documenting every design decision. The key insight from his ["AI as a lifestyle choice"](https://simonwillison.net/2026/Nov/21/muru/) reflection: "The AI may be doing a lot of the work on the surface, but deciding what isn't good enough yet is still down to me, and twenty years of getting things wrong with mod_wsgi turns out to be useful for that." This is the agentic engineering pattern at its most honest — domain expertise setting constraints and quality gates while AI handles implementation velocity. The project's scope (canary deployments, scale-to-zero, Kubernetes-native operation, built-in tracing toolbar) would be implausible for a solo developer without AI augmentation.

## D3 — Build for Agents

**Google's Agent Compute Engine establishes a new isolation primitive for agent execution.** The service [runs AI agents in isolated microVMs with checkpointing to suspend and resume execution environments](https://www.infoq.com/news/2026/11/google-agent-compute-engine/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering). Critically, the architecture keeps credentials, API keys, and OAuth refresh tokens *outside* the agent sandbox — an external Agent Gateway authenticates requests and injects secrets at the boundary. This is infrastructure designed specifically for agents-as-consumers (D3), and the design pattern — treating agent sandboxes as untrusted execution contexts with an external trust boundary — should inform anyone building agent-facing APIs or services. The checkpointing capability is also notable for long-running agent workflows where cost-per-idle-minute matters (D4). Read this alongside the Claude Code secret leak above: Google's architecture would prevent exactly that class of vulnerability by never placing secrets inside the agent's reachable state.

## D4 — Cost of Ownership

**Agent tooling creating new incident surface area directly threatens the ½× downstream cost target.** The [Claude Code secret leak](https://www.infoq.com/news/2026/11/claude-code-leaking-secrets/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) exposed 2,282 secrets across public repositories — a potential incident requiring secret rotation, audit, and remediation across every affected repo. When agentic tools silently create leak vectors as UX features, the 2× velocity they provide is directly offset by the downstream cost of the security incidents they enable. Every team using agentic coding assistants needs a threat model that treats the agent's local state (config files, transcripts, permission caches) as a first-class attack surface, with automated scanning in CI/CD.

**AWS Lambda GPU Managed Instances reshape the cost curve for self-hosted inference.** [Lambda now runs GPU inference with up to 48 concurrent invocations sharing one model per GPU](https://www.infoq.com/news/2026/11/aws-lambda-gpu-managed-instances/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering), billing at instance price plus a 9.75% fee. The vLLM and SGLang base images require no handler code, reducing operational overhead. However, early reports note an 8-minute cold publish time and no response streaming — both significant limitations for latency-sensitive agentic pipelines. For bursty inference workloads (e.g., agentic QE running test generation in bursts), this could reduce idle GPU spend substantially. For real-time agent-serving, the lack of streaming is a dealbreaker until addressed.

## Software Civil Engineering Lens

Today's items offer a sharp illustration of why the SCE thesis matters, even if no item directly advances formal specification or simulation tooling.

The Claude Code secret leak is precisely the kind of failure that SCE's "codes and norms" pillar is designed to prevent. In civil engineering, there are building codes that mandate fire stops between floors — not because every builder is careless, but because convenience shortcuts compound into systemic risk. The agentic equivalent is: *every agent tool that persists state to disk needs a spec for what it writes, where, and how that state is excluded from version control.* Today, this is left to individual developer vigilance — the craft approach. A professionalized discipline would have automated compliance checks enforced at the pipeline level, analogous to code review being automated by linters.

Muru provides a counterpoint worth studying. Dumpleton's approach — exhaustive public documentation of design rationale, 20 years of domain expertise guiding AI output, explicit acknowledgment that "deciding what isn't good enough yet is still down to me" — is essentially a one-person demonstration of spec-driven development. The 18-post series functions as a living specification, and the domain expertise serves as the simulation model (knowing where things will break before they break). This is the **human on the loop** pattern working well, but it depends entirely on the irreplaceable expertise of one person. The SCE challenge remains: how do you make this pattern transferable to teams without 20 years of specialized knowledge?

Google's Agent Compute Engine moves the needle modestly on the "material datasheets" pillar — by defining a standard isolation boundary (microVM + external gateway) for agent execution, it establishes a reusable infrastructure pattern that teams can adopt without reinventing security architecture. This is infrastructure-as-norm, one step toward codified best practices for agent deployment.
