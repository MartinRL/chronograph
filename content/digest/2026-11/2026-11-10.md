## D1 — Agentic Engineering

**Executable finite-state machines prevent agent drift over long procedural runs.** A [pre-registered study on SOP-Bench](https://arxiv.org/abs/2611.10884) shows that LLM agents reliably drift from stated procedures during long-horizon tasks — restating instructions or resuming merely shifts the shortcut. The fix: an executable FSM that keeps workflow state *outside* the model's context and enforces it at tool calls, state transitions, and turn boundaries. Claude Haiku 4.5 + FSM averaged 139 correct procedural decisions vs. 48 for the best baseline, and crucially outperformed plain Claude Sonnet 4.6 at 38% of the cost. The implication for D1 practices is stark: runtime enforcement architecture matters more than model size for procedural automation. This directly validates the SCE thesis that agents need bounded autonomy within spec constraints.

**InfraRSI applies recursive self-improvement to distributed LLM training infrastructure.** [This system](https://arxiv.org/abs/2611.11558) converts open-ended human commands into verified training optimizations through a five-stage workflow (init → doctor → run → report → apply), achieving up to 2.75× speedup and lifting mean MFU from 17.4% to 30.0% across dense and MoE workloads. The key design insight: rather than greedy single-incumbent optimization, it fits global execution-time and memory models across all trials including OOM failures, then pairs memory-hungry optimizations with memory savers. This is agentic SRE applied to the agentic factory itself — recursive cost optimization. (Cross-cutting: D4)

**Agentic discrete-event simulation reaches 86–97% validity on manufacturing design tasks.** [SimuLean](https://arxiv.org/abs/2611.10602) is an open-source 3D DES simulator built to be programmed by AI agents via domain-level commands. Frontier agents built valid models in 93–105 of 108 attempts, each in about two minutes. In an industrial case, an agent-built model of a robotised welding workshop agreed within 1% of the published expert model — and exposed an error in the expert's original. The residual failure mode is telling: all failures were *silent* (models that build, run, but answer wrong), only caught by comparison with independent reference models. This is a blueprint for Specify → Plan → Verify → Apply in physical systems. (Cross-cutting: SCE)

**AI-guided Lean proof refinement improves mathematical bounds through interpretable blueprints.** [This framework](https://arxiv.org/abs/2611.10961) represents proofs as partially-formalized Lean dependency graphs, then lets an AI agent iteratively tighten intermediate lemmas while preserving the blueprint structure. It produced verified numerical improvements to Grothendieck's constant (improving Krivine's 1977 bound) and Korenblum's constant. The design pattern — human-interpretable dependency structure that constrains agent refinement — transfers directly to software engineering: think of it as "refactor within the architecture" with machine-checked invariants.

**Weight-space programming with model checking produces verified policies without training.** [This pipeline](https://arxiv.org/abs/2611.11604) has LLMs write neural network weights directly, then uses the Storm probabilistic model checker to verify PCTL requirements. All 18 runs achieved optimal probability before any feedback. In one case, dataset repair raised accuracy to 98.4% but broke a safety requirement — one round of model-checking feedback restored it. The pattern of "generate then formally verify" is converging from multiple directions simultaneously.

## D2 — AI in the Product

**RADE reframes LLM deployment as a resource-allocation problem, not a model-selection problem.** [Risk-Adjusted Deployment Efficiency](https://arxiv.org/abs/2611.11659) proposes scoring deployed AI systems on utility net of inference, retry, oversight, and priced expected failure cost, with unpriceable harms as hard budget constraints. The paper examines five deployment regimes where the same model capability demands different rational architectures — selective routing, retrieval, abstention, and human escalation in a common framework. For product teams, the key takeaway: "frontier capability should be treated as a resource to allocate, not a default state to maintain." This directly informs how to architect tiered AI product features. (Cross-cutting: D4)

**R-BED provides a 13-dimension assurance framework for AI system deployment authorization.** [This specification-level methodology](https://arxiv.org/abs/2611.10704) distinguishes between model properties and *configured system* properties (model + prompts + tools + permissions + data + safeguards + context). Its Continuous System Evaluation layer attaches configuration pins and expiry dates to evidence, so that a change invalidates evidence *in proportion* rather than wholesale. The synthetic refund-agent walkthrough demonstrates how task-success metrics can miss consequential control weaknesses that the R-BED procedure flags as missing evidence. Practically, this is a governance framework for product teams shipping agentic features. (Cross-cutting: D4, SCE)

## D4 — Cost of Ownership

**Walmart's PTU-to-pay-as-you-go migration slashed inference costs by 10× while maintaining batch SLA.** Moving from \$100k+/month in provisioned throughput units to ~\$10k/month on pay-as-you-go pricing across [4,700 stores of nightly batch inventory forecasting](https://www.infoq.com/presentations/scaling-multi-agent-llm-batch/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) is the clearest production evidence yet that batch-oriented multi-agent workflows can hit the ½× cost target. The key enablers: MCP grounding to reduce retry loops from schema violations, and architectural separation of agent orchestration from inference provisioning.

**Agency's harness interposition cuts agentic coding costs by up to 35% without touching models or accuracy.** [This platform](https://arxiv.org/abs/2611.12122) interposes between existing agent harnesses (Claude Code, OpenAI Codex) and the LLM API, reducing token use and LLM calls through systems-level optimizations. The finding that harness-side variance impacts cost up to 2.6× on the same model and task — while barely affecting accuracy — means cost optimization is largely an infrastructure problem, not a model problem. This is pure downstream cost reduction for the agentic factory.

**Meta's Muse Ember sits on the Pareto frontier at \$0.12/task (xhigh reasoning), offering 40× savings over Muse Wonder for comparable quality.** [Simon Willison's analysis](https://simonwillison.net/2026/Nov/10/muse-ember/) shows Ember at the efficiency frontier of the full Artificial Analysis leaderboard. For the agentic inner loop (tool calls, coding subtasks, routing, extraction, long document parsing), the pricing is \$0.10/M input / \$0.50/M output at ≤200k tokens — matching GPT-6 Luna and Haiku 5.5 at the base tier but with best-in-class cached input pricing at \$0.004/M. The pricing jumps sharply above 200k tokens (\$0.30/\$1.50), making context window management critical for cost control.

**Agentic self-refinement nearly triples carbon footprint while closing accuracy gaps.** [This carbon-tradeoff study](https://arxiv.org/abs/2611.12128) finds that 3 iterations of GPT-4.1-mini self-refinement close a 16-point accuracy gap to within 1 point of GPT-4.1 single-pass, but at 3× the carbon cost. On SWE-bench Lite, GPT-5.3-codex achieves 81.2% resolution but the carbon estimates are explicitly *lower bounds* — prompt tokens (>99% of total in tool-augmented coding) and tool execution aren't even counted. This is a wake-up call: the 2×/½× equation needs to include energy cost, and agentic iteration patterns that seem "free" at the token level carry hidden environmental and compute costs.

## Software Civil Engineering Lens

Today is an unusually strong day for the SCE thesis, with multiple independent research groups converging on the same core insight: **runtime verification and formal constraints are what make agentic systems trustworthy, not model capability alone.**

The most significant development is [AlphaProof Code](https://deepmind.google/blog/introducing-alphaproof-code/) formally verifying Signal's core encryption with 3M lines of Lean proofs. This is the "material datasheet" pillar of SCE made concrete — machine-checked correctness guarantees for production software, generated by agents but verified by theorem provers. It's the strongest evidence yet that the professionalization gap in formal specification can be closed by AI rather than requiring an impractical expansion of human mathematical capability.

The [FSM agent control paper](https://arxiv.org/abs/2611.10884) directly validates **bounded autonomy**: agents that operate reliably within spec constraints outperform unconstrained agents running on bigger models. The paper's finding that "the runtime, not the model, supplies long-horizon reliability" is essentially the SCE thesis stated in empirical terms. The FSM *is* the blueprint; the agent is the construction crew that follows it.

The [SimuLean discrete-event simulation work](https://arxiv.org/abs/2611.10602) demonstrates the **Specify → Plan → Verify** lifecycle for physical systems, but with a crucial finding: all residual failures were *silent* — models that build, run, and answer wrong. Only comparison with independent reference models caught them. This is the strongest argument yet for the "simulation before construction" pillar: you need independent verification, not just self-consistency. The analogy to structural engineering's independent review requirements is exact.

[R-BED's continuous assurance framework](https://arxiv.org/abs/2611.10704) proposes what amounts to a **building code for AI systems** — a fixed 13-dimension evaluation architecture with evidence validity registers, authority envelopes, and proportional invalidation on change. The authors explicitly distinguish model properties from configured-system properties, which maps directly to the SCE distinction between material properties and structural properties.

The [weight-space programming + model checking paper](https://arxiv.org/abs/2611.11604) adds another verification modality: probabilistic model checking via PCTL. The finding that dataset repair improved accuracy to 98.4% but *broke a safety requirement* — only caught by the model checker — is a perfect illustration of why "codes and norms" (formal safety requirements) must be machine-enforced, not manually inspected.

Taken together, today's papers paint a picture of an emerging professional discipline: agents generate, formal methods verify, runtime architectures enforce. The human moves from writing code to specifying requirements, reviewing blueprints, and authorizing deployments. We're watching the professionalization happen in real time.
