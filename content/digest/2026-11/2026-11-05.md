## D1 — Agentic Engineering

**Iterated writer-grader loops quantify the ceiling of multi-agent feedback for end-to-end tasks.** A [study of 49 writer-grader model pairs](https://arxiv.org/abs/2611.05548) across seven models shows that three rounds of agentic feedback lift average scores from 59% to 76% on complete data-science projects — but roughly half the round-over-round improvement is within-grader noise, and weaker models do not improve stronger ones. Self-grading inflates scores by ~9 percentage points. The practical D1 takeaway: multi-agent review loops have real value, but you need asymmetric pairing (strong grader, weaker writer) and should discount self-evaluation. The ~9pp self-grading bias is a concrete number to build into your loop calibration.

**ViBench 2.0 defines the benchmark for long-horizon agentic product building.** [Replit's new benchmark](https://arxiv.org/abs/2611.05620) models real-world usage: 17 full-stack web products grown over 241 sequential feature requests, judged end-to-end by a browser agent running 544 test plans. The headline finding — 98% test-plan pass rate but only 65% fully-working-product rate for the best models, with no open-weight model delivering even one — exposes the compounding fragility of long-horizon agentic engineering. Critically, across three releases of one model family, pass@1 rose from 3% to 53% while cost per build halved, suggesting the reliability gap is closing but still dominant. *(Cross-cuts D4: the 35% failure rate on completed builds represents direct downstream cost.)*

**Agents can now design their own serving infrastructure, outperforming hand-tuned baselines.** [ServerBench](https://arxiv.org/abs/2611.06841) tasks coding agents with building complete LLM serving systems optimized for dollars-per-dollar (latency-qualified token value per GPU cost). Claude Sonnet 5.5 achieves 4.87× the vLLM reference on Gemma E4B, with 22 of 33 runs producing verified systems. The key insight for D1 practitioners: agents that coordinate capacity improvements with load selection outperform those optimizing either in isolation — experimental judgment and verification of execution paths are the differentiators. *(Cross-cuts D4: directly reduces inference cost of the agentic factory.)*

**Agent-driven LLM compression achieves near-BF16 quality autonomously.** In a companion paper, [CompressionBench](https://arxiv.org/abs/2611.06858) shows coding agents can autonomously compress models to 77.33% downstream accuracy versus 79.56% for BF16, with 29 of 36 submissions passing verification. Agents improved perplexity in 21 of 24 revisions, but complete-model feedback reversed 17 of 79 prior local rankings — highlighting that agentic search benefits enormously from global rather than local evaluation signals. This is agents optimizing the infrastructure stack that runs agents: recursive self-improvement made concrete and measurable.

**Bloomberg's production migration pipeline is the industrial case study the field needed.** Their [Automated Uplift initiative](https://arxiv.org/abs/2611.05457) applied hybrid LLM-deterministic pipelines across ~8,600 repositories (Python packaging + C++ build system), generating 2,333 PRs and completing 729 successful migrations. The architecture maximizes deterministic processing (AST transforms, dependency resolution), confines the LLM to bounded file transformations within pre-computed context, and uses runtime production telemetry as input. The most transferable finding: C++ migrations succeeded at higher rates because compilation and tests could verify changes in-pipeline before human review, while heterogeneous Python repos required more human judgment. *(Cross-cuts D4: the core finding is about downstream cost.)*

**AgentTrustCI brings behavioral contract testing to the Java CI pipeline.** This [JUnit 5 framework](https://arxiv.org/abs/2611.06674) expresses agent behavioral expectations — policy compliance, answer grounding, workflow trajectory — as deterministic replay tests over recorded traces. On 55 synthetic cases across seven enterprise domains, it correctly classifies all 30 injected faults and 25 passing controls with zero missed critical cases. The practical contribution is the pattern: record agent traces, write deterministic assertions against them, run them in CI like any other regression suite. *(Cross-cuts D4: directly addresses the observability and maintenance pillar.)*

## D2 — AI in the Product

**ViBench 2.0 implicitly defines the product experience ceiling for agentic builders.** [Replit's benchmark](https://arxiv.org/abs/2611.05620) is not just a D1 tool — it's a product-level statement about what "build with agents" means: users issue successive feature requests and expect a working full-stack product. The 65% success rate at the product level (versus 98% at the test-plan level) quantifies exactly how much product trust is eroded by long-horizon fragility. For any team shipping an agentic product-building experience, this benchmark should be your acceptance bar.

**Continuous authorization (ACCA) models the trust lifecycle for autonomous product agents.** The [ACCA framework](https://arxiv.org/abs/2611.05632) addresses a real product-design problem: agents that act through tools, delegate work, and change execution environments while prior authorizations are still in flight. The key concept — authority epochs that change when effective authority changes, with stale-action rejection at effect time — is directly applicable to any product embedding autonomous agents that touch consequential resources. The trading-domain regression suite demonstrates the pattern concretely.

## D3 — Build for Agents

**Germline execution defeats data exfiltration through signed MCP tools.** The [Signed, Sealed, Leaked paper](https://arxiv.org/abs/2611.06585) demonstrates a critical trust failure: a legitimately signed MCP tool can embed sensitive data in requests to policy-allowed destinations, bypassing Meta's MCPGuard-Dynamic in every trial. Their solution — germline execution — forks each tool invocation from a data-free base process, providing each copy only the data authorized for its destination. Across 153 attack runs, zero unauthorized disclosures occurred, with invocations completing in 10-49ms (2-28× faster than full tool restarts). This is the most practical MCP security primitive proposed to date, and it's architecture-level rather than inspection-level, which makes it composable.

**Evidence-gated authority provides a formal jurisdiction model for multi-agent review.** The [evidence-gated authority paper](https://arxiv.org/abs/2611.05390) studies when a reviewer agent should be authorized to override an upstream agent's decision. Their gate — requiring mechanically valid evidence of a constraint violation plus a compliant repair before override is permitted — sharply reduces corruption of correct proposals while retaining most error repairs. However, the effect is model-dependent (works for Qwen, fails for Mistral), showing that interface design alone is not a model-independent safeguard. For anyone designing A2A delegation protocols, this is a concrete template for bounded authority.

**ACCA's continuous authorization model applies to multi-agent toolchains.** Beyond the D2 product angle, the [ACCA framework](https://arxiv.org/abs/2611.05632) defines composable Domain Governance Profiles that express domain-specific semantics without granting authority — a pattern directly relevant to B2A and A2A interoperability scenarios where agents from different principals must negotiate trust boundaries dynamically.

## D4 — Cost of Ownership

**Bloomberg's migration report proves that generation cost is no longer the bottleneck — downstream review and deployment cost is.** This directly validates the 2× output / ½× downstream cost equation: the [Automated Uplift initiative](https://arxiv.org/abs/2611.05457) found that LLM-generated migrations were the easy part; the expensive part was owning teams reviewing, testing, and deploying them. Costs dropped when changes could be verified in-pipeline (C++ compilation gates) and when population uniformity allowed fixes to transfer across repos. The actionable insight: invest in automated in-pipeline verification proportional to the heterogeneity of your estate. The 729/2,333 PR success rate (31%) means 69% of generated work created review burden without delivering value — exactly the kind of downstream cost that erodes the agentic speed dividend.

**Conformal Reservation for Orchestration (CRO) halves resource waste for agentic pipelines.** The [CRO algorithm](https://arxiv.org/abs/2611.05392) addresses a pure infrastructure cost problem: agentic pipelines have unknown, heavy-tailed, multi-modal resource demands that emerge at runtime. CRO uses conformal prediction over sliding windows of past traces to make dispatch-time reservations with distribution-free coverage guarantees — roughly halving the resource waste of Chebyshev-bound baselines while being the only method that satisfies coverage targets across all risk levels. For teams running agentic workloads at scale, this is directly applicable to GPU and bandwidth provisioning.

**AgentTrustCI shifts behavioral validation left, reducing incident and observability cost.** The [framework's](https://arxiv.org/abs/2611.06674) deterministic replay tests catch policy violations, grounding failures, and trajectory deviations at build time rather than in production. The 100% detection rate on injected faults (including all 12 critical cases) suggests this pattern could materially reduce production incidents from agent misbehavior — though the authors are careful to note these results cover their authored regression suite, not production accuracy.

## Software Civil Engineering Lens

Today's batch is exceptionally rich for the SCE thesis, with multiple papers independently converging on its core claims.

**"Verified but Vacuous" is the single most important SCE paper this quarter.** The [three-surface decomposition](https://arxiv.org/abs/2611.05590) — verifier acceptance (Surface A), spec binding (Surface B), semantic fidelity (Surface C) — is exactly the kind of rigorous failure taxonomy that a professional engineering discipline requires. The finding that 99.1% verifier acceptance coexists with 1.9% genuine spec binding is devastating: it means LLM-generated "verified" code is analogous to a structural analysis that passes because the loads were never actually applied to the model. This paper should become required reading for anyone building agentic code-generation pipelines. It directly supports the SCE thesis that formal specifications (the "blueprints") must be first-class artifacts, not afterthoughts that the verifier can trivially satisfy.

**The evidence-gated authority and ACCA papers both advance "codes and norms" for agentic systems.** The [evidence gate](https://arxiv.org/abs/2611.05390) is a building code for multi-agent review: you may not override without mechanically valid evidence. [ACCA](https://arxiv.org/abs/2611.05632) is a continuous inspection regime: authority degrades when assurance evidence becomes invalid. Both are moving toward the kind of codified governance that civil engineering takes for granted — but both also demonstrate that these norms are necessary but insufficient without model-level competence (the Mistral failure in the evidence gate) or domain-specific calibration (ACCA's domain governance profiles).

**AgentTrustCI and Bloomberg's pipeline both instantiate the Specify → Plan → Verify → Apply → Observe lifecycle.** AgentTrustCI's [behavioral contracts](https://arxiv.org/abs/2611.06674) are specifications; deterministic replay is simulation; build-time assertion is verification before application. Bloomberg's [in-pipeline compilation gates](https://arxiv.org/abs/2611.05457) serve the same function for code migrations. The Bloomberg finding that C++ succeeded more than Python precisely because it had a stronger verification step is direct empirical evidence for the SCE claim that the "simulation" step (terraform plan for domain logic) is the critical bottleneck in the professionalization arc.

**The "One Scale, Four Texts" paper**, while focused on medical grading, provides a [powerful cautionary example](https://arxiv.org/abs/2611.06569) for specification quality: four texts describing the same international scale produce 26.8% disagreement on referral decisions, and LLMs silently "repair" specification defects even when told to read literally. This is the specification ambiguity problem that Event Modeling and formal specs are designed to solve. If human-written medical specifications are this ambiguous, the specifications we write for agent behavior are almost certainly worse.

**Net assessment:** Today moves the SCE needle significantly forward on the "codes/norms" and "simulation" pillars, while the Verified-but-Vacuous paper opens a new front on the "material datasheets" gap — we need standardized ways to report what "verified" actually means for LLM-generated code, analogous to how structural steel comes with certified yield strength, not just a stamp saying "passed."
