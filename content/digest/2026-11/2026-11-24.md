## D1 — Agentic Engineering

**OpenAI's \$100M ads product built with zero human-written code is both a proof point and a cautionary tale.** At QCon SF, Brian Yang described using [Codex agents with layered testing, sandboxes, and batched PR reviews](https://www.infoq.com/news/2026/11/qcon-sf-openai-lessons/) to build the ChatGPT ads product in six weeks. The key organizational shift: engineers become managers of agents, reviewing batched pull requests rather than writing code. But Yang explicitly called out "code slop" — agents generating plausible but subtly wrong code — and unsafe agent actions as failure modes requiring gradual adoption. The implication for agentic engineering practices: the review bottleneck hasn't disappeared, it's moved from code writing to code judgment. (Also D4 — the downstream maintenance cost of agent-generated slop is unquantified but likely substantial.)

**OpenAI's Pando rearchitects Git for concurrent agent workloads.** [Pando coordinates branch updates independently and reuses stored packfiles](https://www.infoq.com/news/2026/11/openai-git-pando/) to achieve ~80% lower median push latency for multi-agent coding sessions. This is infrastructure-level recognition that agentic coding at scale breaks assumptions baked into Git's serialization model. The design is notable for preserving standard Git workflows — agents and humans share the same tooling — rather than forcing migration to a new VCS. For teams scaling past a handful of concurrent coding agents, this is the kind of plumbing work that becomes mandatory. (Also D4 — push latency directly impacts agent throughput cost.)

**Security-focused prompting is cheap and effective but creates a hidden audit surface.** A [controlled experiment across 400 AI-generated web applications](https://arxiv.org/abs/2611.28408) (Claude Code and Codex CLI, 100 specs × 4 variants) found that appending OWASP-aligned security requirements to the prompt cut first-party findings by ~50% (IRR 0.65). However, it roughly doubled the declared dependency surface, bringing more high-severity dependency advisories. The net effect is positive — the advisory rate per application stayed flat — but the finding underscores that agentic coding defaults become the application's security posture, and that prompt-level controls shift rather than eliminate risk. (Also D2, D4.)

**Self-improving agents are blind to half their own failures.** [Research across five task domains](https://arxiv.org/abs/2611.29807) shows that agents performing recursive self-improvement bring programs to high scores but their self-written runtime checks stay silent on 50%+ of failures when the environment changes. The failures are detectable and repairable — a monitor built from normal-run records catches most of them, and the same agents fix the issues once notified. The gap is in detection, not capability. This has direct implications for any team relying on agent-generated test suites or self-healing pipelines: the agent's confidence in its own checks is systematically miscalibrated. (Also D4.)

**AI-assisted auto-formalization works for pure math but struggles across applied computing layers.** A [DOE-funded study](https://arxiv.org/abs/2611.31033) using Claude Code and Codex for formalizing scientific computing proofs finds that agents succeed on self-contained theorem statements but fail when source material describes computational procedures rather than declarative theorems. They provide a cross-layer taxonomy of failure modes and the forms of expert feedback needed to recover soundness. For engineering leaders, the lesson maps directly: agents excel at well-specified, declarative tasks and degrade predictably as specifications become procedural or implicit.

## D2 — AI in the Product

**Agent-managed financial transactions reveal a trust chasm.** The [Agent Money Benchmark](https://arxiv.org/abs/2611.28610) tested 12 models on 80 payment tasks with simulated sellers, settling purchases in USDC on Solana mainnet via the x402 protocol. Only 3 of 12 models passed without payment or budget errors. Nine fell for seller traps — repeat charges and above-list quotes accounted for 79% of scam events. Estimated waste ranged from \$21 to \$70.8 per \$100 spent depending on the model. For any product embedding agent-driven purchasing (D3 crossover), this benchmark provides the first rigorous framework for evaluating financial trust boundaries. The variance between models is enormous and not predictable from general capability scores.

**The OpenAI ads product story validates the "AI in the product built by AI" loop.** [Yang's QCon talk](https://www.infoq.com/news/2026/11/qcon-sf-openai-lessons/) is notable not just as a D1 story but as evidence that products built entirely by agents can reach \$100M revenue scale in weeks. The compressed timeline challenges conventional assumptions about product quality gates — but also raises questions about long-term maintainability that remain unanswered.

## D3 — Build for Agents

**MCP tool schema changes silently widen agent authority — and nobody's checking.** [SchemaCaps](https://arxiv.org/abs/2611.30750) surveyed 8 MCP clients and scanners and found none re-approves a tool whose input schema widens. Across 604 releases of 39 public MCP servers, 412 of 580 "compatible" schema changes widened some coordinate, and at least 76 added or widened an authority-bearing argument. The paper provides a formal re-binding rule (with Coq proof) that asks for 645 re-approvals versus 1,197 for full schema pinning — a practical middle ground. This is a supply-chain security problem specific to the agent-tool ecosystem: backward-compatible API changes that are semantically authority-escalating. Any B2A surface using MCP should treat this as a P1 risk.

**The Agent Money Benchmark doubles as a D3 interoperability stress test.** The [x402 protocol for per-web-request payments](https://arxiv.org/abs/2611.28610) represents a new class of agent-to-service interface: agents autonomously purchasing data from sellers via standard HTTP with crypto settlement. The benchmark reveals that the protocol works but the agents themselves are the weak link — they can't reliably distinguish legitimate from predatory pricing. Building for agent consumers means building with the assumption that agents will be exploited unless interfaces are adversarially hardened.

## D4 — Cost of Ownership

**Agent retry strategies impose a quantifiable and nonlinear cost penalty on completion rates.** This directly threatens the 2×/½× equation: retries buy marginal completions at accelerating cost, meaning the speed gains from "just retry" are borrowed against an escalating inference bill. [The Retry Tax paper](https://arxiv.org/abs/2611.29133) proves mathematically that under stationary success probabilities, cost per completion is always at least as high as one-shot serving, and marginal cost is nondecreasing. Empirically, an OpenHands configuration goes from 59.7% completion at \$0.70/task to 70.0% at \$1.32/task with 4 retries — an 88% cost increase for 17% more completions. Teams using retry loops should model this curve explicitly and set attempt caps based on value-per-completion rather than raw success rate.

**GPU waste by research agents is massive and solvable.** [ComputeWise](https://arxiv.org/abs/2611.31027) finds that agents doing AI research use only 52% of GPU time on work the final answer actually needed — 22% goes to unnecessary work and 26% sits idle. Naive prompting ("finish faster", "keep GPUs busy") doesn't help. Their open-source harness combining structured prompting with deterministic scheduling code removes 80%+ of excess time. Since token costs are negligible relative to GPU costs for research workloads, this is where the real agentic factory cost savings lie.

**Agentic runbook-driven incident resolution reduces support tier load while self-improving.** A [17-week study across 232 production incidents](https://arxiv.org/abs/2611.28441) demonstrates an agentic system that guides human operators through runbook-based mitigation, then evaluates outcomes and suggests runbook edits where it found gaps. The runbook-as-bridge design is clever: it maintains explainability and decouples from the agent system, so the operational knowledge accrues in human-readable artifacts regardless of whether the agent is present. This directly reduces downstream support cost (helpdesk → 2nd/3rd line escalation) while continuously improving the knowledge base that enables self-serve resolution.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with multiple papers providing evidence across the professionalization gap.

**Formal specification and verification are advancing.** The [auto-formalization study](https://arxiv.org/abs/2611.31033) is a direct test of whether AI can produce formal proofs for applied computing — the "blueprints" of SCE. The finding that agents succeed on declarative specifications but fail on procedural ones validates the SCE argument that specification language matters enormously. Event Modeling's declarative, event-centric approach aligns with exactly the kind of specification that agents can formalize; imperative descriptions of "how" remain intractable. This is evidence *for* the thesis: the professionalization path runs through better specs, not better agents.

**The SchemaCaps paper is a "building codes" problem.** The [silent authority widening in MCP schemas](https://arxiv.org/abs/2611.30750) — with its Coq-verified re-binding rule — is exactly the kind of formal norm that the SCE "codes and norms" pillar demands. Today, the agent ecosystem has no code enforcement: 0 of 8 clients check for authority escalation on tool update. The paper's re-binding rule is a candidate building code, and its formal verification approach (Coq proofs, 48 regression tests) exemplifies how such codes should be developed.

**The detection gap in self-improving agents ([blind-to-fix paper](https://arxiv.org/abs/2611.29807)) is a simulation/verification failure.** Agents that can't detect their own failures under changed conditions are analogous to structures that pass initial inspection but fail under unexpected loads. The SCE answer is clear: verification must be external and environment-aware, not self-assessed. The paper's finding that external monitors built from operational records catch what self-checks miss is a direct argument for the "Observe" phase in the Specify → Plan → Verify → Apply → Observe lifecycle — observation must be independent of the system being observed.

**The engineering-around-non-determinism article ([evals, grounding, release gates](https://www.infoq.com/articles/llm-agent-architecture-evals-grounding/)) is the most explicit SCE blueprint today.** Knowledge graphs for grounding, dual-layer eval judges, CI/CD release gates, regression testing against golden datasets — this is the Specify → Verify → Apply pipeline made concrete for agentic systems. The "zero-hallucination compliance" goal maps directly to the Decider pattern's simulation capability: test the domain logic before applying it. This article should be required reading for any team building the kind of bounded-autonomy systems the SCE thesis calls for.

The overall needle movement today: strong evidence that the professionalization gap is real (agents fail in predictable, structurally addressable ways) and that the tools to close it — formal verification, external monitors, schema governance, release gates — are emerging from research. The gap between what's known and what's deployed remains wide.
