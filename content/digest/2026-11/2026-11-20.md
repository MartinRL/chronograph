## D1 — Agentic Engineering

**AWS Emulator: agents writing the tools agents test with.** AWS released a [free, CC0-licensed local emulator for 200+ services](https://www.infoq.com/news/2026/11/aws-emulator-local-testing/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering), notable because agents wrote and maintain all of the code, and AWS publishes per-release fidelity scores. The emulator targets agent test loops — the inner feedback cycle where coding agents validate infrastructure interactions without cloud round-trips. The deliberate omission of IAM evaluation is a significant constraint: agents testing permission-sensitive flows will get false confidence. The practitioner split on trusting unreviewed agent-generated code is itself the story — this is the first major vendor to ship a production-grade tool where the entire codebase was agent-authored, making it a live experiment in D1 maturity. *(Also D3: agents consuming agent-built infrastructure.)*

**Verification-gated workflows for agent-generated hardware.** A [seven-stage verification-gated pipeline](https://arxiv.org/abs/2611.25339) for LLM agents generating RTL (register-transfer-level) hardware code reveals critical limits of agent self-verification. Agents ported a post-quantum cryptographic accelerator to FPGA, but their own test suites killed only 76% of tool-selected netlist mutants. Module-scoped LLM review caught all known flaws in 54/54 sessions, while undirected whole-design review caught them in only 1–3 of 6. The implication for D1 practice: **agent-generated tests are necessary but structurally insufficient; independent mutation testing and formal checks are required verification tiers**, especially for safety-critical outputs.

**Agentic Multiverse Analysis makes robustness testing affordable.** The [AMA framework](https://arxiv.org/abs/2611.25198) deploys 150 autonomous coding agents on the same dataset and research questions, finding they disagree through the same defensible methodological forks human analysts use — but over a narrower range. When exposed to exemplar reports, dispersion collapsed through imitation rather than analysis, a cautionary finding about agent herding. The practical takeaway for D1: multi-agent analysis of specification robustness now costs "hours of agent time and tens of dollars per paper," making what was previously unaffordable sensitivity analysis routine. *(Also D4: inference cost measured in tens of dollars for meaningful verification.)*

**Anchor and Check: a deterministic reconciliation contract for LLM decisions.** The [three-call contract pattern](https://arxiv.org/abs/2611.25818) — commit a greedy answer, then check via alternate prompt or alternate model family — provides a pure-function gate that automates 70% of items while still acting on only 16% of errors. The key D1 insight: cross-family checks raise AUROC by 1.7–4.0 points over same-model temperature checks at every budget, confirming that model diversity in verification loops is structurally superior to same-model sampling.

**Four-level validation protocol for LLM-generated digital twin specs.** A [protocol testing HVAC digital twins](https://arxiv.org/abs/2611.25471) generated from LLM-written declarative specifications reveals that 98.6–100% of specs build successfully, but only 50–98.6% achieve behavioral equivalence with reference models. The gap concentrates in physically complex subsystems (desiccant rotors). This maps directly to D1: agents can generate syntactically valid, convergent specifications that are physically wrong — the "builds and runs but doesn't work" failure mode is the dominant risk in spec-driven agent workflows.

## D2 — AI in the Product

**Medical LLM reasoning: hallucination cascades in multi-agent clinical systems.** A [critical review of agentic clinical reasoning](https://arxiv.org/abs/2611.25898) identifies the "agentic hallucination cascade" — multi-agent and tool-augmented systems propagate and amplify early reasoning errors across steps. Systems with symbolic veto layers (ontology reasoners, knowledge graphs) report large safety gains within their encoded domains but are tested only in single studies on small samples. The review argues that regulation should audit reasoning trajectories, not just accuracy on static benchmarks. For D2 product builders: if your product embeds clinical agents, process-level verification isn't optional — it's the difference between a defensible product and a liability.

**Authorization-bounded agents for physical-world autonomy.** The [self-driving laboratory architecture](https://arxiv.org/abs/2611.25043) demonstrates a production pattern for D2 products where agents control physical instruments: the agent operates within human-defined campaign limits, state-changing operations require explicit authorization, and all actions are auditable. The agent matched expert chemists' rankings while measuring the highest-yielding condition in ~7 injections vs. 14.5 random. This is a template for any product embedding agents that actuate physical systems — bounded autonomy with verifiable audit trails.

## D3 — Build for Agents

**Google donates Agent Substrate and gVisor to CNCF.** [Google's donation](https://www.infoq.com/news/2026/11/google-substrate-gvisor-cncf/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) of Agent Substrate (agent orchestration infrastructure) and gVisor (sandbox kernel) to the CNCF under vendor-neutral governance is a D3 inflection point. It signals that agent sandboxing and orchestration primitives are becoming commodity infrastructure rather than differentiators. For teams building B2A services: target CNCF-governed primitives as your interoperability layer rather than vendor-specific agent runtimes that may fragment.

**ChainIT Authority Protocol for agentic commerce.** The [Provable Authority protocol](https://arxiv.org/abs/2610.22899) addresses a gap that becomes operationally urgent in agent-to-agent transactions: a software agent can produce a valid cryptographic signature while acting outside its delegated purpose, after its sponsor's authority has changed, or on transaction details that differ from those a human approved. The protocol separates durable identity from versioned authority records, binds approvals to canonical transaction digests, and reserves capacity atomically under concurrency. The Agent Subject Profile adds workload registration and attested key hierarchies specifically for AI agent subjects. This is foundational D3 infrastructure for any organization expecting agents to execute financial transactions.

**AWS Emulator as agent-consumable infrastructure.** The [CC0-licensed emulator](https://www.infoq.com/news/2026/11/aws-emulator-local-testing/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) is explicitly designed for consumption by coding agents' test loops — not just human developers. The published fidelity scores per release are themselves a form of machine-readable service contract. This positions it as a D3 artifact: infrastructure that is built for agents to consume, with programmatic quality signals agents can reason about.

## D4 — Cost of Ownership

**Agent runtime environments waste 59× resources due to session reservation patterns.** This directly undermines the 2× output / ½× downstream cost equation: if scaling agent conversations scales infrastructure linearly when it should scale sub-linearly, you're borrowing speed against infrastructure costs. On [Amazon Bedrock AgentCore](https://arxiv.org/abs/2611.26480), agents waited a median of 2.7 seconds per model reply, then computed for 5–40 milliseconds — but each conversation reserved a full VM with its own memory for the entire session plus 15 minutes after. The result: 1,000 conversations reserve 1,000 environments to do the work of 2–15 processor cores. The fix is two-fold: clients can close sessions explicitly (no platform change needed), and platforms should allow environment sharing (64 conversations sharing one environment need 59× fewer resources with ≤40ms p99 delay). Of surveyed agent runtimes, only one partially supports sharing, because isolation for tool/code execution is an unsolved tension.

**Prefill energy costs scale quadratically with input context length.** A [systematic profiling](https://arxiv.org/abs/2610.39621) of compute time and energy across prefill and decode phases shows that while decode costs scale linearly with output tokens, prefill costs exhibit both linear and quadratic scaling with input length. Agentic workflows characteristically have large input contexts (tool outputs, conversation history, retrieved documents), meaning standard per-output-token cost estimates systematically undercount the real expense. The paper demonstrates that compute time serves as a reliable proxy for energy when direct measurement is unavailable — a practical observability technique for teams that can't instrument inference providers' hardware.

**Tether's sandbox-per-action model: security cost vs. throughput.** [Tether](https://arxiv.org/abs/2611.25599) executes each proposed agent action in an ephemeral isolated sandbox before allowing it to proceed, adding latency to every action but achieving 100% block rate on in-scope attacks with <5% false positives. This is a downstream cost trade-off: the sandbox overhead is real infrastructure cost, but it eliminates incident categories (unauthorized network exfiltration, privilege escalation, persistent filesystem mutations) that would otherwise create support-tier and incident-response costs orders of magnitude larger.

## Software Civil Engineering Lens

Today's batch is unusually rich in SCE evidence, with five papers scoring 5/5 on the SCE dimension. The common thread: **agent-generated artifacts that build and run are not the same as artifacts that are correct, and the gap requires engineering-discipline verification practices to close.**

The [FPGA verification paper](https://arxiv.org/abs/2611.25339) is the day's strongest SCE case study. It demonstrates that agent-generated tests create a false sense of coverage — killing 76% of mutants looks adequate until you realize that specification-derived tests guided by surviving mutants raise kill rates from 48% to 74% on specific modules. This is exactly the "material datasheets" and "simulation before construction" pillar: you need independent, specification-derived quality gates, not just tests generated by the same process that wrote the code.

[Tether](https://arxiv.org/abs/2611.25599) advances the "codes and norms" pillar by encoding security policies in Lean 4 — a formal proof language — and verifying that policies satisfy global invariants. This is the software equivalent of building codes: not guidelines, but formally verified constraints that agents cannot violate at runtime. The embedded DSL approach makes this accessible without requiring every team to become formal methods experts.

The [Anchor and Check reconciliation contract](https://arxiv.org/abs/2611.25818) and the [authorization-bounded agent architecture](https://arxiv.org/abs/2611.25043) both embody the "bounded autonomy" principle from SCE: agents operate freely within spec constraints, with deterministic gates that escalate to humans when confidence is low. The reconciliation contract's pure-function decision gate (five outcomes, only Agree is acted on) is a textbook Decider pattern applied to LLM output verification.

The [HVAC digital twin validation protocol](https://arxiv.org/abs/2611.25471) is notable for its four-level hierarchy: static validity → model build → simulation convergence → behavioral equivalence. This mirrors the SCE lifecycle (Specify → Plan → Verify → Apply → Observe) and demonstrates that **the gap between "converges" and "correct" is where the engineering discipline lives**. Seven of eight LLMs build successfully in 98.6–100% of trials but achieve behavioral equivalence in only 50–98.6%. This is the construction industry's distinction between "the building stands up" and "the building meets load specifications."

The [AMA framework's](https://arxiv.org/abs/2611.25198) finding that agent dispersion collapses through imitation rather than analysis when shown exemplars is a warning for SCE: standardization through mimicry is not the same as standardization through principled engineering judgment. If we build our codes and norms as exemplar templates, we'll get conformity without understanding — the agent equivalent of cargo-cult engineering.

**Net assessment**: Today moves the SCE needle meaningfully forward on three of six pillars — formal spec (Tether's Lean 4 DSL), simulation (HVAC protocol, FPGA mutation testing), and codes/norms (authorization-bounded architectures). The remaining gaps — licensure, education, material datasheets — remain unaddressed.
