## D1 — Agentic Engineering

**Spec-Driven Development gets its first empirical audit trail.** A [study of gated SDD workflows with Claude Code](https://arxiv.org/abs/2611.05094) analyzes nine features across seven projects — Fortran solvers, Python programs, even books. The workflow enforces stage gates: a reviewer subagent checks artifacts against defect lists, an executor subagent may only touch declared files, and file-inventory checks run after each task block. Results: 288 of 581 planned tasks completed within constraints, with only one undeclared file change slipping through (and caught by the check). The identified weak point — the orchestrator judging its own compliance — is architecturally significant: it demonstrates that when the model both executes and evaluates, the separation of concerns breaks down. This is exactly the "bounded autonomy" problem SCE predicts. *(Cross-cuts D4: the workflow's audit trail is itself an observability artifact that reduces downstream debugging cost.)*

**Coding agents don't reliably follow AGENTS.md policies, and phrasing matters.** [Research across 86 benchmark tasks](https://arxiv.org/abs/2611.04367) found that conditional phrasing ("if X, then do Y") was followed less often than prescriptive ("always do Y") or explanatory ("do Y because Z") styles. The better of prescriptive vs. explanatory varied by harness-model combination. This is a practical finding for any team writing agent policy files: your specification language isn't just about correctness, it's about compliance probability. Treat AGENTS.md authoring as a prompt engineering discipline with measurable outcomes.

**MaxKernel demonstrates agentic kernel generation matching expert hand-tuned performance.** [This multi-agent system for TPU kernel development](https://arxiv.org/abs/2609.04523) implements three paradigms: human-in-the-loop for collaborative design, fully autonomous metric/trace-driven optimization, and graph-based search for design space exploration. All share specialized sub-agents for planning, implementation, self-debugging, testing, and hardware profiling. Evaluated on JaxBench (50 kernel tasks), it matches expert baselines. The architecture — shared sub-agent pool with multiple orchestration strategies — is a reusable pattern for any domain where you need both interactive and autonomous modes. [Open-sourced](https://github.com/AI-Hypercomputer/accelerator-agents/tree/main/MaxKernel). *(Cross-cuts D4: reduces the need for scarce GPU kernel experts.)*

**"Disposable Implementations" reframes the purpose of software engineering.** This [position paper](https://arxiv.org/abs/2611.04383) proposes that if coding agents can regenerate implementations from requirements, tests, architectural constraints, and operational records, then *maintenance* shifts from patching code to curating the artifacts that survive replacement. The authors coin "regeneration" as a routine alternative to maintenance, arguing it could eliminate technical debt — but warn that existing code contains undocumented safeguards and assumptions that specs and tests don't capture. A regenerated system may pass all tests and still lose behavior that matters in production. This is the most direct academic engagement with the SCE thesis's core claim: **the specification, not the implementation, is the durable engineering artifact.**

## D2 — AI in the Product

**CONFIRM demonstrates deterministic gates for governing autonomous scientific agents.** The [CONFIRM framework](https://arxiv.org/abs/2611.01449) separates running an analysis from deciding which findings to report, using five deterministic gates (multiplicity, confounds, power, analytic stability, replication). On NeuroClaimBench (489 executable claims), it reduces false support of control claims from 23–38% to at most 3%. The key insight applies broadly to any D2 product embedding autonomous agents: LLM judges endorse confounded findings even when shown the confound as evidence. If your product has agents making consequential decisions, you need deterministic policy gates, not LLM-as-judge.

## D3 — Build for Agents

**MCPGuard exposes systemic conformance gaps in official MCP SDKs.** [This automated framework](https://arxiv.org/abs/2611.03662) uses dual-track analysis — structural (JSON Schema alignment) and behavioral (normative prose rule extraction) — to find specification constraints that SDKs silently omit. It confirmed 13 gaps in the official Python SDK (1.26.0) and 19 in TypeScript (1.29.0), none of which two black-box baseline tools detected. Crucially, tests on open MCP servers show these gaps *systematically propagate downstream*. For anyone building B2A interfaces or relying on MCP for agent interoperability, this is a supply-chain risk: your server may be silently non-conformant because the SDK you built on doesn't enforce the spec.

**Global Coherence formalizes why multi-agent systems fail even when every agent is locally correct.** The [Observation-Aliasing Impossibility Theorem](https://arxiv.org/abs/2610.02036) proves that when look-alike worlds require different actions, no amount of reasoning, role assignment, or sampling can guarantee correctness — the best randomized policy succeeds with probability 1/k. The practical remedy: a *harness* that owns shared state and decides validity, while models only propose actions. On TeamBench, teams overspent shared budgets in 5/5 runs; showing the live count still failed 4/5; a harness owning the budget achieved 0/5 failures. This has direct implications for A2A protocol design: agent-to-agent coordination needs a coherence harness, not just message passing. *(Cross-cuts D1 and D4: the harness pattern reduces multi-agent incidents.)*

## D4 — Cost of Ownership

**Context compaction can cut inference costs up to 7× without meaningful accuracy loss.** [Research from NVIDIA](https://arxiv.org/abs/2611.05306) demonstrates that later tokens are up to 7× costlier to generate than earlier ones on frontier open-weight models. Through frequent compaction — aggressively summarizing context between steps — frontier models maintain task accuracy across long-horizon and long-input tasks, including software engineering workloads where agents take at most one action per context. The concept of "semantic state space models" (SSSMs) they outline suggests a fundamental architectural shift: agentic loops should be designed for minimal context carryover, not maximal context windows. This directly improves the 2× output / ½× cost equation by reducing the token cost of each agentic step without reducing capability.

**Continuous diagnostics for agent traces turns nondeterministic failures into actionable engineering issues.** Cisco's [Signals framework](https://arxiv.org/abs/2611.04507) taxonomizes 45 problem types across eight families, distinguishing realized failures, risk exposures, and inefficiencies. Each "Signal" groups related findings and includes developer actions and verification checks. At 91.43% F1 (18 points above one-pass LLM baseline), this is production-grade observability for agentic systems. It addresses the downstream cost equation directly: agents that waste resources or make incorrect decisions *even when tools work normally* are invisible to traditional monitoring. Signals makes these visible and remediable.

**CacheBridge reduces multi-model serving latency by 30–98% through cross-model KV cache transfer.** [This system](https://arxiv.org/abs/2609.00891) addresses a growing cost in agentic architectures: when requests move across models (via routers, cascades, or agent workflows), every switch forces re-prefill of history. CacheBridge's attention-calibrated KV mapper uses 8–12× less memory than alternatives while retaining 97–103% of re-prefill quality. In Qwen3 14B→32B agent serving, it cuts mean time-to-first-token by 30–98% at 1–24 QPS. For multi-model agentic pipelines, this directly reduces both latency-driven support costs and the inference cost of the agentic factory itself.

**ROCm InferaSim reduces LLM serving configuration search from 25,000 GPU-hours to 9.1.** [AMD's simulation approach](https://arxiv.org/abs/2611.04032) benchmarks each distinct kernel set once ("anchor"), then analytically projects to other configurations. Across 226 configurations, 11 anchors took 9.1 GPU-hours with 8.1% median error on time-per-output-token. This is a cost-of-factory optimization: finding optimal serving configurations is currently a major capex drain, and simulation reduces it by ~2,750×.

## Software Civil Engineering Lens

Today is arguably the most SCE-significant day in recent memory, with three papers directly engaging the thesis:

**The "Disposable Implementations" paper is the clearest academic articulation of the SCE position to date.** It explicitly asks: [if implementations become disposable, what should software engineering preserve?](https://arxiv.org/abs/2611.04383) The answer it converges on — requirements, tests, architectural constraints, and operational records — maps directly to the SCE blueprint concept. But it also identifies the critical gap: existing code contains *tacit knowledge* (post-failure safeguards, undocumented assumptions) that no current specification language captures. This is the "material datasheets" problem — we don't yet have the SCE equivalent of knowing a beam's load capacity. Event Modeling and the Decider pattern are partial answers, but the paper correctly notes that the industry hasn't solved continuity across replacements.

**The Gated SDD audit trail provides the first empirical evidence for the Specify → Plan → Verify → Apply → Observe lifecycle** in practice with coding agents. [The study's findings](https://arxiv.org/abs/2611.05094) validate two SCE predictions: (1) spec-driven workflows enable bounded autonomy (the executor stayed within declared file boundaries), and (2) the remaining failure mode is exactly where human oversight thins out (the orchestrator self-judging). This maps to the "human on the loop" transition — the human approved each stage, but couldn't verify the orchestrator's self-assessment. The next step is clear: the orchestrator's compliance checks need to be deterministic gates, not LLM self-evaluation.

**CONFIRM's deterministic gates for scientific reporting are the "codes and norms" pillar in action.** The [five gates](https://arxiv.org/abs/2611.01449) (multiplicity, confounds, power, stability, replication) are domain-specific building codes — they define what's structurally sound before results can be "occupied." The finding that LLM judges endorse confounded results even when shown the confound is a perfect illustration of why the SCE thesis demands *formal, deterministic* verification rather than LLM-as-inspector.

**The Global Coherence impossibility theorem provides a mathematical foundation** for why multi-agent systems need harnesses (i.e., formal coordination structures) rather than just better models. The [sheaves and groupoids formalism](https://arxiv.org/abs/2610.02036) for ensuring local-to-global consistency is exactly the kind of mathematical infrastructure that characterizes a mature engineering discipline. The result that refinement keeps sufficient context at 28% of the cost of sharing everything suggests that formal methods can be practical, not just theoretically correct.

Taken together, today's findings strongly support the SCE thesis and begin to reveal its practical boundaries: the specification must capture tacit knowledge currently embedded only in code, deterministic gates must replace LLM self-judgment for compliance, and multi-agent coordination requires formal coherence guarantees. The gap between "this should work" and "this reliably works" is exactly where professionalization happens.
