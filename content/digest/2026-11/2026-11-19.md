## D1 — Agentic Engineering

**MLE Agents run 1,097 experiments autonomously on production search rankers.** This paper from what appears to be a major tech company demonstrates human-on-the-loop ML engineering agents that propose, implement, train, and evaluate model changes on large-scale recommendation systems. The agents achieved a [29.6% acceptance rate across 1,097 completed experiments](https://arxiv.org/abs/2611.23910), with the best model delivering a 0.23% search volume increase in A/B testing. Crucially, the authors find that "the design of the loop around the model is just as critical" as the underlying LLM — harness engineering (parallel training runs, objective calibration, context engineering) matters more than raw model capability. Several accepted improvements were architectural changes the human team had never tried, suggesting agents explore design-space regions human intuition overlooks. This is the clearest evidence yet that D1 agentic engineering delivers real value at industry scale, not just on benchmarks.

**Metrics-in-the-loop prevents complexity rot in long-horizon agent coding.** Chapados, Gagné, and Dziri introduce an [inference-time intervention](https://arxiv.org/abs/2611.23817) that injects cyclomatic complexity and test-coverage feedback into the agent's context after each code-changing turn. Across three benchmarks and four models, complexity feedback significantly reduced "erosion" (complexity concentration) without hurting correctness. This is agent "re-railing" — catching degradation before it becomes the foundation the agent keeps building on. The practical implication: a cheap static-analysis check per turn can prevent the downstream maintenance explosion that makes agentic speed borrowed rather than real. (Cross-cutting: D4 — directly addresses the ½× downstream cost requirement.)

**EnvAgent automates Docker environment construction for scientific repos.** [ENVAGENT](https://arxiv.org/abs/2611.23258) coordinates multiple specialized agents (repository analysis, planning, Dockerfile synthesis, iterative failure repair) to build verified execution environments. It successfully constructs 43.5 of 54 environments vs. 23.5 for Codex/Claude Code. This matters for D1 because environment setup is one of the most time-consuming and least glamorous parts of agentic engineering pipelines — automating it removes a persistent bottleneck in both development and CI/CD contexts.

**Governed harness with append-only ledger reveals hidden agent failures.** [Wong (2026)](https://arxiv.org/abs/2611.23678) separates the control plane from the LLM proposer: a governance layer owns each trial's lifecycle, checks edit scope, enforces keep/discard decisions, and writes to an immutable ledger. Across 1,445 trials on six ML tasks, the ledger exposed failures invisible to outcome-only scoring — including an entire arm where all 120 trials failed and a reset bug only reproducibility hashes caught. A matched counterfactual showed an ungoverned loop lost records of 43 of 50 trials. The pattern is straightforward to implement and should be table stakes for any autonomous experimentation system. (Cross-cutting: D4 — observability; SCE — formal lifecycle governance.)

**Software thermodynamics quantifies token waste in agentic coding.** [Aspuru-Guzik and Bernales](https://arxiv.org/abs/2611.23375) propose decomposing agent token expenditure into "work" (tokens that advance the task) and "heat" (tokens in model calls that leave the change unchanged). Their experiments show ~80% of tokens in successful runs are heat, and the "free energy" of a coding change is only 14–22% of total cost. The framework also shows coding costs 1.1–1.5× more than uncoding (reverting), and software "temperature" correlates with model sampling temperature. While the thermodynamic metaphor may be overfit, the core insight — that the vast majority of tokens are wasted — provides a principled optimization target. (Cross-cutting: D4 — directly quantifies inference cost inefficiency.)

**Automated audit hits a measurable ceiling: 30% recall at 16% false-flag rate.** [Dong (2026)](https://arxiv.org/abs/2611.23250) studies a shipped two-tier audit system (model auditor + deterministic checks) and measures its limits. On general-purpose code, eight readings reach 30% recall with 16% false flags on correct code. The deterministic tier flagged zero clean items but couldn't detect consistent errors; the model tier caught some but introduced its own errors. For scientific code, reframing the task cut false flags from 68.7% to 36.0%. This provides concrete bounds for what automated review can and cannot do — essential calibration for any team relying on AI-generated code review. (Cross-cutting: D4 — quality assurance cost.)

## D2 — AI in the Product

**Semantic specifications as the primary artifact, code as disposable output.** [Di Santi (2026)](https://arxiv.org/abs/2611.23249) argues that high-level source code should yield its primacy to a semantic specification S = (R, C, I, T, O), from which agents generate, validate, and regenerate executable artifacts. The experiment shows multiple independently generated LLVM artifacts producing the same observable outcomes under a shared specification and oracle. While this echoes decades of model-driven development (the paper explicitly traces lineage through CASE tools and GeneXus), the new ingredient is agents capable of regeneration on demand. For product teams, this reframes the build artifact: if the spec is authoritative and code is disposable, product investment should concentrate on specification quality. (Cross-cutting: D1, SCE.)

**SCAFFOLD formalizes reuse trust for agent skills.** [Cho and Gupta](https://arxiv.org/abs/2611.23990) introduce the concept of a Warranted Reuse Claim (WRC) — a defeasible, context-bound authorization for reusing an agent skill. The framework addresses the problem that a skill passing tests yesterday may not be justified for reuse today if permissions, dependencies, or specifications changed. While this is a formalized problem statement rather than an implemented system, it directly addresses B2A interoperability: agents consuming other agents' skills need a trust protocol. (Cross-cutting: D3 — agent interoperability; SCE — assurance cases.)

## D3 — Build for Agents

**Warrant-Preserving Evidence Transport as an agent-to-agent trust protocol.** The [SCAFFOLD paper](https://arxiv.org/abs/2611.23990) is the strongest D3 signal today. Its Warranted Reuse Claim (WRC) framework — tying skill reuse authorization to versioned evidence, assumptions, and identified defeaters — is essentially a contract protocol for agent skill libraries. The practical implication for B2A: if you're building a skill or tool marketplace for agents, WRCs offer a principled alternative to "it passed tests last time." The three-valued applicability model (valid / invalid / undetermined) and asymmetric context-transfer judgments are directly implementable as metadata in an MCP-style tool registry.

**EnvAgent as infrastructure-level agent service.** While primarily a D1 story, [ENVAGENT](https://arxiv.org/abs/2611.23258) also matters for D3: it demonstrates the kind of infrastructure service that agentic systems need to consume. An agent that can spin up verified execution environments on demand is a capability other agents will want to invoke, making it a natural candidate for exposure via A2A protocols.

## D4 — Cost of Ownership

**Complexity feedback directly protects the 2× output / ½× downstream cost equation.** The [metrics-in-the-loop](https://arxiv.org/abs/2611.23817) approach demonstrates that without active complexity management, agentic coding speed creates a maintenance time bomb — complexity concentrates in agent-written code, and agents then build on that complexity, compounding it. By injecting cyclomatic-complexity feedback per turn, the downstream cost of the code (maintenance burden, incident risk from complex functions, review effort) is held in check without slowing the agent's output rate. This is the most practically deployable finding today for anyone worried about agentic speed being borrowed against future tech debt.

**Timeout cascades cut inference costs 33% without accuracy loss.** [Zhou et al. (2026)](https://arxiv.org/abs/2611.24324) evaluate 36 open-weight models and find the accuracy gap between small and large models concentrates on hard tasks. A simple cascade — try the small model with a timeout, escalate to the large model on failure — achieves [up to 33% GPU-hour reduction](https://arxiv.org/abs/2611.24324) on SWE-bench Verified while matching accuracy. The cascade nearly matches an oracle task-router, meaning you don't need a learned routing model. This directly reduces the cost of the agentic factory itself with minimal engineering complexity.

**HardwareDx reduces GPU-platform downtime 18.3% and QA time 28.3% at Google scale.** [HardwareDx](https://arxiv.org/abs/2611.23398) uses a graph foundation model for automated datacenter machine diagnosis, deployed in production across GPU and TPU fleets. The 18.3% downtime reduction on GPU platforms and 28.3% QA acceleration directly lower the infrastructure cost floor on which agentic workloads run. For any organization running significant inference workloads, this represents a compound saving: less downtime → higher utilization → lower effective cost per token.

**Local inference cost quantified for domain-specific agent loops.** [Li et al. (2026)](https://arxiv.org/abs/2611.24880) measure the actual power, energy, token, and time costs of running agentic simulation loops on local hardware for power electronics tasks. For organizations that cannot use cloud inference due to data sovereignty or export controls, this paper provides the first systematic cost model for on-premises agentic deployment — an increasingly relevant concern as agentic engineering expands beyond software into regulated engineering domains.

## Software Civil Engineering Lens

Today's batch is remarkably SCE-aligned — several papers independently converge on core SCE principles without using the vocabulary.

**Specification as authority is gaining empirical support.** The [semantic artifacts paper](https://arxiv.org/abs/2611.23249) explicitly proposes S = (R, C, I, T, O) as the maintained authority from which code is regenerated on demand. This is the SCE thesis in formal notation: the blueprint is the artifact, the building is disposable. The demonstration that multiple independently generated LLVM artifacts produce identical observable outcomes under a shared oracle is a small but meaningful existence proof for Spec-Driven Development. The connection to Event Modeling is direct — if your semantic specification captures the system's behavior in terms of events, commands, and views, the implementation becomes a deployment choice.

**The governed harness paper implements the Specify → Verify → Observe lifecycle.** [Wong's control plane](https://arxiv.org/abs/2611.23678) that owns trial lifecycle, enforces edit scope, and writes to an append-only ledger is the **Verify → Observe** portion of the SCE lifecycle, applied to agent experimentation. The governance metrics (invalid-action rate, repeated-bad rate, provenance completeness) are essentially **codes and norms** for agentic operation — testable standards that constrain agent behavior within defined boundaries. This is bounded autonomy operationalized.

**Metrics-in-the-loop is real-time simulation feedback.** The [complexity feedback approach](https://arxiv.org/abs/2611.23817) is analogous to structural analysis running during construction — measuring whether the thing being built meets engineering standards before the next layer goes on top. In SCE terms, this is the **simulation** pillar: cheap, automated verification that runs continuously rather than as a post-hoc audit.

**SCAFFOLD's Warranted Reuse Claims parallel professional licensure.** The [WRC framework](https://arxiv.org/abs/2611.23990) — requiring context-bound, evidence-backed, defeasible authorization for skill reuse — mirrors how civil engineering handles material certifications: a steel beam certified for one load profile isn't automatically certified for another. This addresses the **material datasheets** and **codes/norms** pillars simultaneously.

**The automated audit ceiling paper grounds expectations.** [Dong's finding](https://arxiv.org/abs/2611.23250) that model-based audit tops out at ~30% recall with diminishing returns is important calibration: it tells us where human-on-the-loop review remains essential. In SCE terms, this defines the current boundary of automated inspection — analogous to knowing which welds need human NDT and which can be machine-inspected.

**Net assessment:** Today moves the SCE needle meaningfully. We're seeing independent research groups converge on the same structural insights — specs over code, governed lifecycles, continuous verification, bounded trust — that constitute the professionalization thesis. The gap remains in integration: no one has yet assembled these pieces into a coherent end-to-end engineering discipline with the institutional backing (standards bodies, certification, education) that civil engineering has. But the technical ingredients are accumulating faster than the institutional capacity to adopt them.
