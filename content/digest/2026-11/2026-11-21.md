## D1 — Agentic Engineering

**AWS Emulator: agents building the test harness for agents.** AWS has released a [free, CC0-licensed local emulator](https://www.infoq.com/news/2026/11/aws-emulator-local-testing/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) for 200+ services, generated entirely from public API models and — crucially — written and maintained by agents, not human engineers. Each release ships with per-service fidelity scores. The intent is explicit: this is infrastructure for the test loops of coding agents (D1/D3). The strategic question is whether agent-generated emulators can be trusted for correctness-critical paths; IAM evaluation is explicitly excluded. For teams running agentic CI/CD, this is the most significant new piece of test infrastructure this quarter.

**MiracleGro: an agentic system autonomously improving CPU microarchitecture.** Researchers built [MiracleGro](https://arxiv.org/abs/2611.26517v1), an agent that analyzes cycle-level RTL behavior, identifies performance bottlenecks, and writes RTL improvements to the BOOM out-of-order core — achieving an 85% IPC speedup and 27% frequency improvement on SkyWater 130nm, translating to a 2.34× wall-clock speedup on SPEC CPU2017 intspeed (30 trillion instructions). This is a compelling example of the agentic engineering loop — Observe → Diagnose → Plan → Apply — operating at a level of complexity (hardware design) that typically requires large industry teams. It demonstrates that agentic workflows can produce measurable, verifiable improvements in domains far beyond software.

**Claimed AI-assisted proof of the Riemann Hypothesis.** Mathematician Levent Alpöge [claims to have proved the Riemann Hypothesis](https://simonwillison.net/2026/Nov/20/levent-alpoge/) working with Claude, with formal verification in Lean completed "without assumptions." If the proof withstands scrutiny, this is a watershed moment for human-agent collaboration in D1: the agent didn't just assist — it reportedly "far outpaced" the human near the finish. The formalization step matters most for our lens: a proof that compiles in Lean is a proof that meets the highest bar of specification-driven correctness.

**PlayCraft: agents as automated QA for game engagement.** [PlayCraft](https://arxiv.org/abs/2611.26624v1) uses a vision-based agent to play generated games, report its experience, then a crafter agent revises the game to improve learning progression. This is a generalizable pattern for D1: agent-as-tester generating structured feedback that drives iterative refinement. The play-report-revise cycle mirrors the Specify → Apply → Observe loop, applied to UX quality rather than functional correctness (D1/D2).

## D2 — AI in the Product

**Token fraud is a material threat to AI product economics.** Claire Vo of ChatPRD [describes a flood of organized token fraud](https://simonwillison.net/2026/Nov/20/token-fraud-is-here-and-its-bad/) — groups abusing free trials to tunnel through her agent and resell inference for building Roblox/Fortnite maps. Attackers even use signature prompts (SVGs of pelicans riding bicycles) to fingerprint underlying models. She's shutting down free trials entirely. For any D2 product exposing an agent interface, this is a new cost category: the marginal cost of a compromised session isn't just tokens — it's the entire unit economics of your free tier, plus the abuse-detection engineering burden.

**PlayCraft shows agents can tune product engagement, not just build features.** The [PlayCraft framework](https://arxiv.org/abs/2611.26624v1) demonstrates agents improving game *engagement* — a subjective, experience-dependent quality — through systematic play-and-revise loops. This is relevant for D2 because it extends agentic product development beyond functional feature generation into the harder problem of experience optimization. The approach generalizes to any product where user experience can be instrumented and iterated upon by agents.

## D3 — Build for Agents

**Google donates Agent Substrate and gVisor to the CNCF.** [Google is placing Agent Substrate and gVisor under CNCF governance](https://www.infoq.com/news/2026/11/google-substrate-gvisor-cncf/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering), making two critical pieces of agent infrastructure vendor-neutral. Agent Substrate provides the runtime substrate for AI agents; gVisor provides the sandbox isolation model. For D3, this is significant: open governance of agent runtime infrastructure reduces lock-in risk and may accelerate interoperability standards. The sandbox question — how to let agents run tools and code safely — is the same problem the "Held While Waiting" paper identifies as the reason runtimes can't multiplex conversations today.

**AWS Emulator as agent-consumable infrastructure.** The [AWS Emulator](https://www.infoq.com/news/2026/11/aws-emulator-local-testing/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) is explicitly designed for agent test loops, not human developer convenience. It publishes machine-readable fidelity scores per service — a "datasheet" approach that lets agent orchestrators decide programmatically whether the emulator is trustworthy for a given test scenario (D3/D4). This is B2A (build-for-agents) infrastructure in its purest form.

## D4 — Cost of Ownership

**Agent runtimes waste 59× environments on idle sessions, directly threatening the 2×/½× equation.** The ["Held While Waiting" paper](https://arxiv.org/abs/2611.26480v1) quantifies a devastating inefficiency on Amazon Bedrock AgentCore: agents wait a median 2.7 seconds per model reply but compute for only 5–40ms, yet each conversation holds an entire VM. Worse, environments stay reserved 15 minutes after a 33-second conversation ends. At 1,000 concurrent conversations, you reserve 1,000 VMs to do the work of 2–15 cores. The fix is conceptually simple — close sessions explicitly and multiplex 64 conversations per environment with ≤40ms added P99 latency — but only one surveyed runtime even partially supports it. If you're scaling agent deployments, this is likely your largest hidden infrastructure cost today.

**Aggron reclaims wasted GPU memory during agent serving, cutting P99 latency 27–31%.** [Aggron](https://arxiv.org/abs/2611.26435v1) addresses the growing KV cache problem for multi-turn agentic workloads by opportunistically compressing caches during head-of-line stalls in the request queue — using compute and memory that would otherwise sit idle. It achieves 1.34–1.40× throughput improvement and 27–31% P99 latency reduction versus state-of-the-art async summarization. Combined with [TideCache](https://arxiv.org/abs/2611.26619v1), which uses layer-wise streaming on CPU-GPU superchips to complete 2.04× more agent turns and reduce P50 TTFT by 1.40–3.05×, we're seeing a wave of inference infrastructure specifically optimized for agentic workloads. These are factory-cost reductions that directly improve the economics of running agent-powered products.

**ROGUE-AI reveals that 86% of costly agent incidents have no attacker — just missed ordinary hazards.** The [ROGUE-AI framework](https://arxiv.org/abs/2611.26553v1) replicated 108 real-world agent security incidents with 89% fidelity. The critical finding for downstream cost: of 72 incidents with real-world harm, 62 involved no adversary — agents simply missed ordinary hazards like a database shared with production. Current defenses focus on prompt injection, but these incidents contain no injected instructions. A hazard-specific warning after each tool output reduced harm across all five tested models, while generic warnings of the same length did not. This directly informs the ½× downstream cost target: the cheapest incidents to prevent are the ones where the agent just needs to be told what it's pointed at.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with three independent developments converging on the same point: **the gap between "it works" and "it's correct" is the defining challenge of agentic engineering, and formal methods are emerging as the bridge**.

The [Latent Space piece on formal verification](https://latent.space/p/formal-verification/) frames AI-assisted Lean proving as a weapon against "slop" — the mounting volume of agent-generated code that works but can't be reasoned about. This is exactly the SCE argument: when agents produce output at 10× human speed, the verification bottleneck becomes the binding constraint. If AI can help automate theorem-proving, we get the "simulation" pillar of SCE (mathematical proof as the ultimate terraform plan) without requiring every engineer to become a type theorist.

The [Alpöge/Claude Riemann Hypothesis claim](https://simonwillison.net/2026/Nov/20/levent-alpoge/) — if it holds — is an existence proof of the strongest possible form of specification-driven development: a human specifies the conjecture, an agent finds the proof path, and both verify it in Lean with zero assumptions. That's human-on-the-loop at the highest cognitive altitude conceivable.

[ROGUE-AI](https://arxiv.org/abs/2611.26553v1) provides the negative case: what happens when agents operate *without* adequate specification. 86% of real-world agent harms involved agents doing exactly what they were asked but missing "ordinary hazards" — i.e., environmental invariants that were never specified. In SCE terms, these are building code violations: the agent followed the blueprint but nobody checked whether the foundation was on a floodplain. The finding that hazard-specific warnings work while generic warnings don't reinforces the need for explicit, machine-readable environmental specifications — not just task specs.

The [MiracleGro work](https://arxiv.org/abs/2611.26517v1) demonstrates the Specify → Plan → Verify → Apply → Observe loop in hardware, with cycle-exact simulation as the verification step. That the agent achieved a 2.34× speedup on a human-optimized design suggests that the loop itself — not the agent's raw capability — is the force multiplier. This is evidence for the SCE position that disciplined process (blueprints + simulation + verification) enables bounded autonomy even in complex domains.

**Net assessment**: today moves the needle meaningfully on three SCE pillars — formal specification (Lean + AI), simulation/verification (ROGUE-AI, MiracleGro), and codes/norms (the implicit argument that agent runtimes need environmental hazard specs). The professionalization thesis is gaining empirical support from both the success cases and the failure cases.
