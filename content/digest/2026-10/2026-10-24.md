## D1 — Agentic Engineering

**DoorDash automates feature flag cleanup with a multi-agent LLM system, providing concrete industrial economics.** At DoorDash, 56,000+ feature flags span 623 repositories with 1,659 stale as of May 2026, each requiring 1–2 hours of manual cleanup. Their [end-to-end system](https://arxiv.org/abs/2610.31351v1) integrates MCP for querying live rollout data, Jira ticket processing, and automated PR creation. The results are striking: 90% of PRs were engineer-approved, averaging \$4.79 and 13.8 minutes per cleanup. This is a textbook D1→D4 pipeline — agentic engineering directly reducing downstream maintenance cost. The lessons-learned section on architecting multi-agent systems makes this required reading for any team building similar tooling.

**Adaptive Skill Granularity introduces runtime routing for coding agents, treating skill libraries as controllable execution abstractions.** The [framework](https://arxiv.org/abs/2610.31461v1) proposes that coding agents should dynamically choose between macro-level skills and micro-level tool calls based on task structure and execution state, with explicit macro-to-micro recovery when macros fail. Fixed macro execution is efficient but brittle; the hybrid approach improves robustness. This reframes skill libraries from static retrieval resources to runtime-controllable, verifiable execution units — a meaningful step toward agents that can self-regulate their abstraction level during complex engineering tasks.

**Agentic corpus auditing finds 5.3% machine-generated contamination in FineWeb2 for under \$3 per run.** Researchers used a [tool-using LLM agent as a "corpus debugger"](https://arxiv.org/abs/2610.31636v1) that explores data through a budgeted read-only API and compiles findings into executable tests. On Slovak FineWeb2 (26.5M documents), three agent runs at \$2.21–\$2.84 each identified seven issues including a 1.4M-document content farm. The compiled test suite then scans the full corpus in 0.7 seconds without a GPU, compared to \$12k–\$90k for LLM classification. This agent-generates-tests-then-runs-them pattern is a powerful D1 template: use expensive inference once to produce cheap, reusable verification artifacts. (Also D4 — dramatically reduces ongoing QA cost.)

**BrickWright achieves 100% physical validity for agent-generated LEGO builds by providing assembly validators.** The [framework](https://arxiv.org/abs/2610.31651v1) shows that baseline agents (GPT-6 Luna through GPT-6 Astra) achieve only 9–69% valid assemblies, but with BrickLayer's ergonomic API and feasibility validator, all agents reach 100% validity on 512 prompts. The API also halves inference cost compared to working in raw LDraw. While the domain is narrow (LEGO), the principle generalizes: provide agents with constraint-checking tools and domain-specific APIs, and validity goes from probabilistic to deterministic.

## D2 — AI in the Product

**Simon Willison demonstrates Claude Opus 5.5 generating a complete simulated oil-painting tool from a one-line prompt.** The [Quick Study tool](https://simonwillison.net/2026/Oct/23/quick-study-painter/) uses Sobel edge detection on a canvas element with no external libraries beyond Google Fonts, producing painterly renditions of photos in seconds. While this is a lightweight creative demo, it illustrates the continued compression of the prompt-to-working-product cycle for generative interfaces — a single sentence yielding a complete, deployable interactive artifact. The product implication: the gap between "describe what you want" and "ship it" continues to narrow for front-end experiences.

**OpenAI details scaling Habitat storage to serve 1B+ ChatGPT users with 12× faster reads.** The [Part II deep-dive](https://openai.com/index/scaling-storage-one-billion-users-part-two) covers multi-tenancy, global caching, and Azure Cosmos DB optimizations. While primarily an infrastructure story, it's relevant to D2 teams building AI-powered products: understanding the storage architecture behind the world's largest conversational AI product reveals patterns (tenant isolation, cache hierarchies, read-path optimization) that apply to any product embedding agent capabilities at scale.

## D3 — Build for Agents

**Google's Data Agent Kit reaches GA with 37 MCP-connected skills and a dual-guardrail architecture.** The [kit](https://www.infoq.com/news/2026/10/data-agent-kit-ga/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) connects coding agents to 15+ Google Data Cloud services (BigQuery, Spanner, Cloud SQL, etc.) via MCP tools. The critical design decision is the two-tier guardrail model: "skill guardrails" that ask the agent to stop (soft, advisory) and IAM deny policies that refuse the call at the infrastructure level (hard, enforced). This distinction matters architecturally — teams building B2A interfaces need both conversational boundaries that guide agent behavior and infrastructure-level policies that enforce invariants regardless of agent compliance. The GA release with 37 open-source skills also sets a meaningful floor for what "agent-ready data platform" means.

**EpiSEM-Bench systematically evaluates agent safety under missing evidence, revealing that robustness and recovery are distinct capabilities.** The [benchmark](https://arxiv.org/abs/2610.31650v1) contains 300 matched unsafe/safe task pairs across six domains, suppressing critical facts to test whether agents carry out prohibited actions when evidence is incomplete. Key finding: resistance to missing evidence does not predict useful recovery behavior — some agents correctly refuse to act but never seek the missing information. For anyone building systems that agents consume (D3), this means your API design must make safety-critical facts discoverable, not just available, because agents vary dramatically in whether they'll proactively seek what they need.

## D4 — Cost of Ownership

**Agentic tech-debt cleanup directly improves the 2×/½× equation by converting stale feature flags from accumulating operational risk into a \$4.79 automated maintenance task.** DoorDash's [multi-agent system](https://arxiv.org/abs/2610.31351v1) targets exactly the kind of downstream cost that compounds invisibly: dormant code paths behind stale flags that can cause incidents when inadvertently toggled, and the cognitive load on engineers who must reason about dead branches. At 1–2 hours per manual cleanup and 1,659 stale flags, the backlog represents ~2,500 engineer-hours of deferred maintenance. The agent system's 90% success rate at \$4.79/cleanup prices the entire backlog at roughly \$7,900 — a cost reduction of approximately 300×. The remaining 10% failure rate needs human escalation, making this a clean "human on the loop" pattern where agents handle the routine and humans handle the edge cases.

**Multi-cloud FinOps through architecture-level cost governance saves more than rate negotiation.** The [InfoQ article](https://www.infoq.com/articles/multi-cloud-finops-cost-optimization/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=Architecture) on Backend FinOps applies FOCUS-based cost visibility, workload placement, and CI/CD-integrated cost governance to cross-cloud architectures. While not agent-specific, the principle is directly relevant to the cost of the agentic factory: as inference workloads span cloud providers, egress costs driven by service placement and communication patterns can silently erode token-cost savings. Architecture-level cost governance integrated into the deployment pipeline is a prerequisite for sustainable agentic infrastructure.

**Selective auditing algorithms mathematically optimize the human review budget for AI decision streams.** The [paper](https://arxiv.org/abs/2610.31662v1) formulates human-on-the-loop review as an online constrained optimization problem: minimize audit frequency while guaranteeing that unaudited AI error rates stay below a threshold. The algorithms provide provable guarantees with no distributional assumptions, achieving optimal auditing rates for both adversarial and i.i.d. data. Practically, this means support tiers (helpdesk → 2nd/3rd line) that use AI for initial triage can mathematically bound their unreviewed error rate while minimizing the human review load — directly enabling the ½× downstream cost target without sacrificing reliability.

## Software Civil Engineering Lens

Today's batch offers unusually strong evidence for the SCE thesis across multiple fronts.

**Contestable governance is specification-driven development for metadata.** The [Akhtar & Freeman paper](https://arxiv.org/abs/2610.31553v1) instantiates nearly the full Specify → Plan → Verify → Apply → Observe lifecycle: specialist agents produce scored, cited arguments (Plan), a steward reviews with accept/reject/modify authority (Verify), a governance record captures evidence and interventions (Observe), and a precedent gate controls which verified decisions become reusable (codifying norms). The versioned domain glossary functions as a material datasheet — model-specific term definitions that constrain agent behavior. The triage path that reserves full argumentation for uncertain proposals is precisely the "bounded autonomy" concept: agents operate freely within high-confidence bounds and escalate to human judgment when confidence drops. This is the clearest real-world implementation of SCE principles we've seen applied to industrial data governance.

**BrickWright demonstrates simulation-before-apply in a physical domain.** By providing a [validator that checks physical feasibility](https://arxiv.org/abs/2610.31651v1) before committing builds, the framework achieves the "terraform plan for domain logic" analogy — agents propose, validators simulate/verify, and only valid builds proceed. The jump from 9–69% baseline validity to 100% with tool-mediated constraints is a quantitative argument for why the profession needs codes and validators, not just better models.

**Selective auditing formalizes the human-on-the-loop transition.** The [Gibbs et al. work](https://arxiv.org/abs/2610.31662v1) provides the mathematical foundation for the 10% → 10× transition: as agent reliability improves, the optimal audit rate drops, but the error bound guarantee is maintained. This is licensure logic — you don't inspect every bridge, but you have provable bounds on undetected failures. The assumption-free guarantees are particularly notable; they work regardless of whether the data stream is adversarial, removing a common objection to reduced human oversight.

**DoorDash's flag cleanup system is agents operating within well-bounded specifications.** The [system](https://arxiv.org/abs/2610.31351v1) succeeds precisely because the task is formally specifiable (a stale flag has a deterministic definition based on rollout data), verifiable (the resulting PR must pass CI), and reversible (PRs go through standard review). This is bounded autonomy in practice — the agent's action space is constrained to code removals that must pass automated verification, with human approval as the final gate.

The through-line: today's strongest results all share a pattern where agents operate within formally specified constraints, with verification/validation tools that enforce invariants, and human review reserved for the boundary cases. The professionalization isn't about making agents smarter — it's about making the *system around agents* more rigorous. That's civil engineering.
