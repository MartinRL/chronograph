## D1 — Agentic Engineering

**DeskCheck: Systematic code reasoning as an agentic scaffold.** This paper studies 7,955 issue-resolution trajectories and finds that while 67% contain some form of code reasoning, it's "largely unguided" — agents chase surface symptoms, fail to refine near-correct patches, and generate tests with limited behavioral diversity. [DeskCheck](https://arxiv.org/abs/2610.23782) addresses this by structuring four reasoning phases: execution-path simulation for root-cause localization, candidate-patch simulation for near-miss refinement, audit against issue requirements, and corner-case reasoning before test generation. On 731 SWE-bench-Pro instances, it improves resolution by 6.29–10.53% over mini-SWE-Agent and Claude Code at an average marginal cost of \$0.14/instance. The McNemar tests show statistical significance (p < 10⁻¹⁰). This is a direct instantiation of the Specify→Verify→Apply pattern: simulation before commit. (Cross-cutting: D4 — the \$0.14 spend is explicitly justified against downstream patch quality.)

**Agentic Cloud Engineering with zero-trust harness.** [Sakhinana & Runkana](https://arxiv.org/abs/2609.00050) present a framework decomposing autonomous cloud operations into three concerns: *graph engineering* (DAG-based workflow progression with verification-dependent transitions), *loop engineering* (bounded diagnosis→repair→retry→re-verify cycles with explicit termination criteria), and *agent harness engineering* (zero-trust identity, policy-scoped capabilities, isolation). Executions terminate with either a verified deployment or an auditable terminal failure. This is the most complete "terraform plan for agentic DevOps" architecture I've seen — every state transition requires machine-checkable evidence. (Cross-cutting: D4 — bounded recovery prevents runaway agent loops; D3 — the harness pattern is reusable for any agent-to-infrastructure interface.)

**Agentic proof-harness engineering for formal verification.** [Shanmuganathan et al.](https://arxiv.org/abs/2610.23241) propose agents that automatically construct proof harnesses — isolated verification environments with symbolic inputs, initialization code, and dependency models — for real-world C projects. Tested on curl and libuv, the agent successfully builds harnesses enabling CBMC to detect three historical assertion violations. Formal soundness and precision guards validate the agent's abstractions. This is agents building the verification infrastructure that other agents (or humans) then use — meta-verification tooling. (Cross-cutting: SCE — this is the "simulation" pillar made agentic.)

**ForTress: Deterministic rule reuse for LLM-driven code translation.** [ForTress](https://arxiv.org/abs/2610.22528) solidifies recurring LLM translation decisions (Fortran→Python) into guarded executable rules with Lean-verified semantic preservation proofs. Across 15 scientific software projects, it achieves bitwise-identical output, accumulates 193 reusable rules (90%+ cross-project reuse), and *reduces* LLM usage cost by 44.2% compared to direct translation. The key insight: capturing LLM decisions as verified, deterministic rules converts probabilistic translation into an engineering process. (Cross-cutting: SCE — this is "material datasheets" for code transformations.)

## D2 — AI in the Product

**Cognitive systems engineering lens on Anthropic's approach to work.** [Lorin Hochstein's analysis](https://surfingcomplexity.blog/2026/10/18/anthropic-and-the-changing-nature-of-work/) applies the cognitive systems engineering (CSE) tradition — born from 1980s safety-critical automation — to Anthropic's evolving agent paradigm. The core CSE insight is that automation changes the nature of human work rather than simply replacing it. For teams building AI into products: the question isn't whether agents can do the task, but how the human's supervisory role changes and whether your UX accounts for that shift. (Cross-cutting: D4 — misunderstood human-agent task boundaries are a leading cause of incidents in automated systems.)

## D3 — Build for Agents

**Provable Authority Protocol for agentic commerce.** The [ChainIT Authority Protocol](https://arxiv.org/abs/2610.22899) tackles a specific gap: a software agent can produce a valid cryptographic signature while acting outside its delegated authority — after budget exhaustion, after scope change, or on modified transaction details. The protocol introduces versioned organizational authority records, deterministic policy predicates, atomic capacity reservation under concurrency, and single-use sender-constrained Execution Authorization Credentials. The Agent Subject Profile adds workload registration, attested key hierarchies, and sovereignty boundaries without creating a separate authority concept. This is the infrastructure layer that MCP and A2A don't address: *who authorized this agent to spend this money right now?* (Cross-cutting: D4 — unauthorized agent transactions are an existential downstream risk.)

**Cryptographically secure agent-to-agent communication.** [Budzyn et al.](https://arxiv.org/abs/2610.23078) present a zero-trust A2A architecture using decentralized identifiers, task-scoped verifiable credentials on a permissioned ledger, hybrid post-quantum TLS, signed CBOR envelopes for multi-hop integrity, and zero-knowledge proofs for constraint verification without input exposure. This is the security stack that production multi-agent systems need but almost nobody has built yet. The post-quantum key establishment evaluation (KEMTLS with pre-distributed keys) is forward-looking for 6G-era agent mesh networks.

**Thought Blocks: Compiled latent communication.** [Thought Blocks](https://arxiv.org/abs/2610.23056) replace text-based multi-agent messaging with fixed-size KV continuation memory blocks constructed in one shot. Results: 45.7% fewer text tokens, 84.8% fewer autoregressive steps, 8.6× average latency speedup over text communication, 2.5× over autoregressive latent communication. The "trajectory-to-state compilation" formulation is elegant: instead of replaying the reasoning chain that produces a message, precompute the end state directly. For multi-agent architectures, this dramatically reduces the inference cost of coordination. (Cross-cutting: D4 — direct token cost reduction for agent swarms.)

## D4 — Cost of Ownership

**Epistemological debt threatens the 2× output / ½× downstream cost equation at its root.** [Ginac's framework (v4)](https://arxiv.org/abs/2604.26855) names the hidden liability: the share of a system's behavior that no maintainer can currently explain. Debt accrues through two concurrent mechanisms — maintainers who ship AI-generated changes without forming a mental model, and maintainers with models who stop deriving changes, causing their models to drift. Crucially, these two mechanisms "close the transfer window" that deskilling literature assumed would remain open. Amazon's 2025–2026 service incidents are cited as illustrative evidence. The implication for the 2×/½× equation: if you're shipping 2× faster but accumulating epistemological debt, your incident MTTR and support escalation costs will eventually explode because nobody understands the system well enough to debug it. This isn't tech debt — it's *knowledge* debt, and you can't refactor your way out of it.

**Runtime Assurance Contracts formalize when agent autonomy should shrink.** [RAC](https://arxiv.org/abs/2609.39717) shows that score-based trust (the way most agentic systems gate autonomy) is structurally broken: at published weights/thresholds, a score rule admits 56 of 63 cases that should be blocked. The alternative — non-compensatory mandatory gates where a single failed gate forces retry, escalation, or stop regardless of aggregate score — caught all injection cases. On 124 blind-authored cases, both the conjunction rule *and* the tuned score rule missed 35 of 79 injections, proving that missing detectors are invisible to *every* decision rule. The operational implication: your agent observability stack needs mandatory hard gates, not just dashboards with thresholds. (Cross-cutting: SCE — this is "codes and norms" for agent runtime behavior.)

**Annotrace standardizes agent failure analysis.** [Annotrace](https://arxiv.org/abs/2610.23284) observes that every study of agent failures builds its own throwaway trace-labeling tool. It reads six trace formats (OpenTelemetry GenAI, LangSmith, Langfuse), structures runs into nested step lists, and enables joint human-AI annotation with measured inter-annotator agreement (κ = 0.82). For agentic SRE, this converts agent failure analysis from ad-hoc investigation into a repeatable process — directly reducing the cost of understanding why agents fail.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis. Multiple independent research groups are converging on the same structural insight: **agentic systems need formal contracts, not just benchmarks.**

**Specification as intermediate artifact.** The [elicitation agent study](https://arxiv.org/abs/2610.22382) shows that interactive clarification improves Lean specification generation by up to +6.3 points — but *only* in cross-model configurations and *not* uniformly. The recommendation to "treat elicited natural-language specifications as intermediate artifacts" is precisely the SCE claim: specifications are engineering documents that sit between intent and implementation, and optimizing the spec-to-formal pipeline is as important as optimizing code generation. Postconditions being the largest failure mode reinforces that edge-case reasoning — the hardest part of specification — remains the bottleneck.

**Three papers independently build "codes and norms" for agents.** The [Provable Authority Protocol](https://arxiv.org/abs/2610.22899), [Runtime Assurance Contracts](https://arxiv.org/abs/2609.39717), and the [Agentic Cloud Engineering harness](https://arxiv.org/abs/2609.00050) each independently formalize what an agent is *allowed* to do and how evidence must be checked before action. This is the "building codes" pillar of SCE materializing in three different domains (payments, coding agents, cloud ops) simultaneously. The convergence is the signal: the field is groping toward mandatory, externally verifiable constraints on autonomous action.

**ForTress demonstrates "material datasheets."** By capturing LLM translation decisions as [verified, reusable rules with Lean proofs](https://arxiv.org/abs/2610.22528), ForTress creates what are effectively datasheets for code transformations — each rule has known semantic properties, explicit assumptions, and formal guarantees. 90%+ cross-project reuse means these datasheets compose. This is the SCE vision applied to legacy modernization.

**Epistemological debt is the anti-thesis risk.** [Ginac's framework](https://arxiv.org/abs/2604.26855) is the most serious challenge to uncritical adoption of agentic engineering. If the SCE thesis says "professionalize through formal methods," epistemological debt says "your workforce may lose the capacity to operate formal methods if they stop reasoning about systems." The resolution: SCE's *Specify→Verify* lifecycle must be mandatory, not optional, because it's the mechanism that forces maintainers to form theories. Without it, agentic speed creates unmaintainable systems.

**Net assessment:** Today moved the needle significantly on three of six SCE pillars — formal specification (elicitation agents), codes/norms (authority protocols, RACs, zero-trust harnesses), and simulation (proof harness engineering, DeskCheck execution-path simulation). The gap remains widest on licensure and education.
