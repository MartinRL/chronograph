## D1 — Agentic Engineering

**Trace-to-Architecture (T2A) closes the "which knob to turn" gap in agent harness improvement.** When an LLM agent fails, the root cause can be in the prompt, the tool set, the orchestration logic, or the retrieval pipeline — and the same symptom can map to different fixes. T2A uses [execution trajectories to diagnose capability bottlenecks](https://arxiv.org/abs/2610.16725) and revise the harness component responsible, then validates that fixed tasks stay fixed and regressions don't appear. Across ALFWorld, ScienceWorld, and AppWorld it beats the strongest baselines by 6.2–30.3 points. This is operationally important: it turns agent debugging from an art into a structured observe→diagnose→revise→verify loop. *(Cross-cuts D4: every harness revision that sticks is maintenance cost avoided.)*

**SpecForge demonstrates that behavioral specifications can recursively self-improve coding agents without weight updates.** The [framework](https://arxiv.org/abs/2610.15708) formalizes a loop: generate code from specs → run execution-verified tests → refine specs from failures → repeat. The key insight is "output coupling" — improving one entity's spec can break another — addressed via Pareto-guided tree search and dependency-constrained entity selection. A 94.9% solve rate on DevEval+ with Claude-4.5-Sonnet is the headline, but the transfer result matters more: specs refined in the loop outperform benchmark-provided requirement docs on cross-language translation and new-feature tasks. *(Cross-cuts SCE: this is the specify→verify→refine lifecycle made concrete.)*

**Reels-RSI introduces unit-tested agent memory for program-level self-improvement.** Rather than tuning weights or prompts, the [system](https://arxiv.org/abs/2610.14495) learns rules from retrospectives on its own revision diffs. Each rule comes with a must-fail and must-pass example — the memory is literally unit-tested. Rules learned in the field caught four latent defects in older artifacts and served as guardrails for weaker directors. The honest reporting of failure modes (position bias in pairwise judging, lessons that don't compound) adds credibility. *(Cross-cuts D4: the playbook-rewrite is gated by benchmark and human approval, preventing unbounded self-modification.)*

**Pollard provides a framework-independent runtime for governed agent execution and deterministic replay.** The [system](https://arxiv.org/abs/2610.16145) (accepted at IEEE ICTAI 2026) assigns a committed identity to every execution step — input, kind, attempt, parent — and records completion, refusal, resource settlement, and branch history in a semantic execution tree. Strict replay returns verified stored results without re-invoking operations; a transactional store enforces resource leases across concurrent workers. This is infrastructure for auditable agent systems: every tree is verifiable, every mutation is detected. *(Cross-cuts D4: deterministic replay eliminates re-execution cost during incident investigation.)*

**Enterprise reference architecture for agentic AI integration organizes ten responsibilities with boundary invariants.** The [technology-neutral architecture](https://arxiv.org/abs/2610.14818) synthesizes research, industry guidance, and interop specs (MCP, A2A) into a responsibility model covering orchestration, knowledge/memory, model access, tools/actions, security, runtime infrastructure, and evaluation. It defines variation points distinguishing required capabilities from condition-dependent ones. The ESG portfolio-analysis case study realizes seven of ten responsibilities; an independently published architecture maps cleanly without requiring a new one. *(Cross-cuts D3: the architecture explicitly accounts for agent-to-agent interop and tool gateway patterns.)*

## D2 — AI in the Product

**The LLM→SLM lifecycle is a blueprint for shipping agent subtasks at production cost.** [Wang (2026)](https://arxiv.org/abs/2610.14576) demonstrates a home-care scheduling agent where a yes/no safety decision per caregiver-shift pair is developed on GPT-5.4-nano in prompt space with live traffic feedback, then distilled into a LoRA-tuned Qwen3-8B via SFT on 11.6k recorded production decisions. The student achieves 0.913 agreement with the teacher while the teacher agrees with *itself* only 72.7% on re-run — the SLM is more consistent. When they disagreed, a blinded scheduler sided with the student 48–29. Median latency drops 2.5× at fractional cost. This is the "2× output at ½× cost" equation made literal for narrow inference tasks.

**Interpretive lock-in is a product-quality risk for any pipeline using LLM-generated tests as a quality gate.** The [study](https://arxiv.org/abs/2610.15797) on DataFrame code generation shows test-pass rates rising from 22/30 to 30/30 via revision, yet 0/30 solutions matching reference output. The failure modes are damning: tests that omit requirements, adopt the candidate's own schema, use non-discriminating fixtures, or simply re-implement the candidate's incorrect logic. For any product embedding agentic code generation, this means self-generated tests create a false sense of correctness that can propagate silently into production.

## D3 — Build for Agents

**Parameter schema design dominates MCP tool selection — more than names or descriptions.** Analysis of [367,174 MCP tools](https://arxiv.org/abs/2610.14334) reveals that functionally identical tools with different parameter schemas are selected at dramatically different rates. Models consistently favor separate top-level parameters over grouped/composite forms. Descriptions that explain parameters increase selection; name effects are weak. When only one schema satisfies an explicit request requirement, all five tested models choose correctly regardless of position. For MCP server developers, this means schema design is not an implementation detail — it's a discoverability and selection mechanism that directly determines whether your tool gets invoked.

**MCPDisCo trains MCP-native agents across 70 servers and 527 tools with RL, addressing the reasoning–tool seesaw.** The [framework](https://arxiv.org/abs/2610.14956) uses a Thought-MDP that explicitly represents internal reasoning alongside routing and execution. The "seesaw" — improving reasoning degrades tool use and vice versa — is mitigated via token-masked reward attribution and bidirectional gradient surgery. The result is higher success with fewer CoT tokens, and the behavior generalizes to out-of-distribution MCP servers and the GAIA benchmark. This is the first serious RL-at-scale result for the MCP ecosystem.

**Agent-Canary-Mas exposes the gap between local protocol exploitability and downstream consequence in A2A systems.** The [evaluation system](https://arxiv.org/abs/2610.15529) covers five risk classes across A2A, ANP, and BCS protocols with 975 matched attack/benign pairs. Local attack success is ≥90%, but consequence conversion ranges from 7.1% to 100% depending on how downstream agents handle exchanged objects. A protocol-context Guard checking authority at consequential handoffs lowers Finance ASR from 86.1% to 53.8%. The takeaway: measuring protocol security at the handshake is misleading; you must trace risk through the full task.

**Revocation in distributed agent-tool gateways is not complete at receipt.** The [C0-C5 outcome contract](https://arxiv.org/abs/2610.15991) demonstrates that transport acknowledgment and receiver persistence can both succeed while 49.78% of calls still execute post-revocation effects. Tested across Keycloak 26.7, eight physical gateways, and 16 AWS hosts in three AZs, the result is unambiguous: treating C3 or C4 as completion produces 5–7 false positives; the full C0-C5 contract produces none. This directly impacts any system where agents hold delegated authority cached at tool gateways.

## D4 — Cost of Ownership

**The LLM→SLM distillation lifecycle directly addresses the 2× output / ½× downstream cost equation.** [Wang's scheduling agent](https://arxiv.org/abs/2610.14576) shows that recording production decisions from a frontier model and distilling them into a LoRA-tuned 8B model yields 2.5× lower median latency, fractional inference cost, and *higher consistency* than the teacher. The student's superior consistency (0.913 self-agreement vs. the teacher's 72.7%) reduces downstream support cost: inconsistent decisions generate escalations to human schedulers. This is a repeatable pattern for any agent system with high-volume, narrow decision points — develop behavior on the expensive model, serve on the cheap one.

**Token Window Pacing (TWP) cuts P99 tail latency and boosts throughput 45–58% for serverless LLM inference.** The [closed-loop scheduler](https://arxiv.org/abs/2610.17689) uses runtime feedback from inter-token latency, queue depth, and workload characteristics to regulate request admission at the token level rather than the batch level. For agentic workloads where multiple agents fan out concurrent inference requests, this reduces latency spikes that cascade into timeout-induced retries — a direct infrastructure cost multiplier. The 45% throughput improvement over ServerlessLLM means fewer GPU-hours per unit of agent work.

**Counterfactual regret bounds for reflective agents, verified in Lean, establish formal resource-budget tradeoffs.** [Li et al. (2026)](https://arxiv.org/abs/2610.14790) derive sufficient conditions for sublinear regret from local generation and deployment guarantees, formalized as thirteen Lean-verified theorems. The practical relevance for cost of ownership is the explicit quality/coverage/hard-budget tradeoff: it tells you when reflection is worth its inference cost and when it isn't. This is theory, but it's the kind of theory that eventually becomes a design constraint — the same way structural load calculations constrain building design.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis. Several items provide direct evidence for — and one important caution against — the professionalization trajectory.

**SpecForge is the strongest evidence yet for spec-driven development as an engineering discipline.** The recursive loop of specify → generate → test → refine mirrors the SCE lifecycle almost exactly, and the identification of "output coupling" (improving one spec degrades another) is a structural engineering concept in disguise — it's the agentic equivalent of load redistribution when you reinforce one beam. The Pareto-guided search that preserves complementary states is how you avoid local optimization at the cost of global integrity. The transfer result — specs beating benchmark requirement docs on out-of-loop tasks — validates the core SCE claim that specifications are reusable assets, not throwaway prompts.

**Interpretive lock-in is the anti-thesis warning.** The [DataFrame study](https://arxiv.org/abs/2610.15797) shows that even with planning and revision, agents can systematically validate their own incorrect interpretation. In civil engineering terms, this is like a structural simulation that confirms a flawed blueprint because the simulation inherited the blueprint's wrong assumptions. This is exactly the failure mode that external specification languages (Event Modeling, reference outputs, formal properties) are meant to prevent. The fact that 30/30 tests pass while 0/30 solutions are correct is a stark reminder: **self-verification without external ground truth is not verification.**

**Lean-verified regret bounds** ([Li et al.](https://arxiv.org/abs/2610.14790)) and **Pollard's governed execution trees** ([Syed & Silaghi](https://arxiv.org/abs/2610.16145)) both advance the "simulation and audit" pillar. Lean verification is the agent-world equivalent of finite-element analysis certification; Pollard's deterministic replay with immutable semantic trees is the equivalent of as-built documentation. Neither is widely adopted yet, but both are evidence that the infrastructure for formal guarantees in agentic systems is being built.

**Reels-RSI's unit-tested memory** is a small but significant contribution to the "codes and norms" pillar: rules compiled from retrospectives with must-fail/must-pass examples are essentially building codes derived from field failures, which is exactly how structural engineering codes evolved historically.

The overall signal: the SCE thesis is accelerating from theory to tooling. The gap that remains widest is **licensure and education** — none of today's items address who is qualified to operate these systems or how competency is assessed.
