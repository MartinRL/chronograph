## D1 — Agentic Engineering

**AutoCompact teaches coding agents *when* to forget.** [AutoCompact](https://arxiv.org/abs/2610.02163v1) introduces a trained compaction policy for long-horizon coding agents that decides when to compress context, what working state to preserve, and how to continue from a summary. The key insight is that context management is not just about avoiding overflow — it's a first-class policy decision. Using supervised fine-tuning on judge-corrected trajectories followed by RL with task-success rewards, AutoCompact improves SWE-bench Verified pass rates by 9.2% absolute. Critically, gains hold even at a 16K context window with fallback compaction, meaning you can run agents on cheaper, smaller-context models without losing capability. This is a rare paper that simultaneously advances D1 (better agent engineering) and D4 (lower inference cost).

**Uber Eats uses agentic coding workflows alongside traditional pipeline optimization.** [Uber's search pipeline rebuild](https://www.infoq.com/news/2026/10/uber-eats-search-latency/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) achieved a 50% latency reduction through a combination of Above-the-Fold measurement, parallel hydration, retrieval scope reduction, and infrastructure tuning — but notably also credits an "agentic coding workflow" as part of the engineering process. This is one of the clearest real-world signals that D1 practices (agentic coding) are being adopted inside major platform engineering teams, not just in greenfield AI startups. The latency win itself is pure D4 — faster search means fewer abandoned sessions and lower support load.

**Global coherence theorem formalizes why multi-agent teams fail.** [Heng's paper](https://arxiv.org/abs/2610.02036v1) introduces the Observation-Aliasing Impossibility Theorem: if *k* indistinguishable worlds require pairwise-disjoint actions, the best randomized worst-case success is 1/k — no amount of reasoning, roles, or message-passing can fix it. The fix is architectural: a harness that owns shared state and governs commit. On TeamBench, ordinary multi-agent teams exceeded budgets in 5/5 runs; commit enforcement reduced violations to 0/5. On tau2-bench Telecom, the harness scored 1.00 vs. 0.07 for current-state checks after silent reverts. The practical takeaway for anyone orchestrating multi-agent pipelines: **models propose; the harness disposes.** This directly validates the Decider pattern's "propose → verify → apply" lifecycle. (Cross-cutting: D1, D3, SCE.)

**OpenAI DevDay 2026 ships new primitives for agentic engineering.** [DevDay announcements](https://www.infoq.com/news/2026/10/openai-devday-2026/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) include GPT-6.1 Sol, computer use for the Agents API, cloud-based Codex environments, a Decisions API, and new ChatGPT plugin capabilities. The Decisions API is the most architecturally interesting: it signals OpenAI positioning itself as a runtime for agent decision-making, not just inference. Combined with computer-use in the Agents API, the platform is converging on a model where agents can observe screens, reason, and act — raising the stakes for bounded-autonomy guardrails. (Cross-cutting: D1, D2, D3.)

**Airbnb's inside-out AI transformation touches both internal engineering and guest-facing product.** [Ahmad Al-Dahle's interview](https://www.latent.space/p/airbnb) describes how Airbnb is deploying AI both to change how engineering teams build (D1) and to reshape the guest experience (D2). Coming from leading Meta's Llama team, Al-Dahle represents the emerging pattern of AI-native leadership bringing foundational model expertise into product-engineering organizations. The "inside-out" framing — transforming internal workflows first, then the product — mirrors the D1→D2 maturity arc we track.

## D3 — Build for Agents

**Docker Sandbox Kit Spec creates a portable permission model for AI agents.** [Docker is bringing the Sandbox Kit Specification to the CNCF](https://www.infoq.com/news/2026/10/docker-sandbox-ai-agent/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering), aiming to make agent permissions as portable as the agent itself. By packaging what an agent *may access* as OCI images, Docker is doing for agent capabilities what containerization did for application deployment: standardizing the runtime contract. This is the most significant D3 development in weeks — it directly addresses the "build for agents" surface by giving agent consumers a declarative, auditable way to specify tool access boundaries. (Cross-cutting: D3, D4, SCE — this is a "building code" in SCE terms.)

**DigitalOcean Managed Agents offers turnkey agent infrastructure.** [DigitalOcean's public preview](https://www.infoq.com/news/2026/10/digitalocean-managed-agents/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) provides isolated microVM runtimes, governed tool access, and serverless AI inference as a managed service for AI agents. This lowers the barrier for teams that want to deploy agents without building bespoke infrastructure. The "governed tool access" framing is key — it's an opinionated take on bounded autonomy at the infrastructure layer. For B2A scenarios where external agents consume your APIs, managed agent hosting commoditizes the runtime, shifting differentiation to the agent logic itself.

**AsyncAPI governance patterns inform agent-to-agent interoperability.** [Ian Cooper's presentation on managing async APIs at scale](https://www.infoq.com/presentations/managing-async-apis/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=Architecture) covers the "ABCs" of messaging (Address, Binding, Contract), schema registries, and automated provisioning via CI/CD — patterns drawn from Just Eat Takeaway's real-world engineering. While not explicitly about agents, the governance and discovery challenges he describes are precisely what A2A and MCP ecosystems will face at scale. AsyncAPI + CloudEvents may become the event contract layer that agent orchestrators rely on. (Cross-cutting: D3, SCE.)

## D4 — Cost of Ownership

**Uber Eats' 50% latency reduction directly improves the 2×/½× equation.** By [cutting end-to-end search latency in half](https://www.infoq.com/news/2026/10/uber-eats-search-latency/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering), Uber reduces abandoned searches, timeout-related support tickets, and infrastructure cost from redundant retries — all downstream costs. The specific optimizations (Above-the-Fold measurement, parallel hydration, reduced retrieval scope) are not AI-specific, but they demonstrate the principle that agentic speedups in development (D1) must be matched by measurable downstream cost reduction, or the velocity is borrowed against future maintenance debt.

**GCP's networking incident underscores irreducible infrastructure risk.** [Lorin Hochstein's analysis](https://surfingcomplexity.blog/2026/10/02/there-was-a-light-that-never-went-out/) of a recent GCP us-central1 networking incident highlights that networking systems are "inherently unsafe by their very nature." For teams running agentic workloads on cloud infrastructure, this is a reminder that agent-layer reliability gains can be wiped out by infrastructure-layer failures. The cost-of-ownership lens: incident response, blast-radius management, and multi-region resilience remain non-negotiable even as the agentic factory gets cheaper at the inference layer.

**AutoCompact cuts inference token cost while improving outcomes.** [AutoCompact's](https://arxiv.org/abs/2610.02163v1) ability to maintain +9.2% pass-rate improvement even when constrained to a 16K context window means teams can deploy coding agents on significantly cheaper inference budgets. The paper shows that intelligent compaction is not just a performance optimization — it's a direct cost lever for the agentic factory. If your coding agents currently run at 128K+ contexts, this technique could reduce token spend by 8× or more while actually improving task success.

## Software Civil Engineering Lens

Today is a landmark day for the SCE thesis, with three developments converging on the professionalization narrative:

**1. The Global Coherence theorem is the SCE thesis in mathematical form.** [Heng's impossibility result](https://arxiv.org/abs/2610.02036v1) proves what SCE has been arguing qualitatively: you cannot rely on agent intelligence alone to produce correct system behavior. You need a harness — a structural guarantee — that owns shared state and governs commit. This maps directly to the Decider pattern and the "Specify → Plan → Verify → Apply → Observe" lifecycle. The paper's sheaf-theoretic formalization (topology H, category C, groupoid G, sheaf F) is overkill for practitioners, but the core insight is not: **models propose; the harness owns commit**. This is the SCE equivalent of requiring a structural engineer to sign off on load calculations, not just trusting the builder's experience.

**2. Docker's Sandbox Kit Spec is the first real "building code" for agents.** By [packaging agent permissions as OCI images](https://www.infoq.com/news/2026/10/docker-sandbox-ai-agent/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) and submitting the spec to the CNCF, Docker is creating a normative standard for what agents may and may not do — a code/norm in SCE terms. This is exactly the kind of industry-standard constraint that separates craft from engineering discipline. If adopted widely, it closes one of the six pillars gaps: codes and norms for agent behavior.

**3. Huntley's "explainable over readable" thesis provokes the specification pillar.** [Huntley argues](https://ghuntley.com/readable/) that software no longer needs to be readable by humans — it needs to be explainable. This is both aligned with and in tension with SCE. Aligned: if agents write code, the specification (blueprint) becomes the primary artifact humans engage with, not the code itself. In tension: explainability is weaker than formal specification. A building's structural calculations are not merely "explainable" — they are verifiable against codes. The SCE position should be that explainability is necessary but not sufficient; what we actually need is **verifiability** — the ability to mechanically check that generated code satisfies its spec. Huntley is right that readability as a design goal is dying; the question is what replaces it. SCE says: formal specifications and simulation (the blueprint and the load test), not just natural-language explanations.

The AsyncAPI governance patterns from [Just Eat Takeaway](https://www.infoq.com/presentations/managing-async-apis/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=Architecture) also contribute: schema registries, contract-first design, and automated provisioning are mature examples of the kind of disciplined infrastructure that agent-to-agent communication will require. The event-driven architecture community has been doing SCE-adjacent work for years — the agentic era just raises the stakes.
