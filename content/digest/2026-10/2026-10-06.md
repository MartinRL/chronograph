## D1 — Agentic Engineering

**Training reliability into coding agents rather than scaffolding it.** [Teaching Agents to Code Reliably](https://arxiv.org/abs/2610.03984) identifies three failure modes in autonomous coding — narrow location diversity, unexploited edit diversity, and misleading self-written tests — and argues these are *teachable behaviors*, not emergent properties of scale. Using weighted SFT followed by RL that trains the verifier against gold-labeled repairs, they raise pass@1 from 31.9% to 43.0% and more than halve false acceptance, while using 48.1% of the agent-steps of the baseline. The key insight for D1 practice: investing in verification RL yields compounding returns — fewer wasted steps, fewer false positives, and the gains hold across model sizes (7B–30B). This also has strong D4 implications for token cost.

**Harness orchestration is mostly a cost lever, not a quality lever.** [What Does a Harness Buy? Tokens, Mostly](https://arxiv.org/abs/2610.04433) runs five models through three production harnesses (Claude Code, mini-SWE-agent, OpenCode) on SWE-bench Verified and finds that swapping the harness flips the same percentage of tasks (13%) as simply re-running the same harness. The only statistically significant harness effect is a *loss* (OpenCode trailing by 9 points due to output caps). However, cost per task differs by up to 3× across harnesses, driven almost entirely by the preamble of system prompt and tool schemas sent at every step. This is a direct challenge to the industry habit of attributing quality gains to harness engineering — and a strong signal that D1 teams should optimize harness design for cost, not pass rate.

**Second-order self-improvement beats first-order patching.** [SO-RSI](https://arxiv.org/abs/2610.05701) introduces a recursive self-improvement framework for formal verification (Lean 4, Verus) that monitors execution traces for structural anomalies — recurrence, opposing edits, expectation mismatch — before committing to workflow changes. By maintaining persistent inquiry memory across RSI rounds, it accumulates causal evidence rather than thrashing on surface symptoms. The result: +21.8 and +25.8 percentage point improvements over naive RSI under matched 24-hour budgets, with elimination of zero-progress loops. For D1 practitioners building agentic loops, this validates the pattern of investing in *diagnostic infrastructure* within the agent's own optimization cycle. (Also D4-relevant: same budget, dramatically better output.)

**Self-evolving inference engine optimization.** [SEIS](https://arxiv.org/abs/2610.04646) applies agentic self-evolution to optimize an entire LLM inference engine (mini-sglang) end-to-end without human intervention. Across iterative sessions with inherited experiences and code changes, it achieves 3.27× throughput improvement over the original implementation, beating vLLM, TensorRT-LLM, and SGLang on single-request workloads for Qwen3-0.6B on H100. The key architectural insight: building on earlier sessions beats independent attempts, validating the value of persistent context in agentic optimization. This is a concrete example of agents redesigning their own infrastructure — a meta-level D1 capability with direct D4 cost implications.

**Adaptive search budgeting for long-horizon agents.** [ForkPilot](https://arxiv.org/abs/2610.04889) learns a search-value policy that decides when retrospective search (backtracking) is worth its cost in long-horizon agent tasks. Evaluated across 6 benchmarks and 7 LLM families including GPT-5.6 Sol and Opus 4.8 in a production system used by hundreds of thousands of paid users, it achieves comparable SOTA performance while reducing token usage by up to 59.2%. The two-stage approach — offline learning from completed trajectories, then online self-evolution — is a practical pattern for any team running multi-attempt agentic workflows. (Cross-cutting D4: this is pure inference cost reduction at maintained quality.)

## D2 — AI in the Product

**Cost-aware stopping for video reasoning agents.** [CASE](https://arxiv.org/abs/2610.05400) addresses the "when has the agent seen enough?" problem for long-video reasoning, framing it as policy-conditioned sequential stopping. A lightweight Ridge regressor learns to compare the value of answering now versus continuing to gather evidence. On Video-MME, accuracy changes by +0.67 points while token use drops 53.6%, and the frozen policy transfers zero-shot to other benchmarks with +3–5 point accuracy *gains* and ~55% token savings. For product teams building video understanding features, this is a plug-in efficiency multiplier — the same pattern (formal stopping criteria for evidence accumulation) generalizes to any agent-in-product that iteratively gathers context.

No other significant D2 developments today.

## D3 — Build for Agents

**First controlled latency decomposition of agent interop protocols.** [The Cost of a Hop](https://arxiv.org/abs/2610.04053) provides the first empirical head-to-head of NLIP vs A2A, decomposing latency into message creation, connection, and send phases across three hardware environments. For lightweight coordination, NLIP is 8.4–9.6× faster than baseline A2A, but the advantage collapses to near-parity in end-to-end pipelines where LLM inference dominates. The gap comes almost entirely from connection setup; A2A with connection caching narrows it to 2.75× or less. The practical takeaway: for high-frequency agent-to-agent coordination (many short calls), protocol choice matters significantly; for inference-dominated workflows, it's irrelevant. The paper closes with a protocol-selection guide keyed to workload characteristics — useful for any team designing multi-agent architectures.

**Runtime authorization must operate at goal-graph level, not tool level.** [Runtime Authorization of Self-Generated Subgoals](https://arxiv.org/abs/2610.04975) formally proves that per-tool permission checks are insufficient for long-horizon agents that create subgoals, replan, and delegate. Their mechanism requires each goal-graph mutation to carry a version-bound witness that its traces, resources, and obligations refine the active root contract. Across 96 matched cases, the mechanism commits zero forbidden states in 48 drifted cases while completing all 48 benign counterparts. For D3 (building systems that agents consume), this has direct implications: agent-facing APIs must support contract-level authorization, not just action-level permissioning. This is also deeply SCE-relevant.

**LLMs cannot reliably determine their own verification boundaries.** [Not Self-Decidable](https://arxiv.org/abs/2610.04699) tests whether LLMs can correctly classify which regulatory predicates can be settled by a fixed check versus which require human judgment. Across ~22,000 labels from four models on six corpora (EU AI Act, FINRA, deployed credit agent), models agree on obvious cases but collapse on regulatory text, with errors running in opposite directions across models. Critically, on the deployed agent's own rules, models err *together* by over-claiming decidability — the failure mode that never gets escalated. Their CoVer framework treats model unanimity as a nomination that must survive intervention testing. For anyone building agent guardrails in regulated domains: the verification boundary itself must be externally constructed, not delegated to the model.

## D4 — Cost of Ownership

**Harness preamble is the dominant and most controllable cost driver in agentic coding.** This directly impacts the 2× output / ½× downstream cost equation: [What Does a Harness Buy?](https://arxiv.org/abs/2610.04433) shows that system prompt and tool schema preambles, sent with every agent step, create up to 3× cost differences between harnesses *at identical quality*. The cost is set at the first call and scaled by step count. Since the paper shows no quality benefit from heavier harnesses (within noise), this is pure waste — and the easiest lever to pull for teams running coding agents at scale. Cached input pricing from providers scales the bill but does not reorder it across harnesses.

**Adaptive search budgeting halves token spend without quality loss.** [ForkPilot](https://arxiv.org/abs/2610.04889) reduces token usage by up to 59.2% at comparable SOTA accuracy by learning when retrospective search is worth its cost. This is validated in a production system serving hundreds of thousands of paid users, making it one of the more directly applicable cost-reduction techniques for teams running multi-attempt agentic workflows. The self-evolving policy means the savings compound as the system processes more trajectories.

**Agent-optimized inference engines reduce serving cost at the infrastructure layer.** [SEIS](https://arxiv.org/abs/2610.04646) demonstrates 3.27× throughput improvement on LLM inference through agentic self-evolution of the serving engine itself. While demonstrated on a single-request workload with a small model (Qwen3-0.6B), the approach of using agents to holistically optimize inference infrastructure — rather than hand-tuning individual kernels — suggests a path toward automating the ongoing cost optimization of the agentic factory's most expensive component.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with multiple papers addressing professionalization themes from different angles.

**Verification boundaries are not self-assessable.** The [Not Self-Decidable](https://arxiv.org/abs/2610.04699) result is perhaps the day's most important SCE finding. It establishes that the boundary between what can be mechanically verified and what requires human judgment *cannot be delegated to the system under test*. This is a foundational constraint for any "human on the loop" architecture: the loop itself — which checks are automated, which escalate — must be externally specified. In civil engineering terms, you don't ask the building whether it needs an inspection; the code determines when inspections occur. The CoVer framework (corroborate-then-verify with intervention testing) is a practical step toward the "codes and norms" pillar.

**Runtime authorization as structural engineering for agent autonomy.** [Runtime Authorization of Self-Generated Subgoals](https://arxiv.org/abs/2610.04975) is doing exactly what SCE predicts must happen: formalizing the constraints within which agents can autonomously operate. The "root contract" metaphor — every goal-graph mutation must prove it refines the approved specification — is structurally identical to the Decider pattern's approach of validating state transitions against declared invariants. The proof of trace-policy preservation under explicit assumptions mirrors how structural engineers prove load paths.

**Process Constitutions as machine-interpretable blueprints.** [Process Constitutions and Process Stewards](https://arxiv.org/abs/2610.05942) explicitly argues that BPM must shift from modeling human work to governing autonomous agents, proposing "Process Constitutions" as machine-interpretable, value-laden frameworks defining admissible agent behavior. This maps directly onto the SCE thesis: the Process Constitution *is* the blueprint; the Process Steward *is* the inspector. Their core claim — that the value proposition shifts from efficiency to *organizational legibility* — aligns with the SCE argument that the spec is the product, not the code.

**Penumbra as boundary-condition testing for regulatory specs.** [Penumbra](https://arxiv.org/abs/2610.04693) finds pairs of agent responses that straddle compliance boundaries, differing by a handful of words. This is adversarial specification testing — finding where the spec's own terms "stop deciding." In civil engineering, this is analogous to finding the exact load at which a design transitions from safe to unsafe. The fact that this can be done sample-efficiently (adaptive allocation reaches full-budget coverage on 59% of candidates at matched budget) makes it practical for pre-deployment certification.

**Label agreement ≠ authorization: metrics must decompose.** [Label Agreement Does Not Measure Authorization](https://arxiv.org/abs/2610.04544) demonstrates that aggregate accuracy metrics hide three independent failure modes (entitlement, completeness, evidence-sensitivity) in agentic pipelines. The row-order error that erased diagnostic signal while passing all standard metrics is a cautionary tale: the "material datasheet" for an agentic component must specify not just accuracy but the conditions under which that accuracy was measured, including what failure modes the metric is blind to.

Taken together, today's papers paint a picture of a field that is being forced toward formalization — not by choice but by the failure modes of informal approaches. The verification, authorization, and compliance papers all converge on the same insight: agents operating under external constraints need externally constructed boundaries, externally specified verification criteria, and externally defined escalation policies. The craft approach of "try it and see if it works" is hitting walls that only engineering discipline can resolve.
