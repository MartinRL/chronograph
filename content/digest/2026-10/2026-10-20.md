## D1 — Agentic Engineering

**World of SWECraft introduces the first realistic simulation framework for multi-agent software collaboration at scale.** The [Software World framework](https://arxiv.org/abs/2610.24061) creates environments of real, interdependent Python packages and lets agents discover tasks, collaborate, and maintain code autonomously. Across 10,000+ hours of agent work on eight models, performance improvement scales with inference-time compute, with the best model improving downstream package efficiency by 31%. Critically, some frontier models "prematurely stop looking for improvements" — a failure mode invisible in single-task benchmarks. For CTOs building agentic engineering practices, this is the first framework that lets you study collaboration dynamics (communication patterns, ownership models, resource allocation) before deploying multi-agent systems in production. *(Cross-cuts D4: the resource allocation findings directly inform agentic factory cost modeling.)*

**Cortex formalizes governed coding agents as fixed-point computation on a requirement lattice.** The [Cortex technical report](https://arxiv.org/abs/2610.24255) provides a mathematical foundation for supervisory layers that track requirement closure, perform iterative validation, and bound completion time. The key insight: for a fixed requirement set with a sound, monotone validation rule, exhaustive iteration reaches the least fixed point with no more strict increases than there are requirements. The authors are transparent about the gap between theory and practice — "artifact repair, fallible validation, and finite execution budgets do not satisfy [the assumptions] automatically" — which makes the formalization more useful, not less. This is the closest thing to a structural engineering load calculation for coding agents published to date.

**Agentic Interpretation (AgInt) introduces harness-governed evidence construction with append-only certificate states.** The [AgInt framework](https://arxiv.org/abs/2610.23996) separates what the LLM proposes (typed records) from what the deterministic harness admits, grades, and persists. The formal structure — a grounding lattice ordered by record inclusion — ensures that evidence can only grow, never be silently revised. On practical benchmarks, this architecture lifts reject-class F1 from 0.256 to 0.543 on SWE-bench-Live and reduces wasted inspected lines from 31.5 to 11.7 on GitBug-Java. The 35% reduction in executions and 59% cost reduction per candidate are direct D4 wins. *(Cross-cuts D4, SCE.)*

**Verified, cost-aware model assignment proves that no fixed LLM allocation is cheapest across all tasks.** The [analog layout repair paper](https://arxiv.org/abs/2610.24234) shows across 182 blind runs that cheap models execute plans well but rarely succeed alone (1/11 alone vs 16/17 under a flagship planner; p < 0.001). Their Bayesian learning controller selects models per role and updates after every attempt, matching flagship-only quality at 15–40% of the spend on most tasks. The principle generalizes beyond hardware design: any agentic pipeline with plan/execute separation should dynamically assign model tiers by task difficulty rather than using a fixed allocation.

**Symbolic Constraint Agents mine formal tool-call constraints from API docs and enforce them at runtime with an SMT solver.** The [SCA framework](https://arxiv.org/abs/2610.25552) automatically extracts constraints, refines them against execution traces, and checks each agent tool call before execution. When the valid replacement is uniquely determined, it auto-repairs. This removed 59–87% of failed calls across models and raised task success by up to 9.8 points when environment errors are hidden. The approach is directly applicable to any agent using tool APIs — it's essentially a learned type system for tool calls. *(Cross-cuts D3, SCE.)*

## D2 — AI in the Product

**Narrow Decision Models offer a small, deployable alternative to general-purpose LLMs for typed organizational decisions.** The [NDM architecture](https://arxiv.org/abs/2610.25553) answers typed questions (Choice, Score, Yes/No) with calibrated probabilities using a bidirectional encoder with block attention masks that guarantee order-invariance by construction. Trained on real legal document routing, a small instance agrees with the production LLM classifier on 91% of held-out documents while running on the organization's own infrastructure. For product teams: this is the pattern for converting high-volume, repetitive LLM calls into deterministic, auditable, cheap inference — the "compile your prompt into a model" approach made rigorous.

**AllPath demonstrates a three-layer verification architecture for deployed self-revising agents.** The [AllPath system](https://arxiv.org/abs/2610.26662) splits verification into code gates (deterministic risk limits), agent self-review (bounded iteration, no action tools), and human judgment (approval screens). In live deployment, the code gates rejected zero proposals — their value was consistency enforcement. The human rejected two proposals that passed all automated checks (market disagreements) and removed 11 of 19 agent-added rules with a median lag of 8 days. The most instructive finding: the hardest production incidents passed every gate and were only found by manual inspection, with each fix being an interface change. This is the most honest account of human-on-the-loop failure modes in production published to date. *(Cross-cuts D1, D4.)*

## D3 — Build for Agents

**The Architectural Decision Framework (ADF) provides the first rigorous guidance for when NOT to use agents.** The ["Doing Less with More" paper](https://arxiv.org/abs/2610.23921) benchmarks seven architectures — native Python, REST, SOAP, MCP, direct LLM, and agentic MCP — on 1,000 arithmetic tasks. Deterministic methods achieve 100% accuracy at negligible latency. The best agent reaches 99.9% but at ~1,000,000× the baseline latency. The paper's core recommendation: decompose workflows by task type and match each to the lightest sufficient architecture. For teams building B2A interfaces or MCP-based agent ecosystems, this is a quantitative argument for keeping deterministic endpoints deterministic and reserving agentic orchestration for tasks that genuinely require reasoning. The published [ADF code](https://github.com/Ritvik-G/adf/) provides a reusable decision template.

**SCA's runtime constraint enforcement via SMT solving creates a new pattern for agent-safe tool APIs.** Beyond its D1 implications, the [Symbolic Constraint Agents paper](https://arxiv.org/abs/2610.25552) shows that constraints mined from API documentation can transfer across benchmarks (AppWorld → τ²-bench with up to 5.6-point gains). For teams designing APIs that agents will consume, this suggests a new deliverable alongside OpenAPI specs: a formal constraint manifest that any agent harness can load and enforce. This is the D3 corollary — if you're building for agents, publish your tool-call invariants explicitly.

## D4 — Cost of Ownership

**Bellman Language Models turn recurring agentic decisions into a solved MDP, cutting inference cost by up to 98%.** This directly advances the 2× output / ½× downstream cost equation: by treating the decision space of bounded agentic workflows as a saturation problem, the [BLM approach](https://arxiv.org/abs/2610.24871) solves decisions once from workflow logs, caches the policy, and only falls back to the LLM for unseen states. On τ²-bench telecom, Qwen3.8-27B goes from 29% to 96% task success with 93% fewer model calls. Claude Opus 5.5, already at 96%, sees a 98% reduction in cost per task. This is the most impactful cost optimization technique for agentic systems published this quarter — it doesn't change the agent architecture, it wraps it.

**StopLoss early-abort monitors make failure prediction cheap enough to pay for itself.** The [StopLoss system](https://arxiv.org/abs/2610.25525) trains a small language model on completed trajectories and their outcomes, then scores recent tool steps in a single forward pass to decide whether to abort. On the costlier SWE-bench Pro subset, it lowers cost per retained solve by 31% (48% with Qwen3-8B backbone) while preserving 99% of successful runs. The monitor operates at 1–2 orders of magnitude lower cost per check than any general-purpose judge model. For agentic SRE, this is the equivalent of a circuit breaker — it doesn't improve success, it stops paying for guaranteed failure.

**Koi's self-calibrating fleet planner achieves 1.18× greater goodput at 20% lower $/token for heterogeneous LLM inference.** The [Koi system](https://arxiv.org/abs/2610.24355) uses a causal graph linking ~140 deployment variables to outcomes (latency, throughput, cost) and updates its beliefs after each deployment. Ablations show that the LLM alone scores 35.3 on their composite metric, adding deterministic tools reaches 51.6, and the full planner reaches 70.8 — another data point that hybrid LLM+deterministic architectures dominate pure-LLM approaches. For any team running multi-cloud inference at scale, Koi's approach to continuous recalibration of accelerator/parallelism choices is directly applicable to reducing the agentic factory's infrastructure cost.

**MASIF reveals that implicit failures occur in 54% of successful multi-agent traces, creating hidden observability debt.** The [MASIF study](https://arxiv.org/abs/2610.25852) analyzes 1,828 traces across nine MAS configurations and finds that errors are routinely corrected, bypassed, or carried forward without affecting the final outcome — but they correlate with future failures and accumulate as process debt. Their IF-GRPO algorithm uses implicit failure costs to refine preferences among successful trajectories, exposing trade-offs between task performance and IF density. For production MAS, this means that pass/fail outcome metrics are insufficient for operational health — you need process observability that tracks how the system succeeds, not just whether it does.

## Software Civil Engineering Lens

Today's batch is the strongest evidence yet that the SCE thesis is moving from theory to implementation. Three independent research groups — Cortex, AgInt, and SCA — have converged on essentially the same architectural pattern: **deterministic harnesses governing LLM agents through formal verification structures** (finite lattices, append-only certificates, SMT solvers). This is not coordination; it's convergence driven by the same engineering pressures that professionalized other disciplines.

The **lattice-based requirement closure** in Cortex is directly analogous to structural engineering's proof of stability — you define the requirements, you prove the monotone operator converges, and you bound the number of iterations. The fact that the authors explicitly acknowledge where their assumptions break ("artifact repair, fallible validation, and finite execution budgets do not satisfy them automatically") mirrors the honest reporting of material properties in civil engineering datasheets — you state the conditions under which your guarantees hold.

The **AllPath production incident taxonomy** is perhaps the most SCE-relevant artifact published today. Their finding that the hardest failures passed every automated gate — and were only caught by human operators noticing silent changes — is a direct analog to the failure modes that drove civil engineering's shift from craft to codes: the failures that inspection protocols miss are the ones that force the next generation of standards. Their three-layer verification architecture (code gates / bounded self-review / human judgment) maps cleanly onto the Specify → Plan → Verify → Apply → Observe lifecycle, with the crucial insight that each layer catches structurally different failure classes.

The **"Doing Less with More" ADF** advances the SCE thesis by providing what is essentially a **material suitability chart**: given your accuracy and throughput requirements, here is which architectural "material" (deterministic, REST, MCP, agentic) is appropriate. This is exactly the kind of engineering judgment framework that the six pillars gap calls for — and the fact that it includes quantitative performance data (latency multipliers, accuracy bounds) moves it from opinion to engineering specification.

Finally, the **Bellman Language Model** approach resonates with SCE's emphasis on separating what requires judgment from what can be mechanized. By proving that many agent decisions saturate and can be solved as MDPs, BLM effectively identifies which parts of an agentic workflow are "structural" (can be calculated) versus "architectural" (require creative judgment) — a distinction that is foundational to professional engineering practice.
