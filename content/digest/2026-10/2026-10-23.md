## D1 — Agentic Engineering

**RIPPLE closes the gap between critique and corrective action in long-horizon coding agents.** Long-horizon agents frequently generate plausible self-critiques after failure but then continue on the same broken trajectory — what the authors term the "Critique-to-Action Handoff Gap." [RIPPLE](https://arxiv.org/abs/2610.31276) internalizes recovery behavior into a single self-recovering policy through a prefix-only teacher and stage-specific RL credit assignment. The key insight is that reflection triggering, diagnosis, and corrective action each need separate credit signals gated by local validity, not just terminal outcomes. Across four repo-level SE benchmarks, this yields a 4.8-point improvement with no auxiliary critic needed at inference — meaning lower token cost in production. This directly addresses the D4 cost equation: self-recovering agents reduce the human escalation rate in agentic coding pipelines.

**DoorDash automates feature flag cleanup with a multi-agent LLM system, proving industrial ROI.** With [56,000 feature flags across 623 repositories and 1,659 stale flags](https://arxiv.org/abs/2610.31351), DoorDash built an end-to-end system integrating MCP for live rollout data, Jira processing, and automated PR creation. The system produced engineer-approved removal PRs for 45 of 50 stale flags (90%) at \$4.79 and 13.8 minutes per cleanup, versus 1–2 hours manual effort. This is a textbook D1→D4 win: agentic engineering directly attacks tech debt accumulation, one of the most insidious downstream cost drivers. The cross-cutting D3 angle — using MCP to query live flag state — shows protocol interoperability enabling real automation. *(Cross-cuts D3, D4)*

**Agentic verified optimization produces machine-checked proofs alongside performance improvements.** [Aqueduct](https://arxiv.org/abs/2610.30188) migrates C/C++/Go/Rust programs into Lean 4, then has agents produce faster rewrites with machine-checked equivalence proofs. On 189 reference implementations, agents produced proved-faster rewrites for 156, including algorithmic upgrades like replacing exponential recursion with dynamic programming. The critical insight: using the existing implementation as the specification sidesteps the spec-writing bottleneck. This is formal verification made practical through agentic orchestration — exactly the "simulation before apply" step the SCE lifecycle demands. *(Cross-cuts D4, SCE)*

**MemMux provides runtime verification for fleets of parallel coding agents.** When developers run 10+ coding agents simultaneously, [MemMux](https://arxiv.org/abs/2610.07257) solves four problems no standard tool addresses: per-agent memory attribution, complete process reclamation on termination, escaped-process detection, and swap-cliff prevention. Under budget constraints, MemMux holds fleets under 7500 MiB with zero swap while ungoverned tools run 2× over budget into swap. Tested on real Claude Code sessions with 100% attribution. The 2.7% CPU overhead at 10 agents slightly exceeds their 2% target but is a reasonable trade for preventing silent OOM kills that destroy uncommitted agentic work. *(Cross-cuts D4)*

## D3 — Build for Agents

**First empirical measurement of agent-to-agent handshake costs reveals protocol design has direct token-cost implications.** The [handshake benchmark](https://arxiv.org/abs/2610.30151) across MCP, A2A, and ACP shows round-trip count dominates latency (legacy MCP: 3 round trips / 230ms at 50ms RTT; A2A: 1 round trip / 61ms), but the hidden cost is context consumption: capability metadata scales at 24–107 tokens per capability, meaning a 200-capability counterpart burns 11% of a 200k-token context window before the agent reads its task. MCP's own 2026 revision validates the cost by cutting to 2 round trips and zero on warm reconnects with era pinning. For anyone designing agent-facing APIs (D3), this is a forcing function to minimize capability surface area and adopt progressive disclosure.

**MCP vs. CLI: structured governance wins for multi-tenant production, CLI wins for solo workflows.** The [14-dimension comparative analysis](https://arxiv.org/abs/2610.30157) finds CLI more efficient for single-user local work, but MCP addresses requirements CLI fundamentally cannot: fine-grained access control, credential isolation, structured audit trails, and multi-tenant governance. Critically, progressive disclosure techniques have eliminated MCP's historical context-window overhead weakness, making it token-competitive with CLI while preserving architectural benefits. The recommendation of a hybrid architecture aligns with what most production teams are discovering empirically. The security assessment against NSA guidance (CSI U/OO/6030316-26) and OWASP standards adds weight for regulated environments. *(Cross-cuts D4)*

## D4 — Cost of Ownership

**Agentic feature flag cleanup directly improves the 2×/½× equation by attacking accumulated tech debt at 50× speed improvement.** [DoorDash's system](https://arxiv.org/abs/2610.31351) converts 1–2 hours of manual cleanup per flag into 13.8 minutes of automated work at \$4.79, across a backlog of 1,659 stale flags. Stale feature flags are a particularly dangerous form of tech debt: they create dormant code paths that can be inadvertently activated, causing production incidents. At the reported 90% approval rate, this system could clear roughly 1,493 flags autonomously — eliminating an estimated 1,500–3,000 engineer-hours of debt remediation while simultaneously reducing incident surface area. This is downstream cost reduction (tech debt, incident risk) funded by modest agentic factory costs.

**MemMux prevents a class of silent failures that destroy agentic engineering output.** [The resource governance runtime](https://arxiv.org/abs/2610.07257) addresses a subtle but critical cost: when parallel coding agents exhaust memory, OOM kills silently discard uncommitted work. This is wasted inference spend (agentic factory cost) that produces zero output. MemMux's per-agent attribution and pressure-based reclamation trade 2.7% CPU for guaranteed work preservation. The 100% escaped-process detection (10/10) is equally important — orphaned language servers and test runners from terminated agents are a growing ops burden as agent fleet sizes increase.

**Agent protocol handshake overhead is a measurable tax on every agent-to-agent interaction.** The [handshake benchmark](https://arxiv.org/abs/2610.30151) quantifies a cost most teams are ignoring: at 24–107 tokens per capability in metadata exchange, organizations running agents with large capability inventories are spending significant context budget — and therefore inference dollars — before any productive work begins. For a 200-capability server at the high end (107 tokens/capability), that's ~21,400 tokens per handshake, purely overhead.

## Software Civil Engineering Lens

Today's batch is remarkably rich for the SCE thesis — five papers scored SCE 5/5, and they collectively advance multiple pillars.

**The Petri-net execution harness is the strongest SCE signal today.** [Gu & Zhu's certified execution harness](https://arxiv.org/abs/2610.31376) formalizes bounded autonomy with mathematical rigor: Petri net marks represent capabilities, approvals, and budgets; transitions fire only when preconditions are met; prompt-injected requests with unmet preconditions are refused regardless of wording. This is *exactly* the "simulation" pillar — a formal model that can be verified before deployment, analogous to a structural engineer's load analysis. The replanning closed-loop analysis (showing the maximally permissive supervisor can be arbitrarily more intrusive than necessary) provides the theoretical foundation for the least-intrusive governance that production systems need.

**OSTEON and "Superintelligent Software Engineering" directly articulate the SCE thesis.** [Gholinejad's paper](https://arxiv.org/abs/2610.31306) argues that once an agent outpaces its reviewers, reading catches a shrinking share of changes built on stale knowledge — and *governance*, not capability, is the binding constraint. The OSTEON discipline (governed knowledge repository, mechanical checking against decisions/contracts, decay detection at session start) maps almost perfectly to SCE's "Specify → Plan → Verify → Apply → Observe" lifecycle. The empirical finding that 49% of top GitHub repos already have agent context files, but 9.5–22% of the paths they reference don't resolve, is a damning data point: the industry is adopting agent governance but the "material datasheets" are already rotting.

**The partition theory of evaluation limits establishes a fundamental constraint on verification.** [Mahran's paper](https://arxiv.org/abs/2610.30803) proves that behavioral evaluation alone can certify at most a floor on an agent's discrimination, never a ceiling — and that exact imitation of a weaker model is undetectable by any behavioral evaluator. For SCE, this means "testing" alone (the current industry standard) is provably insufficient for safety cases. You need formal specification and structural guarantees — precisely the shift SCE advocates. The companion [Post-Audit Mirage paper](https://arxiv.org/abs/2610.31130) makes this operational: offline tests can produce identical evidence for safe and harmful agent lifecycles.

**Agentic verified optimization and LLM2Cert advance the "formal proof as engineering deliverable" paradigm.** [Aqueduct](https://arxiv.org/abs/2610.30188) producing machine-checked proofs alongside optimized code and [LLM2Cert](https://arxiv.org/abs/2610.30524) synthesizing Lyapunov certificates with SMT/Lean verification both demonstrate that formal methods are becoming tractable through agentic automation. This is the professionalization step: moving from "tests pass, ship it" to "here is the machine-checked proof of equivalence." When agents can produce proofs faster than humans can write tests, the economics of formal verification invert — and that's exactly what happened in civil engineering when computational structural analysis became cheaper than physical load testing.

**The connecting thread**: today's papers collectively show that the industry is simultaneously discovering (a) that agents without governance produce dangerous failures, and (b) that agents *with* formal methods can produce governance artifacts (proofs, certificates, supervisory controllers) that were previously impractical. This is the SCE inflection point: the same technology creating the governance crisis is also the technology that can solve it.
