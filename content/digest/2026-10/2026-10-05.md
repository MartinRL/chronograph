## D1 — Agentic Engineering

**Multi-agent complexity rarely justifies its cost.** A rigorous empirical study across five SE tasks (code generation, tech debt ID, vulnerability detection, log parsing, log analysis) using six open-weight LLMs finds that [multi-agent designs consume 6.36× the energy and run 6.07× as long as non-agentic baselines](https://arxiv.org/abs/2610.03010), with worst-case slowdowns of 160× for specific task-hardware pairs. The damning finding: 59 of 66 Pareto-optimal configurations (accuracy vs. energy) are non-agentic or single-agent. The practical takeaway for D1 is that the default should be single-agent with escalation to multi-agent only where task-specific evidence (e.g., vulnerability detection) justifies it. Model and prompt choice matter more than agent count. Also relevant to D4.

**Generative Test-Driven Development (GTDD) introduces adversarial agent-vs-agent testing loops.** [GTDD](https://arxiv.org/abs/2610.02952) separates the testing agent from the coding agent: after each candidate implementation is fixed, the tester generates new inputs from a human-specified behavioral contract. A trusted evaluator returns reduced counterexamples for regression. In experiments on a stateful key-value store, policies that regenerated tests during development ended with lower mean failure rates than one-shot test generation. Intriguingly, giving the tester the candidate's source produced no detectable additional improvement — the contract-driven adversarial pressure alone was sufficient. This is a concrete instantiation of the Specify → Verify loop for agentic pipelines.

**Decision pins catch the specification gaps that AI-generated tests silently ignore.** Across [600 generated test suites from three models, 42.7% contain no test that distinguishes competing interpretations](https://arxiv.org/abs/2610.03237) of a requirement. The "decision pin" technique enumerates underspecified points, constructs two throwaway implementations that differ only at that point, and finds a discriminating input. Pins achieve 96–97% agreement with benchmark classification on 703 implementations. Every compliance failure under a prose rule came from the model deciding the rule's scope itself — a direct argument for executable specifications over natural language. Deeply cross-cutting with SCE.

**LLM platform infrastructure, not app-level integration, is the right abstraction for production agents.** An [InfoQ article on platform engineering for production LLMs](https://www.infoq.com/articles/platform-engineering-playbook-production-llms/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering) reports how treating LLM hallucinations in an inventory recommendation system as an application bug failed, while treating the LLM stack as shared platform infrastructure — with prompt registry/versioning, schema enforcement, and token cost attribution per request — resolved the issue. This maps directly to D4's cost-of-ownership concern: centralized observability and enforcement at the platform layer prevents the per-team sprawl that makes agentic systems unmaintainable.

## D2 — AI in the Product

**Neuro-symbolic autoformalization achieves 100% accuracy where LLMs alone hit 66%.** [Law&Order](https://arxiv.org/abs/2610.02792) formalizes US tax forms and instructions into executable symbolic programs, combining LLM synthesis with cell-level verification and iterative localized error repair. On 51 held-out tax returns, the system achieves perfect cell-level and form-level accuracy — compared to the most advanced LLM's 66% standalone accuracy. The pattern — LLM generates, symbolic verifier catches, LLM repairs locally — is a template for any domain with large computational structures (insurance, financial products, regulatory compliance). Also strong SCE signal: structural and denotational correspondence between legal text and logic is the specification language concept applied to a real domain.

## D3 — Build for Agents

**VeriPy brings formal verification into agent-compatible Python workflows.** [VeriPy](https://arxiv.org/abs/2610.02814) (accepted at NeurIPS 2026 VeriCodeGen) lets developers and agents express contracts, invariants, and proof hooks as Python comments, then produces Dafny or Lean verification artifacts while preserving executable code. A relational product checks whether updated components maintain backward compatibility. The "developers and agents" framing is key: this is tooling explicitly designed for the world where agents are modifying code and need machine-checkable compatibility guarantees. When an agent updates a component, VeriPy can verify that old callers still work — a critical capability for D3 agent interoperability and D4 maintenance cost.

## D4 — Cost of Ownership

**Agentic coding token costs are 1000× code chat, wildly stochastic, and fundamentally unpredictable — threatening the 2×/½× equation.** A [systematic study of token consumption across eight frontier LLMs on SWE-bench Verified](https://arxiv.org/abs/2604.22750) reveals that runs on identical tasks can differ by 30× in token usage, accuracy peaks at intermediate cost and saturates (more tokens ≠ better), and models vary by 1.5M+ tokens on the same tasks (Kimi-K2 and Claude-Sonnet-4.5 vs. GPT-5). Most critically, models systematically underestimate their own costs (correlation ≤ 0.39 with actual usage). Without per-request cost attribution and hard budget caps, the agentic factory's inference costs are effectively unbounded — directly undermining the ½× downstream cost target.

**LiteTrajEval cuts agent evaluation cost by 6× and time by 8× while improving failure localization by 20–35 percentage points.** [This deployed enterprise system](https://arxiv.org/abs/2610.03315) preprocesses agent trajectories, marks heuristic failure signals, serializes under a fixed budget, and runs a single rubric-guided LLM judge. The improvement over AgentRx on Magentic-One-style traces is substantial: better diagnostics at dramatically lower cost. For the running system, this means incident investigation and quality monitoring for agentic products can scale without proportional cost growth — a direct multiplier on the ½× downstream cost side. The offline rule profile derivation + online heuristic marking pattern is worth adopting for any team running production agents.

**A 23-mode failure taxonomy with measured resilience patterns gives compound AI systems their first engineering handbook.** Analysis of [150 production incidents](https://arxiv.org/abs/2610.02503) across five failure categories (retrieval, generation, tool, orchestration, integration) produces actionable numbers: circuit breakers reduce cascade propagation by 89%, output quality gates catch 73% of silent degradation before user impact, component isolation reduces blast radius by 64%, and 3+ patterns together cut MTTR by 71%. The "silent quality degradation evades standard monitoring" finding is particularly dangerous — it's the failure mode where agentic systems look fine in dashboards while delivering wrong answers to users, driving up support tier costs invisibly.

**PACE determines when to compile repetitive agent procedures into programs, saving 17–25% on tokens.** [The PACE system](https://arxiv.org/abs/2610.02932) addresses a concrete factory cost problem: agents running the same GUI workflow repeatedly burn tokens on every execution. PACE's online algorithm weighs compilation costs (including failed attempts) against estimated future savings, with payback counts of 2–16 uses for successful compilations. The (1+ε)-competitive guarantee means total cost is bounded relative to always using the agent. This is a direct reduction in inference cost for the agentic factory, and the payback measurement protocol is worth adopting even if you build your own compilation approach.

**LOGOS collapses alert floods 124× for zero-knowledge incident triage.** [This unsupervised system](https://arxiv.org/abs/2610.02297) works with only raw text logs — no traces, no topology maps, no baseline metrics — and achieves 99.8% noise elimination in 4.5 minutes median, with 16-hour lead time before diagnosis-verified incidents. Combined with a zero-shot LLM, it reaches 80% enterprise root-cause accuracy. For organizations drowning in observability data from compound AI systems, this directly attacks the incident management cost that scales with system complexity. The zero-prior-knowledge constraint makes it deployable alongside existing tooling without integration overhead.

## Software Civil Engineering Lens

Today is an unusually rich day for the SCE thesis. Three papers independently attack the same problem from different angles: **how do you specify what software should do when the specification is written by or for AI agents?**

**VeriPy** brings formal verification to Python with explicit agent-in-the-loop support — contracts as comments, machine-checkable backward compatibility, Dafny/Lean proof generation. This is the "material datasheets" pillar: components carry their behavioral guarantees with them, and those guarantees survive agent-driven updates. The NeurIPS VeriCodeGen acceptance signals growing academic legitimacy for the spec-driven approach.

**GTDD** is the adversarial counterpart: rather than proving correctness, it generates tests from behavioral contracts that actively hunt for the gaps agents leave. The key finding — agents adapt to observed tests, leaving 42.7% of intended behavior unimplemented — is a direct indictment of the "generate tests, generate code, check green" workflow. GTDD's contract-driven adversarial testing is essentially simulation (the Decider pattern) applied to code generation: specify behavior, generate candidates, verify against spec, repair.

**Decision pins** are perhaps the most SCE-significant. They formalize the observation that natural-language requirements are inherently underspecified, and they provide an executable protocol for resolving ambiguity before implementation. The pin — named point, confirmed input, chosen value — is a micro-specification that constrains generation and verifies compliance by execution. This is the "codes and norms" pillar: not full formal spec, but executable records of resolved design decisions that prevent silent drift.

The [compound AI failure taxonomy](https://arxiv.org/abs/2610.02503) adds empirical grounding to the "codes and norms" pillar from the operations side: 23 classified failure modes with measured resilience patterns is precisely the kind of engineering handbook that civil engineering has and software engineering has lacked. The 71% MTTR reduction from applying 3+ patterns is the kind of evidence that justifies mandatory adoption — a building code, not a suggestion.

The [Law&Order neuro-symbolic system](https://arxiv.org/abs/2610.02792) demonstrates the end state: LLM synthesis + symbolic verification + iterative repair achieves 100% accuracy on a non-trivial domain. The 66% → 100% jump from adding formal verification to LLM output is the strongest argument yet for the thesis that **the professionalization of software is not optional in the agentic era — it's the difference between a system that works and one that doesn't**.

Taken together, today's papers suggest the SCE frontier is advancing simultaneously on specification (decision pins), verification (VeriPy, GTDD), operational standards (failure taxonomy), and domain formalization (Law&Order). The gap between research availability and industry adoption of these techniques is now the binding constraint.
