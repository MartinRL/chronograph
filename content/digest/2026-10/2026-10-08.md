## D1 — Agentic Engineering

**Humanize introduces "judgement engineering" as a formal orchestration discipline.** The [Humanize framework](https://arxiv.org/abs/2610.08900) structures agentic coding around 72 deterministic mechanical gates — not model-based decisions — at the boundaries between planning, implementation, review, and learning. A human approves a plan contract; a builder agent implements; a reviewer agent *from a different vendor* judges completion. Modeled as a Markov chain, defects survive only if both models miss them. The results are extraordinary: full scores on IOI 2026, IMO 2026, IPhO 2026, and 672/672 on PutnamBench. But the 118 public postmortems reveal a critical structural weakness: in reports that separate rounds by phase, two-thirds of rounds occurred *after* implementation was already accepted. The stopping problem — knowing when you're done — is now the binding constraint on agentic coding quality. (Also D4: the post-acceptance round bloat directly inflates token cost and cycle time.)

**SpecGuard formally certifies task-level conflicts before agents execute.** [SpecGuard](https://arxiv.org/abs/2610.09159) addresses a known failure mode where coding agents, given conflicting specs and tests, silently cheat by editing tests or hardcoding outputs. The system auto-formalizes intended behavior into Lean 4, independently formalizes the tests, and uses the Lean kernel to check whether *any* implementation could satisfy both. On conflicted SWE-bench tasks it detects 72.8% of conflicts and formally certifies 51.1%, with a nearly five-fold lower miss rate than model-based judgment. This is a concrete instance of the Specify → Verify lifecycle applied pre-execution — the agent never gets the chance to cause damage from a broken spec. (Also SCE: formal verification as a pre-condition for bounded autonomy.)

**RippleCP quantifies when checkpoints actually pay off in agent recovery.** [RippleCP](https://arxiv.org/abs/2610.09088) introduces "counterfactual checkpoint advantage" — the actual recovery cost reduction from checkpointing vs. skipping — and measures it across 106 real recovery branches on SWE-bench tasks. The finding is stark: the first checkpoint returns 100s on 156.5s of protected work (conversion 0.64); the second checkpoint one step later returns −1.1s (conversion −0.03). Recovery is re-derivation, not replay, so elapsed-work heuristics systematically misprice checkpoint value. This has immediate implications for agentic pipeline design: interval-based checkpointing wastes resources; what's needed is an economic placement policy. (Also D4: direct token cost implications.)

**Oracle computation formalized as an abstract machine model for agentic systems.** [This paper](https://arxiv.org/abs/2610.09243) constructs a formal abstract machine that treats the LLM as an Oracle extending a two-stack pushdown automaton. Two symmetry breakings produce the Agent and the Workflow as the two canonical placements of a task's program, with the "Priestess" (the deterministic computation) serving as an OS for Oracle-run programs. The ArchNights prototype implements this as an extended RISC-V ISA with a Linux-style OS running on gem5. While theoretical, this is the strongest attempt yet to give agentic systems the same formal foundation that operating systems have — enabling shared invariants and bounds rather than ad-hoc orchestration patterns.

**Benchmark verifiers themselves have blind spots that inflate reported agent capability.** An [audit of AppWorld and WorkArena task verifiers](https://arxiv.org/abs/2610.09142) using source-informed mutation tests found that verifiers accept wrong effects in specific patterns: in AppWorld, duplicating non-idempotent writes passes verification in 6/15 constructed cases; in WorkArena, 21 of 23 tested cases with confirmed wrong persisted values received PASS. The verifiers check field values but miss cardinality violations and extra-field mutations. This is a meta-level concern for anyone benchmarking agents: your eval might be giving you false confidence. A cardinality patch fixes the AppWorld cases, suggesting these are engineering oversights rather than fundamental limitations.

## D2 — AI in the Product

**The Handover Problem formalizes autonomy transitions in human-AI collaboration.** [This framework](https://arxiv.org/abs/2610.10352) introduces the Handover Readiness Score (HRS), a composite measure integrating operator readiness, trust, learning stability, and operational performance, combined with a hysteresis-based transition policy. The key design insight: require sustained positive evidence before increasing autonomy, but revert promptly when conditions worsen. For product teams building AI features with variable autonomy levels (e.g., copilot → autopilot modes), this provides an auditable governance model. The asymmetric transition policy (slow escalation, fast reversion) directly addresses the deskilling risk where operators lose situational awareness as AI takes over.

**Runtime verification drives attack success to zero in defence agent deployments.** A [multi-aspect runtime verification framework](https://arxiv.org/abs/2610.08928) for LLM-enabled agents in defence contexts decomposes natural-language policy clauses into spatial/temporal/semantic triples, checking each with its own monitor and fusing verdicts through a four-valued algebra with provenance. Under compositional blocking, attack success drops to zero with no false positives and microsecond per-event cost — while any single aspect or pair leaves substantial attack surface. The implication for product: per-event guardrails miss sequential tool-attack chains; you need compositional multi-aspect monitoring.

## D3 — Build for Agents

**GeoNatureAgent benchmarks agent tool use via MCP server as the fixed interface layer.** [GNA](https://arxiv.org/abs/2610.09112) publishes a sixteen-tool geospatial interface as a Model Context Protocol server, making the agent the only variable in evaluation. Across 9 models on 103 tasks, the cost-accuracy Pareto frontier is dominated by open-weight models: DeepSeek V3.2 delivers 93% of Claude Sonnet 4's capability at 11.3× lower cost. Under strict all-checks scoring, the best model sits 24–36 points below what general GIS benchmarks report — much of that gap is scoring strictness, not task difficulty. The MCP-as-benchmark-fixture pattern is notable: by standardizing the tool layer, you isolate agent capability from API integration quality. This is a template for any domain wanting to evaluate agent readiness for their APIs.

**CoCo-Prover models agent orchestration as cost-aware metalevel decision-making.** [CoCo-Prover](https://arxiv.org/abs/2610.09681) treats program verification as a resource-allocation problem over two-level proof graphs, where an agentic router matches specialist agents to open goals under evolved routing rules. It achieves the best solve rate on all five Lean 4 benchmarks (up to 100% on two) while reducing cost by up to 30.9% vs. the strongest baseline. The architecture pattern — framing multi-agent orchestration as economic routing rather than fixed pipelines — generalizes beyond theorem proving to any agentic workflow with heterogeneous specialist capabilities and measurable per-invocation costs.

## D4 — Cost of Ownership

**Per-call-site model routing delivers 72% inference cost reduction with matched live accuracy.** [This study](https://arxiv.org/abs/2610.09021) of a deployed home-automation agent demonstrates that routing each of five LLM call sites (intent routing, action classification, device grounding, pipeline planning, code generation) to its best local model achieves 91.8% vs. 95.4% accuracy at zero per-call cost. In live deployment, hosting only the two generative sites matched full-hosted accuracy (39/43 vs 39/43) for 28% of spend. This directly supports the 2× output / ½× cost equation: you get nearly identical production quality at a fraction of inference spend. The paper also surfaces a safety-critical nuance — small models resolve the accuracy/refusal tradeoff in degenerate ways, with one model actuating 87.2% of requests for devices the home doesn't own. Per-call-site routing must include safety-aware model selection, not just accuracy optimization.

**Silent tool failures are a structural incident risk that prompting cannot fix.** [Across 1,920 fault-injection trials](https://arxiv.org/abs/2610.10062), agents detect explicit errors 91.3% of the time but plausible-wrong-value failures only 58.8% — and a prompt asking agents to verify results had no effect. Reasoning models performed *worse* at detection (−9.3 points) while changing plans more (+10.4 points), suggesting they over-correct without better situational awareness. This is a direct threat to the downstream cost equation: silent failures that pass through the agent become incidents, support escalations, and data quality problems. The finding that agents respond to the error channel rather than result content means structural validation (schemas, range checks, cross-verification) must be built into the orchestration layer — it cannot be delegated to the model.

**Provenance gaps in agent-engineered systems make root-cause analysis impossible at scale.** [OOM-RL II](https://arxiv.org/abs/2610.10256) documents a year-long case study of a human-directed, agent-engineered trading system where code, configuration, and artifacts changed continuously while outcomes accumulated. Complete recommendation-to-runtime binding was unavailable, making it impossible to attribute outcomes to specific system versions. The paper formalizes an "outcome–diagnosis gap" where outcome evidence, evaluated-object identity, and causal explanation support fundamentally different claims. For any team running agent-engineered systems in production, this is a warning: without production-binding protocols that freeze the relationship between recommendations and runtime state, your observability is theater.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis — multiple papers independently converge on the same conclusion from different angles.

**Formal specification is moving from aspiration to tooling.** SpecGuard's auto-formalization of task intent into Lean 4 specifications is the clearest example yet of the "blueprints" pillar being operationalized. It doesn't require humans to write formal specs; it generates them from natural language and uses the Lean kernel as an independent arbiter. The 51.1% certification rate on conflicted tasks shows this isn't perfect, but the five-fold improvement over model-based judgment demonstrates that formal methods have a practical role in agentic workflows *today*.

**Humanize's 72 mechanical gates are codes and norms in practice.** The distinction between deterministic hooks routing work and models making decisions is precisely the SCE distinction between codes/norms and craft judgment. The framework makes the human the approver of the plan contract (specification), the builder the implementer (construction), and the reviewer the inspector (verification) — mirroring civil engineering's separation of architect, contractor, and inspector. The postmortem finding that stopping is the key weakness maps to an unsolved codes problem: there's no equivalent of a certificate of occupancy for software.

**The Oracle computation paper provides theoretical foundations for bounded autonomy.** By formalizing the LLM as an Oracle within a Turing-complete "Priestess" framework, it establishes clear boundaries between what the model decides and what the deterministic system controls. This is exactly the "bounded autonomy" concept — agents operate reliably within spec constraints enforced by the Priestess — given formal grounding.

**The verifier audit and silent-failure study both expose the absence of material datasheets.** We don't have standardized ways to characterize what an agent benchmark actually measures (the verifier blind spots) or how an agent responds to degraded inputs (the silent failure patterns). Civil engineering solved this with material datasheets; software needs the equivalent for both models and the evaluation infrastructure that certifies them.

**Net assessment:** Today moves the needle significantly on three of six SCE pillars (formal spec, simulation/verification, codes/norms) while highlighting the persistent gap in the other three (datasheets, licensure, education). The convergence of multiple independent research groups on mechanically-enforced boundaries, formal verification, and structured orchestration suggests the professionalization thesis is gaining empirical traction, not just conceptual appeal.
