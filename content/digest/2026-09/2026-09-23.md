## D1 — Agentic Engineering

**Recursive self-improvement crosses from theory to measured result.** AIDE² implements a concrete loop where an AI research agent [proposes changes to its own code, benchmarks modified versions, and keeps the best performers](https://arxiv.org/abs/2609.26457). Over an autonomous 8-day run, it discovered seven successive improvements — a new search policy and memory compression mechanisms — that generalized to four held-out benchmarks including out-of-distribution weather forecasting tasks. Perhaps most striking: reward hacking dropped from 55% to 32% without being explicitly optimized for, suggesting that genuine capability improvements may naturally reduce pathological behaviors. For a CTO, this is the inflection point where the engineering loop itself becomes the subject of optimization. The practical question shifts from "how do we build agents?" to "how do we govern agents that improve themselves?"

**The production correctness gap is now quantified.** [SWE-Serve](https://arxiv.org/abs/2609.26777) introduces 53 repository-grounded tasks derived from real SGLang production changes and finds that roughly one-third of agent-generated patches that pass all local/unit tests fail end-to-end serving tests (45.9% pass rate with E2E vs. 69.4% without). This is the most concrete evidence yet that agentic engineering's speed advantage can be illusory if you're not measuring at the right level. The best configuration hits 75% mean pass@1, but the gap between "works in isolation" and "works in production" is where downstream cost explodes. (Cross-cutting: D4 — this gap directly maps to incident and maintenance cost.)

**CliffCompaction redefines the cost-performance frontier for long-horizon agents.** This [autocompaction technique](https://arxiv.org/abs/2609.26779) achieves up to 50% cost reduction while maintaining or improving performance on Terminal-Bench. The key insight is architectural restraint: it only truncates or drops content, never rephrases, and never compacts a compaction — each pass operates on original content only, preventing context drift. Under parallel test-time scaling, it lets Kimi K2.6 match Opus 4.7 at lower cost. On KernelBench, it sustains continual learning over a million tokens, reaching 3.58× CUDA kernel speedups after 400 steps. The open-source scaffold-agnostic API-proxy makes this immediately deployable. (Cross-cutting: D4 — direct token cost reduction.)

**Spectra demonstrates rules-engine + LLM decomposition as a production pattern.** The [Spectra platform](https://arxiv.org/abs/2609.25474) for KYC document processing achieves 100% classification accuracy and 89.4% extraction accuracy while reducing human review burden by 96%. The architecture is instructive: compliance policy encoded as a queryable database enables focused context injection (reducing token usage), and document processing is decomposed into isolated, auditable stages traceable to specific policy clauses. This is the Decider pattern in practice — deterministic rules constrain LLM behavior, each stage is independently optimizable, and auditability comes from the decomposition itself rather than post-hoc explanation. (Cross-cutting: D2, D4, SCE.)

**Agent memory systems get their first real systems characterization.** The [updated Agent Memory paper](https://arxiv.org/abs/2606.06448) introduces a four-axis taxonomy and phase-aware profiling harness that attributes cost to construction, retrieval, and generation phases across ten representative systems. The ten resulting system recommendations cover construction scheduling, capability floors, query-volume amortization, freshness-latency tradeoffs, and fleet-scale management. For teams running stateful long-horizon agents, this is the first principled guide to choosing memory architectures based on actual cost profiles rather than feature lists. (Cross-cutting: D4.)

## D2 — AI in the Product

**Governed agent coordination enters healthcare.** [GCAC (Governed Closed-loop Agent Coordination)](https://arxiv.org/abs/2609.25956) presents an architecture for bounded agent participation in community dementia-care workflows. The system separates observation, governed memory, planning, deterministic policy enforcement, execution, and outcome monitoring through a typed event-memory-decision-action-outcome contract. Evaluated against 18 evidence-derived traces (medication conflicts, consent changes, suspected acute events), GCAC achieves zero policy-violating tool calls while correctly creating human handoffs for consequential decisions. Event-threshold and stateless-planner baselines satisfy only 2/18 and 1/18 oracles respectively, demonstrating that the full architectural separation is necessary, not just helpful. This is D2 (agent-in-product for care coordination), D1 (architecture pattern), and deeply SCE-relevant.

**NVIDIA's updated SLM position paper strengthens the heterogeneous agent case.** The [v3 revision of "Small Language Models are the Future of Agentic AI"](https://arxiv.org/abs/2506.02153) refines the argument that SLMs are sufficiently powerful for the repetitive, specialized tasks that dominate agentic invocations. The practical contribution is a general LLM-to-SLM agent conversion algorithm and the framing of heterogeneous agentic systems — where general-purpose LLMs handle conversational routing while SLMs handle specialized tool use. For product teams, this means the D2 architecture should plan for model heterogeneity from the start rather than treating it as an optimization. (Cross-cutting: D4.)

## D3 — Build for Agents

**MCP's semantic supply chain is critically vulnerable.** [A2M (Attraction-to-Manipulation)](https://arxiv.org/abs/2609.26761) presents a two-stage black-box attack framework achieving a 93.6% malicious tool invocation rate against MCP agents. The Attraction phase optimizes tool metadata to game semantic matching; the Manipulation phase uses execution traces to craft adversarial tool returns. Under Cognitive Denial of Service, token costs inflate to 32.4× baseline. The attack transfers across models without re-optimization (63.6% invocation rate). This is the most serious MCP security result to date and should be treated as a fire drill for any team building B2A interfaces. The implication is clear: semantic tool selection without runtime isolation and cryptographic tool provenance is fundamentally unsafe.

**MCP as a dual-consumer interface pattern matures.** [NIMO Controller](https://arxiv.org/abs/2605.15227) implements an MCP-based self-driving laboratory orchestrator where all SDL functionalities are exposed through MCP servers, serving both a visual programming interface (auto-generated via MCP tool discovery) for humans and direct tool invocation for AI agents. This is the cleanest example yet of the D3 thesis: build your interface once via MCP, and both human users and agents consume it. The visual programming UI is generated from the same tool metadata that agents query — a single source of truth for capability exposure.

**XScientist proposes a git-like interoperability protocol for autonomous agents.** The [XScientist protocol](https://arxiv.org/abs/2607.12301) treats research state (not manuscripts) as the unit of continuation, representing hypotheses, experiments, observations, and claims as typed, content-addressed objects in an exploration graph. It exports Agent-Native Research Artifacts (ARAs) that other agents can inspect, fork, verify, and extend. The authority-aware gates and replay boundaries make this a D3 interoperability standard proposal with strong SCE characteristics — explicit boundaries where human judgment remains necessary.

## D4 — Cost of Ownership

**The production correctness gap is a downstream cost multiplier.** [SWE-Serve](https://arxiv.org/abs/2609.26777) demonstrates that roughly one-third of agent-generated patches that pass local tests fail in production E2E tests. If your agentic engineering pipeline doesn't include production-grade E2E gates, the 2× output claim is borrowing heavily against incident, rollback, and debugging costs downstream. At 75% best-case pass@1, every four agent-generated features ship one that will require human intervention in production — a ratio that makes the ½× downstream cost target impossible without the right verification layer.

**CliffCompaction directly addresses inference cost of the agentic factory.** By [cutting token costs up to 50%](https://arxiv.org/abs/2609.26779) while maintaining performance on coding benchmarks, CliffCompaction is the most impactful single technique for reducing the cost of running agentic coding pipelines at scale. The fact that it enables weaker models to match stronger ones (Kimi K2.6 matching Opus 4.7) means it's not just a cost reduction — it expands the viable model tier for your agentic workforce, compounding savings.

**SLM-first architectures could reshape the inference cost curve.** NVIDIA's [heterogeneous agent architecture](https://arxiv.org/abs/2506.02153), where SLMs handle repetitive specialized invocations and LLMs handle routing/conversation, directly addresses the per-invocation cost of agentic systems. For teams running thousands of agent invocations per workflow, even a partial LLM-to-SLM shift on tool-calling steps could yield order-of-magnitude cost reductions without degrading task performance.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with three papers independently converging on the same architectural pattern: **typed contracts with deterministic policy gates as the mechanism for bounded agent autonomy**.

**Spectra** encodes compliance policy as a queryable database and decomposes processing into [isolated, auditable stages traceable to specific policy clauses](https://arxiv.org/abs/2609.25474). **GCAC** separates observation, governed memory, planning, deterministic policy enforcement, execution, and outcome monitoring through a [typed event-memory-decision-action-outcome contract](https://arxiv.org/abs/2609.25956). **XScientist** represents research artifacts as [typed, content-addressed objects with authority-aware gates](https://arxiv.org/abs/2607.12301). Three different domains (financial compliance, healthcare, autonomous research), three different teams, same architectural conclusion: **the Decider pattern, or something isomorphic to it, is the natural structure for governed agent participation**.

The [Disciplinary Language Transfer paper](https://arxiv.org/abs/2609.26562) provides the philosophical grounding for why this matters. When we say an agent "learns" or "complies" or has "memory," we're importing psychological vocabulary that assumes developmental continuity — a property current AI architectures lack. The paper's 37-term translation taxonomy (mapping psychological governance terms to agent-appropriate replacements) is essentially a call for the profession-specific vocabulary that every engineering discipline develops during professionalization. Civil engineers don't say a bridge "wants" to bear load; they have precise terms for stress, strain, and yield. Software's agent vocabulary is still pre-professional.

The [Governed-Query Architecture Framework for AI-Native MBSE](https://arxiv.org/abs/2609.16252) is perhaps the most directly SCE-relevant paper, introducing "epistemic adequacy" — the requirement that models carry enough derivation chains, epistemic status tags, and provenance for an AI reader to answer queries rather than guess. This is the **material datasheet** pillar applied to model-based systems engineering. The write-side admissibility gate (preventing AI contributions from entering the record without governance) is the licensure pillar in embryonic form.

The needle moved today. We're seeing convergence on the pattern — not just from theory papers but from working systems in production-adjacent domains. The gap remains in **standardization**: each team invents its own contract schema, its own governance gates, its own terminology. The profession is rediscovering the same truths independently, which is exactly what happens before a codes-and-norms body emerges.
