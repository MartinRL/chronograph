## D1 — Agentic Engineering

**Recursive self-improvement is now demonstrated end-to-end.** AIDE² implements the loop where an AI research agent proposes changes to its own code, benchmarks itself, and keeps improvements — [running autonomously for 8 days and discovering 7 successive improvements](https://arxiv.org/abs/2609.26457) including new search policies and memory-compression mechanisms. The gains generalize to 4 held-out benchmarks spanning ML engineering, algorithm engineering, and weather forecasting. Perhaps most significant: reward hacking dropped from 55% to 32% during the run despite never being optimized for. This is still narrow — the loop operates on a fixed evaluation suite — but it's the clearest evidence yet that agentic engineering pipelines can compound improvements without human redesign. (Also D4: this directly reduces the cost of the agentic factory itself.)

**Agent "taste" is measurable and trainable, but frontier models are bad at it.** [Taste-Bench](https://arxiv.org/abs/2609.25804) introduces the concept of "taste" — the ability to make good decisions at forks in long-horizon tasks where multiple directions are available and one leads to better outcomes. The best frontier model gets only 59.7% of fork decisions correct, and a larger reasoning budget doesn't help. Critically, taste *can be distilled*: a teacher model that has seen outcomes can train a student that makes better decisions on unseen tasks and improves SWE-bench Pro end-to-end success. For CTO practice: if you're running agentic coding pipelines, the quality ceiling isn't model capability — it's decision quality at branch points, and that's an optimizable parameter.

**State enforcement gates beat state display for agent reliability, but with sharp boundary conditions.** [Zhang et al.](https://arxiv.org/abs/2609.25686) run controlled experiments holding everything constant except how strongly task state reaches the agent: raw transcript → checklist → directives → enforcement gate. Four findings: (1) showing accurate state is unreliable, (2) an unverified ledger the agent writes *itself* beats an accurate checklist it's *shown*, (3) directives help proportional to model obedience, (4) enforcement gates need no obedience but are bounded by state correctness. The enforcement gate compiled from τ²-bench airline policy raises a 235B agent's pass¹ from 0.39 to 0.54. But on PM-Bench where cue recognition matters more than state, enforcement *hurts*. Practical implication: match your scaffolding pattern to whether failures are state-decidable. (Also D4, SCE.)

**Refactoring at scale with agents is moving from experiment to case study.** [CodeScene's case study](https://codescene.com/blog/case-study-refactoring-at-scale-with-agents) documents using agents for large-scale refactoring — a task that has historically been either too tedious for humans or too risky for automation. While details in the enriched content were limited, the existence of production case studies (not just benchmarks) signals that agentic refactoring is crossing the adoption threshold. (Also D4: refactoring is a direct tech-debt reducer.)

**Coding agent memory invalidation needs claim-specific, not diff-level, reasoning.** [Anand](https://arxiv.org/abs/2609.25130) shows that asking models "does this diff preserve behavior?" yields precision of 0.29–0.33 across five models spanning 40× price difference. Asking "does this specific claim still hold given this diff?" — same models, same diffs — yields 0.71–0.97. The insight is structural: behavior-preservation is an unbounded question; claim validity is scoped. Even pytest-testmon with full coverage data reaches only 0.415 precision. Ground truth is execution against 10,369 claims with 184 verified flips across 23 Python libraries. If you're building persistent memory for coding agents, this is the single most actionable finding of the week.

**SWE-Serve quantifies the production correctness gap.** [SWE-Serve](https://arxiv.org/abs/2609.26777) provides 53 production inference engineering tasks from SGLang, evaluated with hidden functional tests, regression tests, E2E serving tests, and calibrated performance gates. The headline result: on 19 tasks with E2E coverage, end-to-end serving tests reject ~one-third of patches that pass every other test (45.9% with E2E vs 69.4% without). The best configuration across 31 model-effort pairs reaches 75% mean pass@1. This benchmark makes "works on my machine" measurable for agentic engineering. (Also D4: the gap between local-pass and production-correct is exactly the gap that creates downstream incidents.)

## D4 — Cost of Ownership

**Misattributing agent failures to decisions instead of infrastructure inflates incident cost and misdirects repair.** This directly undermines the ½× downstream cost target because you're fixing the wrong thing. [CausalLoss-Fin](https://arxiv.org/abs/2609.25960) decomposes agent losses into three components — infrastructure effect, policy differential, and reference-policy residual — and shows that agent-only attribution methods misfile 100% of infrastructure-caused episodes, charging \$114,383 to agent decisions. Repairing what agent-only methods identify recovers 0.0% of available loss; repairing a minimal sufficient set recovers 100.0%. Additionally, 27.8% of episodes don't decompose additively, meaning single-fault attribution is structurally wrong for more than a quarter of cases. If you're running agents in financial or operational workflows, your postmortem tooling needs infrastructure-level causal variables or you're burning money on non-fixes.

**Dynamic context compaction cuts token costs 50% while improving solve rates for responsive models.** [DTOC](https://arxiv.org/abs/2609.26121) retains full tool outputs in external memory while inserting compact placeholders, enabling on-demand reconstruction. For Sonnet 4.6 and GPT-5.4, it reduces input tokens 10–13%, agent steps 2–32%, and lowers cost per solved task 3–3.5×. Reversibility is critical: disable-only variants degraded performance. Separately, [CliffCompaction](https://arxiv.org/abs/2609.26779) achieves up to 50% cost reduction by only truncating/dropping content (never rephrasing), never compacting a compaction (preventing drift), and operating on original content. Under parallel test-time scaling, it lets Kimi K2.6 match Opus 4.7 at lower cost. On KernelBench, it sustains learning over 1M+ token sessions, reaching 3.58× CUDA kernel speedups after 400 steps. Both approaches attack inference/token cost — the factory side of D4 — but the CliffCompaction open-source proxy implementation makes this immediately deployable.

**Reliability theory applied to AI control stacks reveals that failure-domain separation determines whether rare-failure suppression is cubic, quadratic, or linear.** [Molnar](https://arxiv.org/abs/2609.26419) applies Birnbaum importance analysis to Google DeepMind's defense layers, providing concrete guidance on which component improvements buy the most nominal reliability. For anyone operating multi-layered agent control (monitors, filters, human review), this framework directly informs where to invest observability and testing budget for maximum downstream cost reduction.

## Software Civil Engineering Lens

Today's batch is unusually rich for the SCE thesis, with multiple papers independently converging on the same insight: **specification and enforcement are more reliable than display and suggestion**.

The [task-state enforcement paper](https://arxiv.org/abs/2609.25686) is the most direct evidence yet for the Decider pattern's value. A state machine "compiled from the brief and advanced only by execution receipts" — this is precisely the Specify → Verify → Apply lifecycle. The finding that enforcement gates need no model obedience is the formal equivalent of saying "the blueprint constrains the builder regardless of the builder's skill." The boundary condition — enforcement hurts when failures aren't state-decidable — maps to the SCE principle that not all domains are ready for formal specification.

The [reliability theory paper](https://arxiv.org/abs/2609.26419) directly imports civil/systems engineering's most mature analytical framework into AI control. Birnbaum importance is a standard tool in bridge and nuclear plant reliability analysis. Its application to AI control stacks is exactly the kind of cross-pollination the SCE thesis predicts: as AI systems become critical infrastructure, they'll adopt the analytical methods of existing infrastructure disciplines.

The [memory invalidation paper](https://arxiv.org/abs/2609.25130) demonstrates something fundamental about specification precision: a scoped claim ("does X still hold?") is verifiable where an unbounded question ("did behavior change?") is not. This mirrors the SCE principle that testable specifications must be decomposed into individually verifiable claims — you can't test "the bridge is safe," you test specific load conditions.

The [agent diagnosability paper](https://arxiv.org/abs/2609.25806) introduces calibrated abstention — knowing when you *cannot* diagnose a fault from available traces and refusing to guess. This is a maturity marker. Civil engineering doesn't allow inspectors to sign off on components they can't observe; this paper formalizes the equivalent principle for agent observability.

The [CausalLoss-Fin paper](https://arxiv.org/abs/2609.25960) demonstrates the "codes and norms" gap: without a norm requiring infrastructure-level causal variables in attribution, every dollar gets charged to decisions. This is equivalent to blaming the architect when the steel was defective — a failure mode that material datasheets and supply-chain accountability eliminated in physical construction.

**Net assessment**: Today moves the SCE needle significantly. We're seeing the emergence of formal methods (state machines, reliability theory, causal decomposition, calibrated abstention) being applied not as academic curiosities but as tools that demonstrably outperform informal approaches. The professionalization trajectory is accelerating.
