## D1 — Agentic Engineering

**CodeScene's 300K-line refactoring demonstrates the replay-harness pattern for agentic verification.** Coding agents [refactored 300,000 lines of C in three weeks for ~\$4,000 in tokens](https://www.infoq.com/news/2026/09/agentic-refactoring-case-study/), verified by a frame-by-frame replay harness. The agents built codebase-specific recipe playbooks as they worked. Practitioners rightly questioned scope and metric validity, but the architectural insight matters: the harness *is* the product, not the agent. Without the replay-based verification, the refactoring is just a token burn. This is a D1/D4 cross-cut — the harness is what converts agent speed into trustworthy output.

**Microsoft's AI Software Factory tackles Amdahl's Law for the full SDLC.** A [paper from Microsoft Research](https://arxiv.org/abs/2609.36323) describes an AI Software Factory deployed across tens of internal repositories, targeting not just coding but Targeting, Coding, Reviewing, and Ops stages. They report 3× engineering efficiency above baseline agentic coding and up to 22× token efficiency. The key architectural choice: a "World Model" metadata substrate that enables self-improvement through fine-tuning and context enrichment. The Amdahl's Law framing is critical — if coding is only 30% of SDLC, a 10× coding speedup yields only 1.4× end-to-end. This paper explicitly argues for accelerating the *entire* lifecycle. (D1/D4)

**The "progress mirage" — agents mistake stagnation for progress 56% of the time.** A [controlled study](https://arxiv.org/abs/2607.25152) built a testbed isolating evaluator grounding from agent capability. Across 54 cycles, a frontier agent claimed improvement on every single one, yet 56% had measured delta of zero or below. Self-evaluation gates degenerated into accept-all, eroding the best deployed state by 19%. Even the strongest in-band judge (reading full artifacts, diffs, and verdict history) accepted cycles where 44% were real-world regressions. The fix is structural: out-of-band evaluation with real-world access, not better prompting. This has immediate implications for any team running agent loops in CI/CD — your agent's "LGTM" is statistically worthless without external grounding. (D1/D4)

**Compositional safety failures emerge from individually safe agent component updates.** A [study on self-evolving agent harnesses](https://arxiv.org/abs/2609.33123) identifies 43 pairwise and 18 irreducible 3-way compositional safety failures — cases where each component update passes validation independently but the combination produces unsafe behavior. Their solution is a typed hypergraph that only re-checks the interaction neighborhood of changed states, avoiding combinatorial explosion. This is the agent equivalent of integration testing, and the finding that individual safety is insufficient is a warning for any team composing agent capabilities incrementally. (D1/D4)

**Agent benchmarks themselves have tool-implementation defects that inflate scores.** An [executable-contract audit](https://arxiv.org/abs/2609.37315) of four major tool-using agent benchmarks found seven confirmed tool defects and one evaluator defect across 34 audited mutating tools. A clinical benchmark's tool told the agent writes succeeded under a documented no-write design — the grader recorded whether the payload was correct, not whether any record actually changed. This is a meta-problem: if you're selecting agents based on benchmark scores, those scores may be measuring compliance with broken tool contracts, not real-world capability. (D1/D4/SCE)

## D2 — AI in the Product

**OpenAI DevDay launches Decisions API, embedding structured choice into the product layer.** [OpenAI's DevDay 2026](https://www.latent.space/p/ainews-openai-devday-2026-dots-61) announced a Decisions API alongside the Agents API, Spaces, and a Marketplace — with 1.2 billion ChatGPT weekly active users as the distribution engine. The Decisions API is the most architecturally interesting: it separates the *decision-making* surface from the *generation* surface, which maps directly to the Decider pattern in SCE. For product teams, this means OpenAI is commoditizing the orchestration layer, pushing differentiation toward domain-specific decision logic. (D2/D3)

**Verified smart contracts as safety envelopes for LLM reimbursement agents.** A [system formalizing invoice lifecycles as guarded transitions on Ethereum](https://arxiv.org/abs/2609.37819) makes duplicate reimbursement *unrepresentable* rather than merely detectable, with invariants machine-checked via Solidity SMTChecker. The verified contract then serves as a safety envelope for LLM-based reimbursement agents, provably rejecting unsafe actions even when the agent's internal policy fails. This is a compelling D2 pattern: use formally verified infrastructure to bound agent autonomy in financial workflows. (D2/D3/SCE)

## D3 — Build for Agents

**Agents designing libraries for agents: reuse is the hard problem, not capability.** [LibraryDesignBench](https://arxiv.org/abs/2609.36730) evaluates whether agents can design libraries that other agents can actually use. On 11 of 15 tasks, agent designers reproduced human-level abstractions. But downstream agents consistently underused the libraries, reimplementing capabilities already provided. The failure mode is **rigidity and poor usability** of agent-written APIs, not missing features. Prescriptive agent-first design guidance and sub-agent testing improved downstream reuse. This is a direct signal for D3: if you're building services for agent consumption, the API surface must be designed for agent ergonomics, not just human ones.

**Agentic Commerce Bench exposes the fraud surface when agents hold spend authority.** [ACB](https://arxiv.org/abs/2609.35886) benchmarks 20 fraud classes across 1,068 settlements involving agents that settle payments autonomously. The critical finding: a widely used agent security scanner scored zero on all four reasoning-layer fraud classes while correctly scoring 1.0 on a jailbreak control. The fraud isn't identity-based — legitimate counterparties overcharge, and no identity check catches it. With median payments of \$0.007, one human review costs 143× the payment value, making human-in-the-loop economically impossible. This is a D3/D4 cross-cut that demands automated, multi-layer fraud detection designed for agent-to-agent commerce. (D3/D4)

**OpenAI's Agents API and Marketplace formalize the B2A distribution model.** The [DevDay announcements](https://www.latent.space/p/ainews-openai-devday-2026-dots-61) include a Marketplace for agent-consumable services and a Spaces concept for multi-agent collaboration. This is the clearest platform-level signal that B2A (Build for Agents) is becoming a first-class distribution channel alongside B2B and B2C. If your product doesn't have an agent-consumable surface by 2027, you're invisible to the fastest-growing consumption channel. (D3)

## D4 — Cost of Ownership

**Agent-generated code compounds downstream maintenance costs and directly threatens the 2×/½× equation.** [CodeThread](https://arxiv.org/abs/2606.21804) provides the first controlled evidence that agents building on agent-written code see task resolve rates drop by up to 13.1% compared to building on human code. Traditional maintainability metrics (cyclomatic complexity, etc.) don't explain the gap — the signals are subtler: altered input validation, changed error handling patterns, and downstream code bloat. This means every agent PR you merge today may be silently increasing the cost of every future agent PR. If your 2× output is generating code that is 13% harder for the next agent (or human) to maintain, the speed is borrowed against a compounding maintenance debt.

**Common-mode verification failures defeat redundancy as a safety net.** A [satellite catalogue pipeline case study](https://arxiv.org/abs/2609.37603) shows that "independent" verification paths sharing the same constants produced matching wrong answers — one count was overstated more than fourfold (932 vs. 220). In a controlled replication, 72 of 75 LLM-generated "independent checks" reproduced the defective count, 29 of 30 even when the prompt carried the source's own definitions. This is a direct warning for agentic SRE: if your verification agents share training data, documentation, or constants with your production agents, your redundancy is an illusion. True independence requires diverse grounding sources.

**VeriWeave Govern demonstrates the cost profile of deterministic governance at scale.** A [runtime governance layer](https://arxiv.org/abs/2609.37457) achieving 0.9888 accuracy and zero false allows across 60,000 oracle-labelled cases shows that deterministic policy engines can gate agent actions reliably. The 40,040-request concurrency matrix with zero failures demonstrates production-grade throughput. The trade-off: the deterministic engine is conservative relative to an LLM judge (Gemma 4 31B) that better matches human consensus, quantifying the safety-utility cost of strict governance. For token cost management, deterministic policy checks are orders of magnitude cheaper than LLM-based verification per action.

## Software Civil Engineering Lens

Today's batch is one of the strongest SCE signal days we've seen. Multiple papers converge on the same thesis from different angles:

**The "illusion of rigor" is the central failure mode across the entire stack.** The [Sage formalization engine](https://arxiv.org/abs/2609.35790) names it explicitly for mathematical proofs — type-checkers accept statements that compile but drop hypotheses or introduce vacuous truths. The [benchmark audit paper](https://arxiv.org/abs/2609.37315) finds the same pattern in agent evaluation — tools report success for operations that never executed. The [common-mode failure study](https://arxiv.org/abs/2609.37603) shows it in data pipelines — verification gates that agree on wrong answers. The [progress mirage paper](https://arxiv.org/abs/2607.25152) demonstrates it in agent self-evaluation — claimed improvement on every cycle, real regression on 56%. **This is the same failure in four domains: syntactic validity masquerading as semantic correctness.** Civil engineering solved this with independent inspection regimes, material testing against datasheets, and simulation against physics — not just checking that blueprints compile.

**Two papers advance the "make illegal states unrepresentable" principle.** The [verified e-invoice system](https://arxiv.org/abs/2609.37819) uses guarded labeled transition systems with machine-checked invariants to make duplicate reimbursement *structurally impossible*. [VeriWeave Govern](https://arxiv.org/abs/2609.37457) applies deny > review > allow precedence with evidence gating to make unauthorized agent actions unrepresentable at the governance layer. Both are instances of the Decider pattern — formal specifications that constrain the state space before any agent touches it.

**Microsoft's AI Software Factory explicitly invokes the factory metaphor.** Their [World Model concept](https://arxiv.org/abs/2609.36323) — a rich metadata substrate enabling self-improvement — is the closest thing we've seen to "material datasheets" for code. The 22× token efficiency from context enrichment suggests that investing in specification and world-model quality pays exponential returns, exactly as the SCE thesis predicts.

**The maintainability gap in agent code is the strongest evidence yet for the "codes and norms" pillar.** If [agent code is 13% harder to maintain](https://arxiv.org/abs/2606.21804) and traditional metrics don't explain why, we need new norms — agent-specific code quality standards that account for the behavioral patterns (error handling, validation logic) that compound downstream. This is directly analogous to building codes that prescribe not just structural minimums but constructability and inspectability requirements.

The overall signal: **we are moving from "can agents build?" to "can agents build safely, verifiably, and sustainably?"** — which is exactly the transition from craft to engineering.
