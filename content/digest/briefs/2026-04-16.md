## D1 — Agentic Engineering

**Formal architecture descriptors dramatically reduce agent waste.** A rigorous three-study investigation shows that [providing AI coding agents with formal architecture descriptors reduces navigation steps by 33-44%](https://arxiv.org/abs/2604.13108) (p=0.009, d=0.92) across 24 controlled tasks, and cuts behavioral variance by 52% across 7,012 real Claude Code sessions. The most operationally significant finding: format matters less than having *any* descriptor (JSON, YAML, Markdown, S-expressions all work), but failure modes differ critically — YAML silently corrupts 50% of errors while S-expressions detect all structural completeness failures. The authors propose `intent.lisp` as an S-expression architecture descriptor with an open-source Forge toolkit. For agentic engineering practices, this is a concrete, measurable intervention: give your agents a map before sending them into the codebase. *Also relevant to D4 — fewer tool calls = lower inference cost.*

**Contract-Coding attacks "vibe coding" fragility with formal contracts.** The [Contract-Coding framework](https://arxiv.org/abs/2604.13100) addresses the observation that intent-driven ("vibe") coding causes "architectural collapse" in repo-level generation. By projecting ambiguous intents into a formal Language Contract that serves as a Single Source of Truth, the system enforces topological independence between modules, unlocking parallel agent execution. On the Greenfield-5 benchmark, it achieves 47% functional success with near-perfect structural integrity where SOTA agents fail via hallucination. The key insight: the contract layer decouples *what* from *how*, letting agents work on isolated modules without cross-contamination. *Also relevant to SCE — this is spec-driven development operationalized for agents.*

**AgentForge makes execution-grounded verification mandatory, not optional.** [AGENTFORGE](https://arxiv.org/abs/2604.13120) introduces a multi-agent framework (Planner, Coder, Tester, Debugger, Critic) where every code change must survive sandboxed Docker execution before propagation. It achieves 40% resolution on SWE-BENCH Lite, outperforming single-agent baselines by 26-28 points. Ablations confirm both execution feedback *and* role decomposition independently drive performance — this isn't just more agents, it's the verification gate that matters. The framing of software engineering as "an iterative decision process over repository states" is the right abstraction level for agentic pipelines.

**Two-stage agentic pipeline improves published algorithms in a single day.** A [practical pipeline using Claude Code](https://arxiv.org/abs/2604.13109) demonstrates LLM-assisted improvement of published algorithm implementations across 11 experiments, all yielding improvements achievable within one working day. The most valuable contribution is the explicit enumeration of *indispensable human roles*: selecting targets, verifying experimental validity, assessing novelty, providing compute, and responsible disclosure. This is a concrete template for "human on the loop" agentic engineering — the agent iterates, the human steers and validates.

## D2 — AI in the Product

**Cognitive decomposition for embodied agents.** The [Tri-Spirit Architecture](https://arxiv.org/abs/2604.13757) decomposes agent intelligence into planning (Super Layer), reasoning (Agent Layer), and execution (Reflex Layer) mapped to distinct hardware substrates. While primarily a D4 contribution (75.6% latency reduction, 71.1% energy reduction), the "habit-compilation mechanism" — which promotes repeated reasoning paths into zero-inference execution policies — is a product-relevant pattern. For products embedding autonomous agents, this suggests a maturation path: expensive reasoning at launch, progressively cheaper cached policies over time. The 77.6% offline task completion rate is notable for edge/mobile product scenarios.

## D3 — Build for Agents

**MCP gets its first comprehensive threat taxonomy.** [MCPThreatHive](https://arxiv.org/abs/2604.13849) operationalizes 38 MCP-specific threat patterns mapped to STRIDE, OWASP Top 10 for LLM Applications, and OWASP Top 10 for Agentic Applications. The platform automates the full threat intelligence lifecycle — collection, AI-driven extraction, knowledge graph storage, and visualization. Three critical gaps in existing MCP security tools are identified: incomplete compositional attack modeling, absence of continuous threat intelligence, and lack of unified multi-framework classification. For teams building MCP servers or consuming MCP-exposed tools, this is the first systematic security baseline. The existence of 38 distinct threat patterns should give pause to anyone deploying MCP without a security review.

**Formal verification framework unifies MCP and A2A analysis.** An updated [modeling framework](https://arxiv.org/abs/2510.14133) introduces 30 formally specified properties (16 for host agents, 14 for task lifecycle) expressed in temporal logic, covering liveness, safety, completeness, and fairness. The key contribution is bridging the semantic gap between MCP (tool access) and A2A (coordination) protocols — currently analyzed in isolation, creating exploitable coordination issues. This is the first attempt at a unified, domain-agnostic verification framework for multi-agent systems. For teams building agent orchestration layers, these temporal logic properties could become the equivalent of API contract tests.

**ECM Contracts propose a package-manager model for agent capabilities.** [ECM Contracts](https://arxiv.org/abs/2604.13097) encode six dimensions for embodied agent modules: functional signature, behavioral assumptions, resource requirements, permission boundaries, recovery semantics, and version compatibility. The release discipline includes version-aware compatibility classes, deprecation rules, and policy-sensitive upgrade checks. While focused on robotics, the pattern — treating agent capabilities as versioned, contract-governed packages with explicit compatibility guarantees — applies directly to any modular agent architecture. *Also highly relevant to SCE — this is "material datasheets" for agent capabilities.*

## D4 — Performance & Cost at Scale

**Token-budget routing saves $1.2-15.4M/yr with zero architectural disruption.** [Token-budget-aware pool routing](https://arxiv.org/abs/2604.09613) addresses the fact that production vLLM fleets provision for worst-case context length, wasting 4-8x concurrency on the 80-95% of requests that are short. The solution: estimate each request's token budget using a self-calibrating bytes-per-token ratio, dispatch to short or long pools. Results on Azure LLM Inference and LMSYS-Chat-1M traces show 17-39% GPU reduction. A Qwen3-235B on MI300X projection at 10K req/s shows $15.4M/yr savings. The O(1) overhead and compatibility with PagedAttention, continuous batching, and prefill-decode disaggregation make this a drop-in optimization. *Note: this paper has been withdrawn by the author, so validate before adopting.*

**CPU-only LLM serving gets a 2-3.4x speedup.** [Sandwich](https://arxiv.org/abs/2507.18454) resolves the prefill/decode resource conflict on CPU-based LLM serving through phase-wise plan switching, sub-NUMA-aware allocation (TopoTree), and fast-start dynamic-shape kernel generation. Across five x86/ARM platforms, it achieves 2.01x average speedup with up to 3.40x latency reduction. For edge and cost-sensitive deployments where GPUs aren't available, this makes CPU-based inference significantly more viable. The three-orders-of-magnitude reduction in kernel tuning cost compared to static compilers is the operationally important detail.

## Software Civil Engineering Lens

Today's batch is one of the strongest SCE signal days in recent memory. Five of twelve items directly advance the professionalization thesis:

**Formal specification is becoming computational.** Contract-Coding's [Language Contract as SSOT](https://arxiv.org/abs/2604.13100) is essentially the blueprint pattern from SCE — a formal spec that both humans and agents operate against. The fact that this *prevents architectural collapse* is direct evidence that spec-driven development isn't just good practice, it's a necessary precondition for agent-scale code generation. The Decider pattern's "terraform plan for domain logic" finds its analogue in the contract layer's topological independence guarantee.

**Verification is crossing the automation threshold.** [VeruSAGE](https://arxiv.org/abs/2512.18436) shows LLM-agent systems completing 80%+ of formal Rust verification tasks and outperforming human experts on unfinished proofs. [WybeCoder](https://arxiv.org/abs/2603.29088) achieves 74% on Verina and 62% on Clever for verified imperative code generation. These aren't toy examples — they're system-level verification tasks. The "prove-as-you-generate" paradigm in WybeCoder maps precisely to the SCE lifecycle's Verify step being concurrent with, not sequential to, the Apply step. We're approaching the point where formal verification becomes economically viable at scale because agents do the proof work.

**Material datasheets are emerging for agent capabilities.** [ECM Contracts](https://arxiv.org/abs/2604.13097) with their six-dimensional capability encoding (functional signature, behavioral assumptions, resource requirements, permission boundaries, recovery semantics, version compatibility) and [the formal property framework for agentic systems](https://arxiv.org/abs/2510.14133) with its 30 temporal logic properties are *exactly* what the SCE thesis predicts: you cannot safely compose autonomous components without standardized material specifications. The analogy to structural steel datasheets (yield strength, fatigue limits, environmental constraints) is no longer metaphorical.

**The gap that remains widest: codes/norms and licensure.** While specifications and verification tools are advancing rapidly, there's still no equivalent of building codes — mandatory compliance standards for agentic system deployment. MCPThreatHive's 38-pattern taxonomy could seed such standards, but adoption remains voluntary. The professionalization arc is accelerating on the tooling axis while the institutional axis lags.
